# ツリーパネルの見直し（`tsukumoe-core` / `tsukumoe-app`）

- REQ: REQ-UI-004（エディタの標準パネル。M5-02 の標準パネルの改善）
- 単位: M5-05b
- 状態: 実装済み（実機の GUI 操作は未確認）
- 依存: M5-05
- クレート: `tsukumoe-core`（名前変更・所属変更のコマンド）、`tsukumoe-app`（ツリーパネルの再構成、デフォーマパネルの新設、ビューポートの複数選択の表示）、`tsukumoe-ui`（必要な部品。行の操作ボタンなど）

## 目的

パーツのツリーを、行が多くても目的のものを探して操作しやすくする。実機で使って出た不満は次のとおり。

- Part のフォルダを閉じられない
- 種別（メッシュ・Part・デフォーマ）で絞り込めない
- 行が多くて目的のものを探しにくい
- 選択・複数選択が分かりにくい。複数選択のときビューポートの表示も見づらい
- 操作がメニューに隠れている。名前の変更・削除・複製ができない

## 範囲

- **パネルの分割**: 「パーツ」パネル（Part とメッシュ）と、「デフォーマ」パネル（デフォーマの親子階層）に分ける。どちらも標準パネルで、ドックのタブとして並ぶ。選択は両パネルとビューポートで共有する
  - パーツ: Part の入れ子とメッシュ。デフォーマは出さない
  - デフォーマ: 親を持たないデフォーマを根に、ワープ・回転の親子を入れ子にする。メッシュは親デフォーマの下に葉として出す。親デフォーマを持たないメッシュは出さない。各行の右に所属 Part を薄く出す
  - 既定の配置（「Tsukumoe」「Cubism 風」の両方）に「デフォーマ」を足す。パーツと同じ領域にタブで並べる。「デフォーマ」を含まない古い配置は、標準パネルの補完（M5-02）で右の帯に補われる。サイドストリップのアイコンは Lucide から追加する
- **パネルを開く導線とタブのアイコン化**（全標準パネル。実機で、新しい「デフォーマ」パネルを開く方法が分からなかったため）
  - メニュー「表示 > パネル」に、全標準パネル（ビューポート・パーツ・デフォーマ・パラメータ・インスペクタ・履歴・コマンドパレット・AI の変更）を並べる。項目の左に、現在のワークスペースで見えているかをチェックで示す。選ぶと、そのパネルを前面に出す（タブならそのタブを選び、サイドドックの帯ならスライドして開く。配置に無いときは、標準パネルの補完と同じく右の帯に足して開く）
  - 各項目はアクション `panel.show.<パネル名>` として登録する。キーマップ・コマンドパレット・パイメニューから呼べる（既定のキーは割り当てない）。egui のメニューバーと macOS のネイティブメニュー（M5-02a）は、どちらも `menu.rs` の定義から作られるので、1 か所の追加で両方に出る
  - パネルを閉じる操作は作らない（標準パネルは配置から消えない。M5-02 の方針のまま）。見つからない・隠れているパネルを出す導線だけを足す
  - ドックのタブの見出しを短くする。選択中のタブは「アイコン + 名前」、そうでないタブは「アイコンのみ」で、カーソルを置くと名前のツールチップを出す。サイドドックの帯は M5-02 のとおりアイコン。アイコンを持たないパネルは頭文字に落ちる（M5-02 の方針）。メニュー「表示 > タブの表示」で「アイコンのみ（選択中は名前つき）」「アイコンと名前」を切り替えられる。選択は利用者設定（`<設定>/editor/` 配下）に保存する
  - 全標準パネルにアイコンを割り当てる（M5-02 の割り当てに、デフォーマ用の grid-3x3 を追加済み）
- **行のレイアウトとインデントの線**（両パネル）
  - 現状は、インデントを目のボタンの前に入れており、目を持たない行（デフォーマ）は、同じ深さのメッシュ行よりアイコンが左へずれる。目のボタンを左端の固定幅の列に置き、目を持たない行は同じ幅の空きを置く。インデントは、その右（開閉の矢印・アイコン・名前）にだけ掛ける。同じ深さの行は、種別によらずアイコンと名前の位置がそろう
  - 深さごとに縦のガイド線を引く（インデントの 1 段ごと、親の開閉の矢印の下を通る細い線。トークンの弱い線色。選択中の行の祖先の線だけを少し濃くする）。行は表示中の分だけ作る（`show_rows`）ので、線は行ごとの矩形として描く
  - 深さが大きいときは、名前を切り詰めて右端の操作ボタンを隠さない
- **折りたたみ・展開**（両パネル）
  - Part とデフォーマの行に開閉の矢印を付ける。クリックまたはキー（右で開く・左で閉じる）で操作する
  - すべて開く・すべて閉じる・選択を開く（選択行の祖先を開く）。名前・種別で絞り込み中は、一致する行の祖先を自動で開く（絞り込みを解除すると元の開閉に戻る）
  - 開閉の状態は編集モデルに入れず、ビューの状態として持つ。保存はワークスペースの画面状態に含めるかは未決
  - ツリー以外で選択が変わったとき（M5-05 の自動スクロール）は、閉じた祖先を開いてから選択行へ動く
- **種別フィルタ**（両パネル）
  - 種別のトグル（パーツ: Part・メッシュ。デフォーマ: ワープ・回転・メッシュ）。複数同時に有効にできる。名前の絞り込みと AND
  - 「非表示のものだけ」のトグル
  - フィルタは行の一覧を決める純粋関数に入れ、状態関数としてテストする
- **並び**: 表示設定（編集モデルの順序は変えない）として「モデル順・名前順・描画順（メッシュのみ）」を切り替えられる。データの順序の入れ替えは本単位では行わない
- **選択**
  - 選択行の強調を強める。選択数（「3 選択中」）をパネルのヘッダに出す
  - Part の行は、クリックで Part を選び、ダブルクリックまたはメニュー「配下を選択」で、配下の全メッシュを選択に入れる
  - 範囲選択（Shift）は、表示中の行の間で、メッシュとデフォーマの混在を許す（M5-05 はメッシュのみ）。Ctrl / Cmd でトグル。選択と操作の対象は、ツールの要求する種別にそろえる（要求と異なるものは無視する）
  - 空き地のクリックで選択を解除する
- **行の操作**: 行にカーソルを置くと、目のボタンに加えて「…」ボタンが出て、右クリックメニューと同じ内容を開く。キーボードでも操作できる
  - 上下で選択を移動、左右で開閉、Enter で名前を編集、Delete で削除、Ctrl / Cmd + D で複製。パネルにフォーカスがあるときだけ
  - 右クリックメニュー: 名前を変更、複製、削除、親を設定・親を外す（デフォーマ、メッシュ）、所属 Part を変更（メッシュ、デフォーマ、Part の親）、配下を選択、配下を開く・閉じる
- **名前の変更・削除・複製**
  - 名前の変更: 行のダブルクリック、F2、メニューからインライン入力。重複・空はエラーとして表示し、変更しない。コマンドは `RenamePart` / `RenameMesh` / `RenameWarp` / `RenameRotation`（またはそれらを 1 つにした形。実装で既存の流儀に合わせる）。曲線の対象（`CurveTarget`）やバインディングは ID で持つので、モデル内の参照は壊れない。名前で保存するファイル（`.tmod` など）への影響は実装時に確認する
  - 削除: メッシュ・デフォーマはそのまま、Part は配下があれば確認ダイアログ（件数を表示）を出して、配下を葉から消す。`Batch` 1 回にまとめ、1 回の undo で戻る。ほかのメッシュのマスクに使われているメッシュの削除、子を持つデフォーマの削除は、既存コマンドの検証に従い、失敗はエラー表示する（連鎖で消す範囲は Part の削除だけ）
  - 複製: メッシュとデフォーマ（子は複製しない）。名前は `<元の名前>.copy`（重複するときは連番）。`AddMesh` などの既存コマンドを `Batch` で組み立てる。キーフォーム・ボーン影響を持つ要素は拒否する（M5-05 と同じ）
  - 所属の変更: `SetMeshPart` / `SetDeformerPart` / `SetPartParent`（循環は失敗）。ドラッグ・メニューの両方から。デフォーマの親付けは M5-05 のコマンドを使う
- **ビューポートの複数選択の表示**（M5-05 の外接矩形の拡張）
  - 選択中のメッシュそれぞれの外周（境界の辺）を、薄い accent の線で描く。最後に選んだもの（主）は太く、濃くする
  - 外接矩形は全選択の合成のまま。隅に選択数のバッジを出す
  - メッシュツール以外で出す。評価後の位置・ライブ反映への追従は M5-05 と同じ
- 範囲外: データの順序の入れ替え（描画順の変更は別）、Part・メッシュのロック、色分けタグ、ツリー間のドラッグでの複数同時移動、ワークスペースをまたぐ開閉状態の保存（未決）

## 方針

- 画面状態（開閉・フィルタ・並び・選択・インライン編集中の名前）は編集モデルに入れない。モデルは `Command` でしか変えない（ADR-0019）
- 行の一覧（開閉・フィルタ・並びを反映）と、キー操作での選択移動・開閉は、描画と分けた純粋関数にしてテストする（M5-02 のパネルの流儀）
- 行は表示中の分だけ作る（`show_rows`）。631 メッシュでも軽い
- 文言は翻訳キーで引く（REQ-UI-005）。新しい依存クレートは足さない

## 未決（レビューで決めたい）

- 開閉・フィルタ・並びの状態をワークスペースの保存に含めるか（既定は含めない）
- 名前変更コマンドの形（4 本か、種別つき 1 本か）。保存ファイル側の名前参照への影響
- 「デフォーマ」パネルに親を持たないメッシュを出さない方針で足りるか（探しにくくならないか）
- キー操作の割り当て（F2・Delete・Ctrl+D は暫定。ほかのアクションとの衝突を確認）
- Part 配下を削除するときの確認ダイアログの文面と、undo の説明（履歴ラベル）

## 検査

- 行の一覧: 開閉・種別フィルタ・名前フィルタ・非表示のみ・並びの組み合わせで期待する行が出る。絞り込み中は祖先が開いて見え、解除で元の開閉に戻る。デフォーマパネルの親子と、メッシュの葉、所属 Part の表示。631 メッシュでも軽い
- 選択: Shift の範囲（メッシュ・デフォーマの混在）、Ctrl のトグル、Part の「配下を選択」、空き地での解除、選択数の表示。ツールの要求しない種別は操作から無視される
- キー操作: 上下・左右・Enter・Delete・Ctrl+D が状態関数としてテストされる。フォーカスがないときは効かない
- コマンド: 名前変更・所属変更が重複・空・循環・存在しない名前で失敗し、モデルが変わらずエラーが UI に出る。成功後の undo / redo で戻る。JSON Schema の一覧に出る（バリアント追加で落ちるテストが通る）。名前変更のあと、曲線の対象・バインディング・マスク・デフォーマの親が壊れない
- 削除・複製: Part の配下の連鎖削除が 1 回の undo で戻る。複製したメッシュ・デフォーマが元と同じ見た目で、キーフォーム付きは拒否される
- ビューポート: 複数選択で、各メッシュの外周と主の強調、選択数のバッジが出る。メッシュツール中は出ない。スナップショット（ライト・ダーク）
- レイアウト: 同じ深さのメッシュ・Part・デフォーマの行で、アイコンと名前の x 位置が一致する（目の有無によらない）。ガイド線が深さごとに描かれ、選択の祖先だけ濃い。スナップショット（ライト・ダーク）で固定する
- パネル導線: メニュー定義に全標準パネルの項目があり、チェックが見え方と一致する。選ぶとタブが前面になる・帯のパネルが開く・欠けたパネルが右の帯に足されて開く（純粋な状態関数）。アクション `panel.show.*` がキーマップ・パレットに出る。egui のメニューとネイティブメニューが同じ項目を持つ（M5-02a の検査に追加）
- タブの見出し: 選択中は「アイコン + 名前」、そうでなければアイコンのみで、ツールチップに名前が出る。設定の切替で「アイコンと名前」になり、設定が保存・復元される。幅が狭いタブ列でも切れない。スナップショット（ライト・ダーク）で固定する
- 配置: 両プリセットに「デフォーマ」が含まれ、古い配置を読んでも落ちず補われる（M5-02 の検査に追加）
- 応答: 631 メッシュのツリーで、開閉・絞り込み・選択の操作 1 回が 16 ms 以下（release）
- 依存: ランタイム系クレートに egui 系が現れない（CI）。`tsukumoe-core` が wasm32 でビルドできる

## 受入条件

- [ ] 同じ深さの行は、メッシュ・Part・デフォーマでアイコンと名前の位置がそろい、深さごとの縦のガイド線が見える
- [ ] Part とデフォーマの行を開閉でき、すべて開く・閉じるが使える。絞り込み中は一致の祖先が自動で開く
- [ ] 種別（Part・メッシュ・ワープ・回転）と「非表示のみ」で絞り込め、名前の絞り込みと併用できる
- [ ] 「パーツ」と「デフォーマ」が別パネルになり、デフォーマの親子が見える。選択は両パネルとビューポートで共有される
- [ ] 行から名前の変更・複製・削除ができ、Part 配下の削除は確認を経て 1 回の undo で戻る
- [ ] 行にカーソルを置くと操作ボタンが出て、キーボードで選択移動・開閉・名前変更ができる
- [ ] 複数選択のとき、ビューポートで各メッシュの外周と選択数が見える
- [ ] メニュー「表示 > パネル」から全標準パネルを前面に出せる（隠れている・帯にあるものを含む）。ネイティブメニューにも出る
- [ ] ドックのタブが、選択中は名前つき、ほかはアイコンのみで短くなり、設定で「アイコンと名前」に切り替えられる
- [ ] 631 メッシュで操作が 16 ms 以下である

## 決めたこと

- パーツとデフォーマは別の標準パネルにする（利用者の回答）。Part とメッシュはパーツ、デフォーマの階層はデフォーマ
- 追加する機能は、折りたたみ・種別フィルタ・名前の変更・削除・複製・キーボード操作・並びの表示設定（利用者の回答）。データの順序の入れ替えは行わない
- 開閉・フィルタ・並び・選択は画面状態で、編集モデルに入れない
- 名前の変更・所属の変更・削除・複製はすべて `Command`（`Batch`）を通し、undo できる
- 実装での決定（未決の暫定案と、計画との差）:
  - 名前変更のコマンドは 4 本（`RenamePart` / `RenameMesh` / `RenameWarp` / `RenameRotation`）。ワープと回転は 1 つの名前空間を共有するので、`RenameWarp` / `RenameRotation` は両方の表の重複を調べる。履歴は、旧名の除去と新名の挿入（同じ内部 ID）の 2 変更で持つ。所属変更は `SetMeshPart` / `SetDeformerPart` / `SetPartParent`（循環は既存の検証で失敗）
  - 名前で持つ保存物への影響: モデル内の参照は ID なので壊れない（マスク・親・バインディングをテスト）。ただし `sources/psd-map.json` はメッシュ名と Part 名を文字列で持つので、名前を変えると PSD の再取り込みが対応を見失う。`.tmod` とランタイム API（`tsukumoe-ffi`・`tsukumoe-wasm`）はメッシュ名を出すので、外部がメッシュ名で引いていると変更後は引けなくなる
  - 開閉・フィルタ・並び・インライン編集の状態は `ViewState`（パーツとデフォーマで別）に持ち、ワークスペースの保存には含めない
  - 「デフォーマ」パネルは親デフォーマを持たないメッシュを出さない（計画どおり。探しにくさは実機で確認する）
  - 絞り込み中は一致する行の祖先を自動で開く（解除すると元の開閉に戻る）。「非表示のみ」は、自分または上の Part が非表示の行（薄く出る行）
  - 並びの「描画順」は、メッシュを描画順（`draw_order`）の昇順（後ろから前）で並べる。Part とデフォーマはモデル順のまま
  - 選択は単一のメッシュのみから、Part・メッシュ・ワープ・回転の混在に広げた。Shift の範囲は表示中の行の間で、ツールの要求する種別だけを入れる（メッシュツール: メッシュのみ、デフォーマツール: Part 以外、選択ツール: すべて。クリックした行は常に入る）。メッシュツールの対象は最後に選んだメッシュ、デフォーマツールの対象は最後に選んだデフォーマ
  - Part のダブルクリックは、Part の配下のメッシュを選ぶ（Part 自身は選択に入らない）。メッシュ・デフォーマのダブルクリックは名前の変更
  - ドラッグは、デフォーマ行へ落とすと親付け（`SetDeformerParent` / `SetMeshParent`、見た目を保つ）、Part 行へ落とすと所属の変更（Part は親 Part の変更）。ドラッグで親を外す操作は作らず、メニューの「親を外す」だけ
  - キー: 上下左右・Enter（F2 も）・Delete（Backspace も）・Ctrl / Cmd + D は、パネルにフォーカスがあるとき（行か空き地をクリックしたあと）だけ効く。名前を入力しているあいだは効かない。ビューポート文脈のキー（Delete など）はポインタがビューポートの上にあるときに別に効く
  - 複製は、メッシュ（頂点・UV・テクスチャ・ブレンド・不透明度・描画順・表示・マスク・親デフォーマ）とデフォーマ（ワープは格子、回転は基本形・親・所属 Part）。乗算色・スクリーン色・両面・ワープのベジェ設定は、対応するコマンドが無いため引き継がない。キーフォームまたはボーン影響を持つ要素は拒否する
  - Part の削除は、配下の Part・メッシュ・デフォーマを葉から消す。別の Part のメッシュが配下のデフォーマにぶら下がっている、またはマスクに使われているときは、既存の検証で失敗し、モデルは変わらない（確認ダイアログは件数だけを出す）
  - ビューポートの複数選択: 2 つ以上のメッシュを選んだとき、各メッシュの外周（三角形 1 枚だけの辺）を薄い accent の線、最後に選んだものを太い線で描き、外接矩形の右上の内側に選択数のバッジを出す。1 つだけのときは外接矩形のみ。メッシュツール中は出さない
  - パネルの行は、目の列（固定幅）、インデント、開閉の矢印、アイコン、名前の順。目を持たない行も同じ幅の空きを置く。ガイド線は親の矢印の下を通し、選択行の祖先のものだけを濃くする

- 追加の実装での決定（パネルを開く導線・タブ・状態保存・名前変更・バッジ・連動）:
  - **表示 > パネル**: 標準パネル 8 つをメニュー定義の動的項目 `Def::Panels` で並べ、現在のワークスペースで見えているものにチェックを付ける（タブの前面、またはサイドドックの開いているパネル）。選ぶとアクション `panel.show.<パネル名>` が `Layout::show_panel` を呼ぶ（タブなら選択、帯なら開く、配置に無ければ右の帯に足して開く）。egui のメニューと macOS ネイティブメニュー（`CheckMenuItem`）が同じ `Entry` 木（`checked` を追加）から作られる。既定のキーは割り当てず、キーマップ設定の一覧には出る。コマンドパレットは編集コマンド（`Command`）の一覧なので、パネルのアクションは載せていない。パネルを閉じる操作は作らない
  - **タブの見出し**: 選択中は「アイコン + 名前」、ほかは「アイコンのみ」+ ツールチップ。アイコンの無いパネルは頭文字。メニュー「表示 > タブの表示」で「アイコン（選択中は名前つき）」「アイコンと名前」を切り替え、`state.json` の `tab_style` に保存する。幅が足りないときは、名前を選択中だけ、さらに全部なし、の順に落として、見出しがグループの幅に収まるようにする
  - **開閉・フィルタ・並びの保存**（既定を変更）: 閉じた Part・デフォーマ、名前フィルタ、種別、非表示のみ、並びを、ワークスペースごとに `<設定>/editor/tree.json` へ保存する（ドックの配置とは別の隣のファイル）。選択・スクロール位置・入力中の名前は保存しない。1 項目ずつ読み、壊れた項目だけ既定に戻す。名前で持つ閉じた項目は、保存のたびにプロジェクトに無いものを捨てる。プロジェクトを開き直しても状態は保つ
  - **名前変更とPSD の対応表**: `sources/psd-map.json` の名前を、ログの再生ではなく、パーツ・メッシュの内部 ID ごとに「最後に対応表をモデルに合わせたときの名前」と今の名前を比べて、名前の変化をまとめて当てる（`Document::psd_map_bytes` / `sync_names`）。ID は名前変更・undo・redo・削除の取り消しで変わらないので、コマンド・undo・redo・名前の入れ替えのどれでも対応表が名前に追随し、undo 履歴が切り詰められても崩れない。再取り込みの計画は常にこの追随した対応表で作る。保存時にも書き出す。名前変更のたびに「旧名で参照している外部（ランタイム API・.tmod）は更新が必要」のトーストを 1 回出す（変更は止めない）
  - **パーツパネルの親デフォーマ**: メッシュ行の右端に歯車と親デフォーマの名前を薄く出す（「…」ボタンの左、名前に最低限の幅を残して切り詰める）。ホバーで祖先の連鎖（外側から `Outer › Inner`）。クリックでそのデフォーマを選択する。デフォーマパネルの行には付けない
  - **選択の連動ハイライト**: デフォーマを選ぶとパーツパネルでその配下のメッシュ（下のデフォーマ経由を含む）の行を、メッシュを選ぶとデフォーマパネルでその上のデフォーマの行を、選択の強調より淡い accent で塗る。複数選択は和。見えていない行（絞り込み・折りたたみ）には何もしない
