# ツリーパネルの見直し（`tsukumoe-core` / `tsukumoe-app`）

- REQ: REQ-UI-004（エディタの標準パネル。M5-02 の標準パネルの改善）
- 単位: M5-05b
- 状態: 計画中
- 依存: M5-05
- クレート: `tsukumoe-core`（名前変更・所属変更のコマンド）、`tsukumoe-app`（ツリーパネルの再構成、デフォーマパネルの新設、ビューポートの複数選択の表示）、`tsukumoe-ui`（必要な部品。行の操作ボタンなど）

## 目的

パーツのツリーを、行が多くても目的のものを探して操作しやすくする。実機で使って出た不満は次のとおり。

- Part のフォルダを閉じられない
- 種別（メッシュ・Part・デフォーマ）で絞り込めない
- 行が多くて目的のものを探しにくい
- 選択・複数選択が分かりにくい。複数選択のときビューポートの表示も見づらい
- 操作がメニューに隠れている。名前の変更・削除・複製ができない

## 範囲

- **パネルの分割**: 「パーツ」パネル（Part とメッシュ）と、「デフォーマ」パネル（デフォーマの親子階層）に分ける。どちらも標準パネルで、ドックのタブとして並ぶ。選択は両パネルとビューポートで共有する
  - パーツ: Part の入れ子とメッシュ。デフォーマは出さない
  - デフォーマ: 親を持たないデフォーマを根に、ワープ・回転の親子を入れ子にする。メッシュは親デフォーマの下に葉として出す。親デフォーマを持たないメッシュは出さない。各行の右に所属 Part を薄く出す
  - 既定の配置（「Tsukumoe」「Cubism 風」の両方）に「デフォーマ」を足す。パーツと同じ領域にタブで並べる。「デフォーマ」を含まない古い配置は、標準パネルの補完（M5-02）で右の帯に補われる。サイドストリップのアイコンは Lucide から追加する
- **折りたたみ・展開**（両パネル）
  - Part とデフォーマの行に開閉の矢印を付ける。クリックまたはキー（右で開く・左で閉じる）で操作する
  - すべて開く・すべて閉じる・選択を開く（選択行の祖先を開く）。名前・種別で絞り込み中は、一致する行の祖先を自動で開く（絞り込みを解除すると元の開閉に戻る）
  - 開閉の状態は編集モデルに入れず、ビューの状態として持つ。保存はワークスペースの画面状態に含めるかは未決
  - ツリー以外で選択が変わったとき（M5-05 の自動スクロール）は、閉じた祖先を開いてから選択行へ動く
- **種別フィルタ**（両パネル）
  - 種別のトグル（パーツ: Part・メッシュ。デフォーマ: ワープ・回転・メッシュ）。複数同時に有効にできる。名前の絞り込みと AND
  - 「非表示のものだけ」のトグル
  - フィルタは行の一覧を決める純粋関数に入れ、状態関数としてテストする
- **並び**: 表示設定（編集モデルの順序は変えない）として「モデル順・名前順・描画順（メッシュのみ）」を切り替えられる。データの順序の入れ替えは本単位では行わない
- **選択**
  - 選択行の強調を強める。選択数（「3 選択中」）をパネルのヘッダに出す
  - Part の行は、クリックで Part を選び、ダブルクリックまたはメニュー「配下を選択」で、配下の全メッシュを選択に入れる
  - 範囲選択（Shift）は、表示中の行の間で、メッシュとデフォーマの混在を許す（M5-05 はメッシュのみ）。Ctrl / Cmd でトグル。選択と操作の対象は、ツールの要求する種別にそろえる（要求と異なるものは無視する）
  - 空き地のクリックで選択を解除する
- **行の操作**: 行にカーソルを置くと、目のボタンに加えて「…」ボタンが出て、右クリックメニューと同じ内容を開く。キーボードでも操作できる
  - 上下で選択を移動、左右で開閉、Enter で名前を編集、Delete で削除、Ctrl / Cmd + D で複製。パネルにフォーカスがあるときだけ
  - 右クリックメニュー: 名前を変更、複製、削除、親を設定・親を外す（デフォーマ、メッシュ）、所属 Part を変更（メッシュ、デフォーマ、Part の親）、配下を選択、配下を開く・閉じる
- **名前の変更・削除・複製**
  - 名前の変更: 行のダブルクリック、F2、メニューからインライン入力。重複・空はエラーとして表示し、変更しない。コマンドは `RenamePart` / `RenameMesh` / `RenameWarp` / `RenameRotation`（またはそれらを 1 つにした形。実装で既存の流儀に合わせる）。曲線の対象（`CurveTarget`）やバインディングは ID で持つので、モデル内の参照は壊れない。名前で保存するファイル（`.tmod` など）への影響は実装時に確認する
  - 削除: メッシュ・デフォーマはそのまま、Part は配下があれば確認ダイアログ（件数を表示）を出して、配下を葉から消す。`Batch` 1 回にまとめ、1 回の undo で戻る。ほかのメッシュのマスクに使われているメッシュの削除、子を持つデフォーマの削除は、既存コマンドの検証に従い、失敗はエラー表示する（連鎖で消す範囲は Part の削除だけ）
  - 複製: メッシュとデフォーマ（子は複製しない）。名前は `<元の名前>.copy`（重複するときは連番）。`AddMesh` などの既存コマンドを `Batch` で組み立てる。キーフォーム・ボーン影響を持つ要素は拒否する（M5-05 と同じ）
  - 所属の変更: `SetMeshPart` / `SetDeformerPart` / `SetPartParent`（循環は失敗）。ドラッグ・メニューの両方から。デフォーマの親付けは M5-05 のコマンドを使う
- **ビューポートの複数選択の表示**（M5-05 の外接矩形の拡張）
  - 選択中のメッシュそれぞれの外周（境界の辺）を、薄い accent の線で描く。最後に選んだもの（主）は太く、濃くする
  - 外接矩形は全選択の合成のまま。隅に選択数のバッジを出す
  - メッシュツール以外で出す。評価後の位置・ライブ反映への追従は M5-05 と同じ
- 範囲外: データの順序の入れ替え（描画順の変更は別）、Part・メッシュのロック、色分けタグ、ツリー間のドラッグでの複数同時移動、ワークスペースをまたぐ開閉状態の保存（未決）

## 方針

- 画面状態（開閉・フィルタ・並び・選択・インライン編集中の名前）は編集モデルに入れない。モデルは `Command` でしか変えない（ADR-0019）
- 行の一覧（開閉・フィルタ・並びを反映）と、キー操作での選択移動・開閉は、描画と分けた純粋関数にしてテストする（M5-02 のパネルの流儀）
- 行は表示中の分だけ作る（`show_rows`）。631 メッシュでも軽い
- 文言は翻訳キーで引く（REQ-UI-005）。新しい依存クレートは足さない

## 未決（レビューで決めたい）

- 開閉・フィルタ・並びの状態をワークスペースの保存に含めるか（既定は含めない）
- 名前変更コマンドの形（4 本か、種別つき 1 本か）。保存ファイル側の名前参照への影響
- 「デフォーマ」パネルに親を持たないメッシュを出さない方針で足りるか（探しにくくならないか）
- キー操作の割り当て（F2・Delete・Ctrl+D は暫定。ほかのアクションとの衝突を確認）
- Part 配下を削除するときの確認ダイアログの文面と、undo の説明（履歴ラベル）

## 検査

- 行の一覧: 開閉・種別フィルタ・名前フィルタ・非表示のみ・並びの組み合わせで期待する行が出る。絞り込み中は祖先が開いて見え、解除で元の開閉に戻る。デフォーマパネルの親子と、メッシュの葉、所属 Part の表示。631 メッシュでも軽い
- 選択: Shift の範囲（メッシュ・デフォーマの混在）、Ctrl のトグル、Part の「配下を選択」、空き地での解除、選択数の表示。ツールの要求しない種別は操作から無視される
- キー操作: 上下・左右・Enter・Delete・Ctrl+D が状態関数としてテストされる。フォーカスがないときは効かない
- コマンド: 名前変更・所属変更が重複・空・循環・存在しない名前で失敗し、モデルが変わらずエラーが UI に出る。成功後の undo / redo で戻る。JSON Schema の一覧に出る（バリアント追加で落ちるテストが通る）。名前変更のあと、曲線の対象・バインディング・マスク・デフォーマの親が壊れない
- 削除・複製: Part の配下の連鎖削除が 1 回の undo で戻る。複製したメッシュ・デフォーマが元と同じ見た目で、キーフォーム付きは拒否される
- ビューポート: 複数選択で、各メッシュの外周と主の強調、選択数のバッジが出る。メッシュツール中は出ない。スナップショット（ライト・ダーク）
- 配置: 両プリセットに「デフォーマ」が含まれ、古い配置を読んでも落ちず補われる（M5-02 の検査に追加）
- 応答: 631 メッシュのツリーで、開閉・絞り込み・選択の操作 1 回が 16 ms 以下（release）
- 依存: ランタイム系クレートに egui 系が現れない（CI）。`tsukumoe-core` が wasm32 でビルドできる

## 受入条件

- [ ] Part とデフォーマの行を開閉でき、すべて開く・閉じるが使える。絞り込み中は一致の祖先が自動で開く
- [ ] 種別（Part・メッシュ・ワープ・回転）と「非表示のみ」で絞り込め、名前の絞り込みと併用できる
- [ ] 「パーツ」と「デフォーマ」が別パネルになり、デフォーマの親子が見える。選択は両パネルとビューポートで共有される
- [ ] 行から名前の変更・複製・削除ができ、Part 配下の削除は確認を経て 1 回の undo で戻る
- [ ] 行にカーソルを置くと操作ボタンが出て、キーボードで選択移動・開閉・名前変更ができる
- [ ] 複数選択のとき、ビューポートで各メッシュの外周と選択数が見える
- [ ] 631 メッシュで操作が 16 ms 以下である

## 決めたこと

- パーツとデフォーマは別の標準パネルにする（利用者の回答）。Part とメッシュはパーツ、デフォーマの階層はデフォーマ
- 追加する機能は、折りたたみ・種別フィルタ・名前の変更・削除・複製・キーボード操作・並びの表示設定（利用者の回答）。データの順序の入れ替えは行わない
- 開閉・フィルタ・並び・選択は画面状態で、編集モデルに入れない
- 名前の変更・所属の変更・削除・複製はすべて `Command`（`Batch`）を通し、undo できる
