## 範囲

- ファイル > 「連番画像・動画で書き出す...」（`file.export-frames`）で、タイムラインで選んだモーションを PNG の連番に書き出す。書き出し先は OS のフォルダ選択（それ以外はパス入力ダイアログ）
- `ffmpeg` が PATH にあれば、同じフォルダに `<モーション名>.mp4` も作る（H.264、`yuv420p`）。無ければ連番画像だけで、画面には何も出さない
- 範囲外: ビューポートのカメラ・背景色の指定、サイズの指定、`ffmpeg` 以外のエンコーダ、パーツ不透明度のカーブの反映（タイムラインの再生と同じ）

## 決めたこと

- **フレーム**: モーションの fps で 1 刻みに 1 枚。ループしないモーションは最後の刻みも書く（`floor(長さ × fps) + 1`）。ループするものは `floor(長さ × fps)`（最小 1）。ファイル名は `<名前>_0001.png`（名前の記号は `_` にする）
- **値**: 各フレームで、パラメータのカーブの値をモデルに入れ、物理を 1 刻み進める（`Frame::advance`）。レンダは CLI の `tsukumoe render` と同じ `tsukumoe-gpu` のヘッドレス
- **カメラ**: 全フレームの頂点を含む箱に固定する（先に全フレームを評価して箱を求め、2 周目で描く）。絵が跳ねない。長辺は 1024px 固定、縦横比は箱に合わせる
- **動画**: 書いた連番画像を `ffmpeg` で束ねる。縦横は偶数に揃える。`ffmpeg` の失敗は、最後の 1 行をそのままエラーに出す
- メニューの項目は、プロジェクトを開いているときだけ有効。モーションを選んでいなければ、エラーを出して何も書かない

## 検証

- `frames_export`: フレーム数、ファイル名、サイズ、`ffmpeg` の引数のテスト。参照モデルで全フレームが PNG になり、`ffmpeg` があれば動画ができるテスト
- `editor`: モーション未選択では何も書かない
- 実機の GUI 操作は `gui-checklist.md` に追記

## 受け入れ基準

- [ ] モーションを選んで実行すると、フォルダに連番画像ができ、`tsukumoe render` と同じ見た目になる
- [ ] `ffmpeg` があれば `.mp4` ができ、再生するとビューポートと同じ動き（長さ・fps が合う）
- [ ] カメラが跳ねない
- [ ] モーション未選択ではエラーが出て、何も書かれない
