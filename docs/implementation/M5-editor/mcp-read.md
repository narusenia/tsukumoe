# MCP の読み取りツール（`tsukumoe-cli`）

- REQ: REQ-AI-001
- 単位: M5-01a
- 状態: 計画中
- 依存: M5-01
- クレート: `tsukumoe-cli`（MCP のツール）。`tsukumoe-core`（モデルの読み取り API。足りなければ足す）

## 目的

エージェントが編集の前提になるモデルの状態を読めるようにする。現状の `get_model` は要素名と件数しか返さず、パラメータの範囲やキーフォーム、親子関係を推測で書くしかない。

## 範囲

- ツール（すべて読み取り専用。モデルも履歴も変えない）
  - `get_tree`: パーツの階層と、各パーツに属するメッシュ・デフォーマ。デフォーマとメッシュの親子。描画順
  - `get_parameter { name }`: 範囲・既定値・繰り返し・グループ・標準パラメータの役割・キー位置・このパラメータに紐づく要素（要素名と種類）
  - `get_element { kind, name }`: `kind` は `mesh` / `warp` / `rotation` / `glue` / `bone` / `part`。共通で名前・親・パーツ・紐づくパラメータとキーフォームの格子。種類別に、メッシュは頂点数・三角形数・外接矩形・テクスチャ・ブレンド・マスク・描画順・色、ワープは格子の大きさと基本形、回転は基本形、グルーは対の数と強さ、ボーンは親・基本形・影響するメッシュ
  - `get_element` の `detail: true` で頂点座標・UV・キーフォームの値を全部返す（既定は要約だけ。大きいメッシュで応答が膨らまないように）
  - `find { pattern?, kind?, bound_to?, unbound? }`: 名前の部分一致（`*` のワイルドカード）・種類・紐づくパラメータ・どこにも紐づかない要素で絞り込む。結果は名前と種類の一覧
  - `get_motion { name }` / `get_expression { name }` / `get_physics { name? }` / `get_bones`: それぞれの定義をコマンドの JSON と同じ形で返す
  - `get_settings`: モデル情報・ヒットエリア・標準パラメータの割り当て
  - `evaluate { params, elements? }`: 指定の姿勢で評価し、要素ごとの変形後の外接矩形・不透明度・描画順を返す。`detail: true` で変形後の頂点
- `get_model` は残す（概要として）
- 範囲外: 画像（M5-01b）、検査（M5-01d）、エディタ上の選択の取得（M5-01i）

## 方針

- 出力の形はコマンドの引数の形に合わせる。読んだものをそのまま書き換えてコマンドに渡せるようにする
- 応答の大きさを抑える。要約を既定にし、全部が要るときだけ `detail` を付ける。配列が長い（頂点 1000 超など）ときは件数だけ返し、`detail` でも上限（1 応答 4 MiB）を超えるならエラーにして範囲指定を促す
- 名前で引けない（存在しない）ときは `isError: true` で、近い名前の候補を最大 5 つ添える
- 読み取りは `Model` の公開 API だけで作る。足りないものは `tsukumoe-core` に読み取り関数を足す（`Command` は増やさない）

## 検査

- 各ツールの往復: 既知のテストモデル（`tsukumoe generate` の出力）で、期待の JSON と一致する
- `get_motion` などの出力を対応する `Add*` / `Set*` コマンドに渡すと、同じものができる（読み書きの往復）
- `evaluate` の値が、`Frame::evaluate` を直接呼んだ結果と一致する
- 存在しない名前・不正な `kind` がツールエラーになり、サーバは落ちない
- 上限を超える `detail` 要求がエラーになる

## 受入条件

- [ ] パラメータ・要素・階層・モーション・表情・物理・ボーン・設定を MCP から読める
- [ ] 任意の姿勢での評価結果を数値で読める
- [ ] 読んだ定義をそのままコマンドに渡して同じものを作れる
