# M5-06e: パラメータの整理

パラメータグループ、ドラッグでの並べ替え、パラメータのコピー・貼り付け（キーフォームを含む）。REQ-EDIT-004。

## 現状

- `Parameter.group: Option<String>` は `core`・`ParameterDto`・保存形式にすでにある。設定するコマンドと UI がない。
- パラメータの順序は `Table` のスロット順で、保存・コンパイル（`.tmod` のパラメータ index）はこの順を使う。並べ替える手段がない。
- パラメータを使う要素（バインディング）は `ParameterId`（スロット）で参照する。

## 決めたこと（利用者確認済み）

- グループは保存に含める（形式の追加は不要。`group` は既存）。
- コピー・貼り付けはキーフォーム・バインディングを含む。
- 並べ替えはドラッグ。
- 要件・仕様書の更新は、糊・設定ダイアログなど未更新分とまとめて行う。

## 範囲

| 項目 | 内容 |
|---|---|
| グループ | `SetParameterGroup { name, group }` コマンド。パラメータパネルはグループ見出しで折りたたみ。グループ名の変更・解除 |
| 並べ替え | `MoveParameter { name, to }` コマンド。ドラッグで順序・グループ間移動（1 ドラッグ = undo 1 回） |
| コピー | 選択パラメータの定義（範囲・既定値・反復・グループ）とバインディング（キー・キーフォーム）を内部クリップボードへ |
| 貼り付け | 新しい名前（`name`, `name_2`…）で作成し、同じ要素へバインド。1 ステップの `Batch` |

## 確認済みの判断

- **順序の持ち方**: 案 A。`Table` に順序リストを持たせ、`iter()` をその順にする。`put`（履歴復元）は位置も戻す。コンパイル・保存・ランタイムの呼び出しは無改修で順序に従う。他の表（パーツ・メッシュ）にも使える。
- **貼り付け先**: コピー元と同じ要素のみ。要素の型が違うとキーフォームの意味が崩れる。
