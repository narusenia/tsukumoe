# 削除の確認ダイアログ（`tsukumoe-app` / `tsukumoe-ui`）

- REQ: REQ-UI-001（エディタの操作性）
- 単位: M5-02d
- 状態: 計画中
- 依存: M5-02、M5-05b、M5-06a
- クレート: `tsukumoe-app`（確認の仕組み、設定の保存）、`tsukumoe-ui`（ダイアログ部品は既存の `dialog` を使う。足りなければ足す）、`tsukumoe-i18n`（文言）。新しい依存クレートは足さない。`tsukumoe-core` には触れない

## 目的

削除の操作が、確認なしで通ってしまう。誤操作の被害を減らすため、削除の前に確認ダイアログを出す。操作に慣れた利用者のため、種類ごとに「次回から表示しない」を選べるようにし、あとから設定で戻せるようにする。

## 範囲

- **確認を出す削除**（エディタの UI からの操作のみ）
  - パーツ、メッシュ、デフォーマ（ワープ・回転）、パラメータの削除（ツリーパネル・パラメータパネル・メニュー・キー・右クリック・パイメニューのどこから呼んでも同じ）
  - パラメータのキーの削除、バインドの解除
  - メッシュの頂点・辺の削除（`mesh.delete-vertices`）
  - 保存したレイアウトの削除
  - 複数選択の削除は 1 回の確認にまとめる（件数と、先頭の数件の名前を出す）
- **ダイアログ**
  - 「何を削除するか」（名前と種別、複数なら件数と数件の名前）、「元に戻せる（Undo）」か（モデルの編集は戻せる、レイアウトの削除は戻せない）を 1 行で伝える
  - 「次回から表示しない」のチェック。種類ごとに別の設定
  - ボタンは「削除」（危険色）と「キャンセル」。Enter で削除、Esc でキャンセル。既定のフォーカスは「キャンセル」とし、Enter 連打で消えないようにする（削除は Enter ではなく明示のクリック、または Cmd/Ctrl+Enter。実装時に決めて「決めたこと」に書く）
- **設定**
  - 種類ごとの「確認する／しない」を、ワークスペースでなく利用者の設定（`confirm.json`、ほかの設定ファイルと同じ設定ディレクトリ）に保存する
  - メニューの設定項目から、種類ごとのオン・オフを一覧で切り替えられる（「次回から表示しない」にした後でも戻せる）。一括で「すべて確認する」に戻すボタン
  - 既定は、すべて「確認する」
- 範囲外: MCP・CLI・スクリプトなど、エージェントからのコマンド（確認なしで通す。Undo で戻せる）、モデルの削除以外の確認（保存していない変更を閉じるときの確認は別の単位）、ごみ箱

## 方針

- 画面状態（ダイアログの開閉、チェックの状態）は編集モデルに入れない（ADR-0019）。新しい `Command` は足さない。確認を通ったときだけ、既存のコマンドを送る
- 削除の入口が複数あるので、確認は 1 か所（`run_action` や削除を組み立てる関数の手前）に集め、入口ごとに足さない
- キー（`Delete` など）で削除したときも同じダイアログを出す。ダイアログが開いている間は、ほかのキー操作を通さない
- 設定ファイルが壊れていた・無いときは、既定（すべて確認する）で動く（読み込みの失敗でエディタを止めない）

## 受け入れ基準

- 上の削除が、すべての入口で確認ダイアログを通る。キャンセルで何も変わらない
- 「次回から表示しない」を付けた種類は、以降確認なしで削除される。再起動しても保たれる。設定画面で戻せる
- 複数選択は 1 回の確認で、件数が正しい
- ダイアログが開いている間、ビューポートやツリーへのキー・クリックが通らない
- 画像比較（ライト・ダーク）、変更したクレートのテスト、fmt、clippy が通る

## 未決・確認

- メッシュの頂点・辺の削除は頻度が高い。既定を「確認する」にするが、使ってみて重ければ既定を変える
- 実機の GUI 操作は利用者の確認待ち
