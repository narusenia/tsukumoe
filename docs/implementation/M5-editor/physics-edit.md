# 物理の設定（`tsukumoe-core` / `tsukumoe-app`）

- REQ: REQ-EDIT-005（物理の設定。振り子物理と物理チェーンの設定、およびその場でのプレビュー）
- 単位: M5-07
- 状態: 実装済み（①。実機の GUI 操作は未確認）。②設定しやすさの改善（型・つまみ・テスト揺らし）も実装済み（実機未確認）
- 依存: M5-02、M1-06（物理の評価）
- クレート: `tsukumoe-core`（コマンドと Undo。評価は変えない）、`tsukumoe-app`（`physics` パネル）。新しい依存クレートは足さない

## 目的

振り子グループ（physics3 互換）と物理チェーンを、エディタで作って編集し、ビューポートの絵がその場で変わるのを見て調整する。

## 前提（現状）

- 型は `tsukumoe-core/src/physics.rs`（`PhysicsRig { pendulums, chains }`、`PendulumGroup`、`PhysicsChain`、`PhysicsInput` / `PhysicsOutput`、`Particle`、`ChainJoint`、`Range`、`Channel`）。`Table` ではなく素の配列。名前は文字列で、`Model` の物理の編集コマンドは無い
- 評価は `simulate.rs`（仕様は `docs/specifications/physics.md`）。`Model::validate()` は入出力のパラメータが消えていないか、出力の粒子番号が範囲内かを検査する。パラメータの削除は、物理が名指ししていれば失敗する
- ビューポートは `Scene::advance(dt)` で物理を進める（ADR-0027）。モデルが変わると `Scene` を作り直し、物理は静止姿勢から始まる。だから設定を変えれば、その場でプレビューに反映される（REQ-EDIT-005 の受入条件）
- 出力パラメータにドライバの出力が重なるとコンパイルエラー（`PhysicsOutputConflict`）。コマンドの時点では検査せず、既存の経路（`Scene` を作れずに出るエラー）に任せる
- `.tproj` の保存（`tsukumoe-format` の DTO）は物理を持っている。追加の保存処理は無い

## 設計

- **コマンド**（すべて `Command`。Undo 1 回で戻る。パラメータは名前で指す）
  - 振り子: `AddPendulum { name }`（粒子 2 つ・入出力なしの既定で作る）、`RemovePendulum`、`RenamePendulum`、`SetPendulum`（入力・出力・粒子・位置範囲・角度範囲を全置換）
  - チェーン: `AddPhysicsChain { name }`（関節 3 つの既定）、`RemovePhysicsChain`、`RenamePhysicsChain`、`SetPhysicsChain`（関節・重力・風・入力・出力を全置換）
  - 検査: 数値は有限、振り子は粒子 1 つ以上、チェーンは関節 1 つ以上、出力の粒子番号は範囲内、重み・半径などは 0 以上（`bad-range`）、入出力のパラメータは存在する。名前は同じ種類の中で一意
- **Undo**: 物理は `Table` ではないので、変更の記録は物理全体の前後（`Change::Physics`）にする。物理は小さいので全体の複製で足りる
- **パネル `physics`**: 上にグループの一覧（振り子とチェーンを 1 つの選択に）と「＋」「ゴミ箱」。選んだグループの下に、入力表（パラメータ・チャンネル・重み・反転）、出力表（パラメータ・チャンネル・粒子・倍率・重み・反転）、粒子（振り子）または関節（チェーン）の表、範囲（振り子）または重力・風（チェーン）。編集は、数値欄が確定したときに 1 回 `SetPendulum` / `SetPhysicsChain` を送る（Undo 1 回）
- **プレビュー**: 設定を変えるたびに `Scene` が作り直されて静止から揺れ始める。入力パラメータのスライダを動かして揺れを見る。「揺れをやり直す」は入れない（Scene の作り直しで足りる）

## 決めたこと（実装）

- 入出力のパラメータはコンボボックスで名前を選ぶ。出力の粒子（関節）の番号もコンボボックス
- チェーンの `rest`（静止の向き）は重力の向きで決まるため、独立した欄は持たない
- 数値欄は確定したとき（ドラッグを離す、フォーカスが外れる）に、グループ全体を 1 回送る
- 粒子（関節）を消すと、その粒子の出力も消し、後ろの出力の番号を 1 つ詰める
- パネル `physics` は、Modeling は履歴・タイムライン・表情の隣、Animation はタイムライン・表情の隣に置く。名前の変更 UI は無い（コマンドはある）
- `Range` は最小 ≤ 既定 ≤ 最大でないと拒否する

## ② 設定しやすさの改善（型・つまみ・テスト揺らし）

生の数値の表だけでは、値の意味・繋ぎ方・確認の手間がつらい。振り子グループに次を足す（コマンドは増やさない。すべて `SetPendulum` に落とす）。

- **型**: 髪（長）・髪（短）・スカート・リボン・耳。選ぶと、粒子の数と並びが入り、つまみの値が決まる。頭の入力が空なら、モデルにあるものを入れる
- **3 つのつまみ**（0〜1）: 揺れやすさ（加速・遅れ）、粘り（動きやすさ）、長さ（粒子の半径）。つまみは粒子 1 から逆算して出し、動かすと粒子 1 以降を作り直す（根は変えない）。粒子ごとに値を変えてあっても、つまみを動かすと揃う
- **頭の入力のチェック**: `ParamAngleX` `ParamAngleZ` `ParamBodyAngleX` `ParamBodyAngleZ` のうちモデルにあるものを並べ、チェックで入力を足す・外す（X は X チャンネル、Z は角度チャンネル。重みは 60 / 40）。他のパラメータは表で足す
- **詳細**: 範囲と粒子の表は「詳細」に畳む。入力・出力の表は出したまま
- **出力を足す**: パラメータパネルでフォーカス中のパラメータを使う（無ければ先頭）
- **テスト揺らし**: ボタンで、選んだグループの入力パラメータを自動で往復させ、揺れを見ながら調整する。止めると元の値に戻る。出力の波形は出さない（ビューポートで見る）
- **図**（振り子のみ）: パネルの上に粒子の鎖を描く。根は固定で、粒子 1 以降をドラッグすると、位置とその粒子の半径（前の粒子との距離）が変わる。ドラッグ中は作業用の複製に溜め、離したときに `SetPendulum` を 1 回送る（Undo 1 回）。ドラッグ中は拡縮を固定し、離したあとにまとめて合わせ直す。パネル内でのシミュレーションは持たない（揺れはビューポートで見る）
- チェーンには型・つまみ・図を付けない（テスト揺らしだけ使える）

## 検証（変更したクレートだけ）

- `tsukumoe-core`: 各コマンドの適用・Undo・不正値の拒否、パラメータを物理が指していると削除できないこと
- `tsukumoe-app`: パネルの kittest（グループを作る、入力の追加、値の確定でコマンドが出る）
- 実機の GUI 操作は `gui-checklist.md` に追記

- [ ] 設定を変えるとビューポートの揺れがその場で変わる
- [ ] 保存して開き直すと同じ内容。変更は Undo / Redo で戻る
