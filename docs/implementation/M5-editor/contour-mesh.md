# 輪郭メッシュ（`tsukumoe-core` / `tsukumoe-app`）

- REQ: REQ-EDIT-002（REQ-AI-005 の最小版を含む）
- 単位: M5-04a
- 状態: 実装済み（実機の GUI 操作は未確認）
- 依存: M5-04
- クレート: `tsukumoe-core`（輪郭抽出・間引き・三角形分割の純粋関数）、`tsukumoe-app`（ツールのアクションとオプション欄）。`tsukumoe-core` は `wgpu` に依存せず `wasm32-unknown-unknown` で動く。新しい依存クレートは足さない

## 目的

メッシュが参照するテクスチャのアルファから輪郭を取り、輪郭に沿った頂点と、内側の格子点でメッシュを作り直す。PSD 取り込み直後の 4 頂点の四角形を、パーツの形に合ったメッシュにする。

AI は使わない。画像処理だけで決まる。REQ-AI-005（自動メッシュ生成）の「頂点密度を指定して生成できる」の最小版にあたり、「目・口で密度を上げる」と AI 出力としての適用（差分プレビュー）は M6-02 に残す。M6-02 はこの単位の関数を土台にできる。

## 範囲

- **アルファの取得**: 編集中メッシュの `texture` が指すテクスチャ（プロジェクトの `textures/*.png`。M5-03 ではレイヤごとに 1 枚）をデコードし、アルファを読む。デコードは既存の経路（`tsukumoe-gpu` / ビューポートが使うもの）を再利用する。経路が `tsukumoe-core` から使えない場合、アルファ（幅・高さ・8 ビット配列）を渡す形にして、デコードは `tsukumoe-app` 側で行う
- **輪郭抽出**（`tsukumoe-core` の純粋関数。入力はアルファ配列・幅・高さ）
  1. 閾値（既定 16 / 255）で二値化する
  2. 外側の輪郭を marching squares で追う。複数の島（離れた部分）は、それぞれ別の輪郭になる。面積が小さい島（既定: 画像面積の 0.1% 未満）は捨てる
  3. Douglas–Peucker で間引く（許容誤差の既定 2 px）
  4. 輪郭を外側へオフセットする（既定 2 px。縁のにじみが切れないように）。オフセットで自己交差する場合は、オフセットを減らして再試行し、0 でも交差するなら輪郭を捨てる
  - 穴（リング状のパーツの内側）は扱わない。外側の輪郭だけで埋める
- **内側の頂点**: 輪郭の内側に、間隔（既定 64 px）の格子点を足す。輪郭から近すぎる点（間隔の 1/4 未満）は足さない。間隔を 0 にすると足さない（輪郭の頂点だけ）
- **三角形分割**: 輪郭を外周とする。
  1. 全頂点を Delaunay で三角形にする（Bowyer–Watson）
  2. 輪郭の辺を M5-04 の `connect`（辺引き）で復元し、輪郭の外側の三角形を取り除く
  3. M5-04 の `retriangulate`（外周のみ拘束）で整える
  - 島ごとに独立の外周を持つ。向きは元のメッシュに合わせる（表向きが反時計回り）
- **UV**: 新しい頂点の位置から、元のメッシュの位置と UV の対応で求める。元の三角形の内側なら重心座標、外側（オフセットで広がった分）は最も近い三角形のアフィン式で外挿する。UV は 0..1 にクランプしない（サンプラのアドレスモードに任せる。扱いは M5-03 の描画と合わせて確認する）
- **コマンド**: 新しい `Command` は足さない。結果は `SetMeshGeometry`（M5-04）1 回で確定する。頂点数が変わるため、キーフォーム・ボーン影響・ブレンドシェイプ・グルーが参照しているメッシュでは、`SetMeshGeometry` が拒否する（既存の検証）。取り込み直後（リグ未作成）に使う前提
- **ツール**: メッシュ編集ツール（M5-04）のアクション `mesh.contour`（キー `C`、暫定）。オプション欄（グリッド敷きの列数・行数と同じ場所）に、閾値・間引き許容誤差・オフセット・間隔の数値欄を置く。状態はツール側が持ち、編集モデルには入れない。実行前に頂点数が変わることを、履歴パネルのラベル（`mesh_contour: <メッシュ名>`）で示す。手で引いた辺・頂点は残らない（M5-04 のグリッド敷きと同じ）
- 範囲外: 穴の扱い、局所的な密度の指定（目・口で上げる）、AI の使用、複数メッシュの一括生成、拘束辺の記憶、リグ済みメッシュの頂点の移行（頂点数が変わるキーフォームの再計算）

## 方針

- 画面状態（オプション値）は編集モデルに入れない。モデルは `Command` でしか変えない（ADR-0019）
- 画像のデコードと輪郭の計算を分け、輪郭の計算は画像ファイルなしでテストできる
- 輪郭の計算は決定的にする（同じ入力で同じ出力）
- 文言は翻訳キーで引く（REQ-UI-005）
- 検証用 PSD（`~/Downloads/DeepSeek-chan/psd/`、再配布不可）はリポジトリに入れない。テストの画像は、コードで生成した形（円・L 字・2 つの島・細い線）を使う

## 未決（レビューで決めたい）

- 既定値（閾値 16、間引き 2 px、オフセット 2 px、間隔 64 px、島の面積 0.1%）は暫定。実際のパーツ（髪の束・目・口）で試して決める
- 細い形（髪の毛の 1 本、まつ毛）で、間引きとオフセットの結果が不安定になる場合の扱い。最小幅を決めて輪郭を捨てるか、間引き許容誤差を自動で下げるか
- UV を 0..1 にクランプするか。オフセットで画像の外へ出る分の描画（縁の色の伸び）が不自然な場合に変える
- キー `C` が既存のアクションと衝突しないか（`tsukumoe-app` のキーマップで確認）
- 穴を扱う時期（リング状のパーツは M5-04a では埋まる）
- アルファのデコード経路を `tsukumoe-core` に置けるか、`tsukumoe-app` に置くか（実装時に既存のコードを確認して決める）

## 検査

- 輪郭抽出: 円・L 字・2 つの島・細い線・全透明・全不透明の画像で、期待する輪郭の数と頂点数の範囲が出る。全透明は `NothingToAdd` 相当のエラー。島の面積の閾値で小さい島が落ちる。同じ入力で同じ出力
- 間引き: 許容誤差の範囲内で元の輪郭に近い（各点との距離が許容誤差以下）。許容誤差 0 で頂点が減らない
- オフセット: 外側へ広がる（面積が増える）。自己交差する入力で再試行して有効な輪郭を返すか、捨てる
- 三角形分割: 結果の三角形の外周が輪郭と一致する。総面積が輪郭の多角形の面積と等しい。向きが保たれる。退化がない。index が範囲内。ランダムな多角形（凸・凹）で不変条件が保たれる。輪郭の外側に三角形がない
- UV: 元の頂点位置での UV が元と一致する。外側の点は外挿で連続する
- コマンドの流れ: `SetMeshGeometry` 1 回で確定し、1 回の undo で元の 4 頂点に戻る。キーフォームを持つメッシュでは拒否され、モデルが変わらずエラーが UI に出る
- ツール: `mesh.contour` が状態関数としてテストされる（オプション値の反映、アルファが取れない場合のエラー表示）
- 応答: 基準モデルの実画像（コードで生成した 1024×1024 相当のアルファ）で、輪郭抽出から確定までが 100 ms 以下（人が 1 回押す操作。連続操作ではない）。実測値を記録する
- 描画: `egui_kittest` のスナップショットで、オプション欄を固定する（ライト・ダーク）
- 依存: `tsukumoe-core` が `wgpu` に依存せず、`wasm32-unknown-unknown` でビルドできる（CI）。新規依存なし

- [ ] 離れた島を持つパーツで、島ごとに輪郭が作られる
- [ ] 閾値・間引き・オフセット・間隔を変えて結果を調整できる
- [ ] リグを持つメッシュでは拒否され、エラーが画面に出る
- [ ] 実際の PSD のパーツ（髪・目・口）で試し、使えるメッシュになることを確認した

## 決めたこと

- AI は使わず、画像処理（二値化・輪郭追跡・間引き・三角形分割）で作る。M6-02（自動メッシュ生成）は、この単位の関数を使い、局所密度と AI 出力の適用を足す
- 新しい `Command` は足さず、`SetMeshGeometry` で確定する
- 外側の輪郭だけを扱い、穴は埋める。島は別々の輪郭
- 手で引いた辺・頂点は残らない。リグ済みメッシュでは拒否する
- 三角形分割は M5-04 の `connect`・`retriangulate` を再利用し、一般の多角形の三角形分割を別に作らない
- 実装での決定: アルファのデコードは `tsukumoe-app` が行う（`Document::texture_alpha`。`tsukumoe-gpu` の `Texture::from_png` を再利用し、`tsukumoe-core` は `contour::Alpha`（幅・高さ・8 ビット配列）だけを受ける）。`tsukumoe-core` に `contour` モジュールを 1 つ置き、輪郭抽出・間引き・オフセット・三角形分割・UV の対応づけをここに入れた
- 輪郭は画素中心の格子で marching squares を行い、辺の交点は 2 画素中心の中点に置く（補間しない）。穴は捨て、穴の中の島は穴を埋める外側に含めて捨てる。1 つの島の点（輪郭 + 内側の格子）は 3000 まで（`TooManyPoints`）、間隔は 0 または 4 px 以上
- 輪郭と格子点は画素座標で求め、UV は画素座標を画像の大きさで割った値にした（元メッシュの位置と UV の対応は位置の計算にだけ使う）。位置は元の三角形の重心座標、外側は最も近い三角形のアフィン式で外挿する。UV はクランプしない
- 実画像（髪・目・口）での確認、既定値の妥当性は未確認。計画書の受入条件の最後の項目は未達
- `mesh.contour` は右クリックメニュー（M5-04）にも並ぶ
