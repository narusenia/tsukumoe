# メッシュ編集（`tsukumoe-core` / `tsukumoe-app`）

- REQ: REQ-EDIT-002
- 単位: M5-04
- 状態: 計画中
- 依存: M5-02
- クレート: `tsukumoe-core`（コマンドの追加と、三角形分割の純粋関数）、`tsukumoe-app`（メッシュ編集ツール）、`tsukumoe-cli`（コマンド一覧の自動生成に新コマンドが出る確認のみ）。`tsukumoe-core` は `wgpu` に依存せず `wasm32-unknown-unknown` で動く

## 目的

アートメッシュの頂点・辺を、ビューポート上で追加・削除・移動できるようにする。すべての操作を `Command` として記録し、undo できる（REQ-EDIT-002 の受入条件）。

## 範囲

- **コマンド**: `SetMeshGeometry { name, positions, uvs, indices }` を 1 本足す。頂点の追加・削除、辺の付け替え、三角形分割はすべて UI 側で新しい配列を作り、このコマンドで確定する。検証は `AddMesh` と同じ（`positions` と `uvs` の長さ一致、`indices` が 3 の倍数で範囲内）。頂点数が変わるとき、そのメッシュを参照するキーフォームやデフォーマの頂点データが壊れないかを調べ、壊れる場合は失敗させる（M3 以降のリグが未実装の範囲は、参照がないことを確認して通す）
- **三角形分割**（`tsukumoe-core` の純粋関数。`Command` とは別に、UI とテストから呼ぶ）
  - 頂点の追加: 含む三角形を 3 分割する。辺の上に置いたときは両側の三角形を 2 分割する。全体の再分割（Delaunay の再計算）はしない。手で付けた辺を壊さないため
  - 頂点の削除: その頂点を囲む多角形を耳切りで三角形に張り直す。張り直せない場合（外周の頂点で凹になるなど）は削除を拒否してエラー表示
  - 辺を引く: 選んだ 2 頂点の間に辺を作る。すでにある辺ならなにもしない。交差する辺を反転（flip）で順に消して、2 頂点が直接つながるまで繰り返す。収束しない場合（凹四角形で反転できない）は拒否する
  - 辺の反転: 隣り合う 2 三角形が凸四角形のときだけ、対角線を付け替える
  - 反転と辺引きの結果、メッシュの外形（外周）は変わらない。三角形の向きは元のメッシュに合わせる
- **ツール**（ビューポートの差し込み枠に載せる。ツール切替はキーマップのアクション `tool.mesh-edit`）
  - 選択: クリック（頂点優先、次に辺）、Shift でトグル追加、矩形ドラッグで範囲内の頂点を追加。なげなわは本単位では作らない
  - 移動: 選択した頂点をドラッグ。ドラッグ中は編集モデルを変えず、プレビューだけ動かす。放した時に `SetMeshGeometry`（位置のみの変更は既存の `SetMeshPositions`）を 1 回送る
  - 追加: 空の場所をクリックで頂点を足す（メッシュの外周の内側のみ。外側は拒否）。辺の上をクリックで辺を分割
  - 削除: 選択した頂点を Delete で消す。複数選択は 1 コマンドにまとめる
  - 辺を引く: 頂点を 2 つ選んで `E`（暫定）。辺を選んで `F` で反転
  - 対象メッシュは、ツリーの選択（または、ビューポートで最前面のメッシュをクリックして選択）で決める。メッシュ編集中は他のメッシュを薄く描く
  - 描画: 頂点・辺・選択をオーバーレイで重ねる。ビューポートの 16 ms 予算（REQ-PERF-008）を守る
- **自動メッシュ（REQ-AI-005）は別単位**。呼び出し口（ツールバーのボタン枠）も作らない
- 範囲外: なげなわ選択、UV の編集、メッシュの結合・分割、頂点のスナップ、メッシュの複製、フローティングパネル

## 方針

- 画面状態（選択された頂点・辺、ツールのプレビュー）は編集モデルに入れない。モデルは `Command` でしか変えない（ADR-0019）
- ドラッグは放した時に 1 コマンド。操作ごとに履歴へ 1 行出し、履歴パネルの名前で何をしたか分かるようにする
- ツールの状態（選択・ドラッグ中）はツールが持ち、純粋な状態関数としてテストできる形にする（M5-02 のパネルと同じ）
- 文言は翻訳キーで引く（REQ-UI-005）

## 未決（レビューで決めたい）

- 辺を引く・辺の反転のキー（`E`・`F` は暫定。「Cubism 互換」の割り当てはメンテナーが確認）
- 辺を引くとき、交差する辺を反転で消す方式で足りるか。失敗する形（凹の頂点が間にある場合）が実際のメッシュでどれだけ出るか。足りなければ、拘束付き Delaunay（拘束辺を記憶する）へ変える
- 頂点を足すときの UV は、含む三角形の重心座標から補間する（暫定）。これで足りるか
- 削除で多角形を張り直せない場合に拒否ではなく、近傍の頂点を巻き込んで張り直すか

## 検査

- コマンド: `SetMeshGeometry` が検証で拒否する形（長さ不一致・範囲外の index・3 の倍数でない）で、モデルが変わらずエラーを返す。成功したあとの undo / redo で元の配列に戻る。JSON Schema のコマンド一覧に出る（バリアント追加で落ちるテストが通る）
- 三角形分割: 頂点追加で三角形の総面積が変わらず、向きが保たれる。辺上への追加で隣の三角形も分割される。削除で面積が保たれる。反転が凸四角形のときだけ成功する。辺引きで 2 頂点が直接つながり、元の外周が変わらない。基準モデルのメッシュで、ランダムな操作列のあとに「三角形が退化していない・外周が同じ・index が範囲内」の不変条件が保たれる
- ツール: 選択（クリック・Shift・矩形）、移動の確定（放した時に 1 コマンド）、削除、追加、辺を引く・反転が状態関数としてテストされる。ドラッグ中はモデルが変わらない
- 応答: 基準モデルの最大メッシュ（631 メッシュのうち頂点数最大）で頂点ドラッグ中のフレーム時間が 16 ms 以下
- 依存: `tsukumoe-core` が `wgpu` に依存せず、`wasm32-unknown-unknown` でビルドできる（CI）
- 描画: `egui_kittest` のスナップショットで、メッシュ編集中の見た目を固定する（ライト・ダーク）

## 受入条件

- [ ] ビューポートで頂点を選択（クリック・Shift・矩形）して移動でき、放した時に 1 回の undo で戻る
- [ ] 頂点の追加・削除ができ、三角形が張り直される。張り直せない削除は拒否されてエラーが出る
- [ ] 2 頂点を選んで辺を引け、辺を選んで反転できる
- [ ] すべての操作が `Command` として履歴パネルに出て、undo / redo できる
- [ ] 基準モデルの最大メッシュで頂点ドラッグ中のフレーム時間が 16 ms 以下である

## 決めたこと

- 頂点・辺の変更は `SetMeshGeometry` 1 本で確定する。操作別のコマンドは作らない（コマンドとパレット・MCP の面を増やさないため）
- 三角形分割は全体の再計算をしない。頂点追加は局所分割、削除は多角形の張り直し、辺引きと反転は辺の反転で行う。手で付けた辺を保つため。辺を引く機能は後回しにせず本単位に含める（利用者の要望）
- 選択は頂点・辺の単純選択と矩形。なげなわは範囲外
- 自動メッシュ（AI-005）の呼び出し口は本単位で作らない
