# PSD 読み込み（`tsukumoe-psd` / `tsukumoe-cli` / `tsukumoe-app`）

- REQ: REQ-EDIT-001
- 単位: M5-03
- 状態: 完了
- 依存: M5-02
- クレート: `tsukumoe-psd`（新規。PSD リーダと取り込み計画。egui・wgpu に依存しない）、`tsukumoe-core`（コマンドの追加）、`tsukumoe-cli`（`tsukumoe psd`）、`tsukumoe-app`（取り込みダイアログ）

## 目的

PSD のレイヤ構成をパーツとメッシュとして取り込む。PSD を差し替えて再読み込みしたとき、レイヤ名で対応づけて、既存のメッシュ・リグを保ったまま画像だけを更新する。

## 範囲

- **PSD リーダ（自前の最小実装、依存追加なし）**: 8 / 16 ビットの RGB。レイヤ画像は非圧縮と RLE（PackBits）。レイヤ名（Unicode）、グループ（開始・終了の区切り）、不透明度、ブレンドモードのキー、非表示フラグ、レイヤの位置と大きさを読む。16 ビットは 8 ビットに落とす。
  - 非対応は、黙って捨てず、明確なエラーか警告にする: ZIP 圧縮のチャンネル、RGB 以外の色モード（CMYK・Lab・インデックス・グレースケール）、PSB（エラー）、レイヤマスク・調整レイヤ・レイヤ効果（警告して無視）。クリッピングは下記のとおり
  - 上限（既定。設定で変えられる）: キャンバスの一辺 16384 px、レイヤ 4096 枚、1 レイヤの展開後 512 MiB、全レイヤの展開後の合計 16 GiB（異常な入力を弾くための値で、通常は届かない）
  - メモリ: 1 レイヤずつ展開して PNG に書き、解放する。全レイヤを同時にメモリへ持たない（実測した検証用 PSD は展開後の合計が約 0.97 GiB）
- **取り込み計画**: PSD と現在のモデル・プロジェクトから、変更の計画（追加・変更・消えたもの・画像が変わったもの）を作る。計画は純粋な値で、適用前に一覧できる。適用は `Batch` コマンド 1 つにまとめ、1 回の undo で戻る
- **対応づけ**: キーは「グループのパス + レイヤ名」（`/` 区切り）。同じキーが複数あれば上からの順番で区別する。対応は `sources/psd-map.json` に持つ（下記）
- **レイヤ → モデルの対応**:
  - グループ → `Part`（グループの入れ子は `Part` の親子）。レイヤ → `ArtMesh`（所属は親グループの `Part`、トップのレイヤは取り込み用のルート `Part` に入れる）
  - メッシュの初期形はレイヤの外接矩形の四角（頂点 4・三角形 2）。細分と自動メッシュは M5-04 / AI-005
  - 描画順は PSD の重なり順（下が奥）、不透明度は PSD の値。ブレンドは Normal / Additive / Multiply のみ。PSD の「通常」（`norm`）、「乗算」（`mul `）、「覆い焼き（リニア）- 加算」（`lddg`）を対応させ、それ以外（`over`・`sLit` など）は Normal にして警告する。グループの「通過」（`pass`）はレイヤのブレンドではないので警告しない
  - 非表示レイヤは取り込み、メッシュの可視フラグを偽にする（不透明度は PSD の値のまま）。可視フラグは新設する（下記「可視フラグ」）
  - クリッピング（下のレイヤの形で切り抜く）は、`ArtMesh.masks`（切り抜き元のメッシュ）に対応づける。ランタイムのマスクの意味（切り抜き元の形かアルファか）を `docs/specifications/rendering.md` で確認し、PSD のクリッピングと同じ結果になるときだけ対応づける。ならないときは警告して無視する
- **テクスチャ**: レイヤごとに 1 枚の PNG（不透明部分の外接矩形に切り詰める。全透明のレイヤは警告してメッシュを作らない）を `textures/` に置く。メッシュの UV は、そのレイヤ画像の 0..1 に対応する。アトラス化は M5-09 の書き出しで行い、UV を付け替える
- **元 PSD の扱い**: `sources/psd-map.json` に、元ファイルのパス・ハッシュ・キャンバスの大きさと、レイヤごと（キー、メッシュ名、`Part` 名、テクスチャ、キャンバス上の矩形、画像のハッシュ、PSD 側の不透明度・ブレンド・可視）を記録する。PSD 本体はコピーしない（REQ-FMT-001 の「参照」）
- **再読み込み**: 次を差分として計画に出す。
  - 新規レイヤ: 追加する
  - 消えたレイヤ: メッシュを残す / 削除する（項目ごとに選ぶ）
  - 名前が変わったレイヤ: 「消えたレイヤ」を「新規レイヤ」に手で対応づけられる
  - 画像が変わったレイヤ: テクスチャを差し替え、UV を付け替える。キャンバス上のピクセルの位置を保つ（古い UV をキャンバス座標に戻し、新しい矩形で UV を計算し直す）。頂点位置・キーフォーム・リグは変えない
  - PSD 側の不透明度・ブレンド・可視・クリッピングが変わったレイヤ: 取り込み後にユーザーが編集していないものだけ更新する（記録した PSD 値と現在値が同じなら更新する）
- **可視フラグ**: `ArtMesh` に `visible`（既定は真）を足す。非表示のメッシュは描画リストに入れない（`Part` の `visible` と合わせ、どちらかが偽なら描かない）。プロジェクト形式の `model.json` に任意の項目として足して、JSON Schema を再生成する（既存ファイルは真として読む。形式の MINOR を上げるかを `docs/specifications/file-formats.md` の規則で確認する）。`.tmod` への影響は同じ規則で確認する。操作は `SetMeshVisible`（`SetPartVisible` と同様）で、UI のツリーのパネルと将来のキーフォーム編集（可視の切替）で使う
- **コマンドの追加**: いまの `Command` にはテクスチャ・ブレンド・描画順・UV を変える操作が無い。取り込みに必要な分だけ足す。
  - `AddMesh` にテクスチャ番号の引数（省略時 0）、または `SetMeshTexture`
  - `SetMeshBlendMode`、`SetMeshOpacity`、`SetMeshDrawOrder`、`SetMeshUvs`、`SetMeshVisible`、`SetPartVisible`、`SetMeshMasks`
  - どれも JSON でシリアライズでき、undo / redo でき、M5-01 の MCP / CLI から自動で使える（`docs/reference/commands.md` を再生成する）
- **CLI**: `tsukumoe psd inspect <psd>`（レイヤ構成と警告を JSON で出す）、`tsukumoe psd import <project> <psd> [--plan] [--apply]`（計画の表示と適用。再読み込みの選択は `--keep-missing` / `--remove-missing`、手で対応づけるときは `--map 古いキー=新しいキー`）
- **エディタ**: ファイルメニューに「PSD を取り込む…」。パスを入力し（ファイルピッカーは依存追加が要るため M5-02 と同じ入力ダイアログ）、差分の一覧（追加 / 消えた / 画像変更 / 対応づけ）を見せ、確定すると 1 コマンドとして適用する。対応づけのやり直しは同じダイアログから
- 範囲外: PSD の書き出し、ZIP 圧縮・PSB・CMYK、レイヤマスクの取り込み、スマートオブジェクトの再計算、自動メッシュ、アトラス生成、MCP への取り込みツールの公開（取り込みはファイルを読む操作で、モデルを変える `Command` ではないため。公開するかは別途判断）

## 方針

- PSD は外部由来。ヘッダ・各セクションの長さ・レイヤ数・チャンネル長・RLE の行長を境界検査し、宣言サイズを信用しない。上限を超える入力は、メモリを確保する前に拒否する。パニックしない
- 色は PSD の非乗算アルファのまま、PNG（RGBA 8 ビット、非乗算）に書く。色空間の変換はしない
- 取り込み計画は純粋な関数で、入力が同じなら出力も同じ（決定的）。ファイルと GUI に触れない
- 対応づけの結果と警告は、利用者が適用前に全部見える形にする。黙って捨てるものを作らない
- モデルを変えるのは `Command` だけ（ADR-0019）。テクスチャ PNG の書き込みは、コマンド適用が成功した後に行い、失敗時に孤立した PNG を残さない
- メッシュ名・`Part` 名は「パス + レイヤ名」をそのまま使う（日本語を含む）。既存の名前表（一意）に衝突するときは、取り込み側で番号を付ける

## 検査

- リーダ: テスト用の最小 PSD ライタ（テストコードのみ。外部の PSD を使わない）で作った PSD を読む。8 / 16 ビット、非圧縮と RLE、入れ子のグループ、Unicode 名、不透明度、ブレンドキー、非表示、レイヤの位置と大きさ、全透明レイヤ
- 拒否: ZIP 圧縮・PSB・非対応の色モードが明確なエラーになる。上限超過・宣言サイズの嘘・途中で切れた入力・RLE の行長の不整合・巨大なレイヤ数が、メモリを確保せず拒否される。バイト列の変異テストでパニックしない
- 計画: 新規 / 消えた / 名前変更（手の対応づけ）/ 画像変更 / PSD 側の値変更のそれぞれで、計画が期待どおり。同名レイヤが上からの順で区別される。同じ入力で同じ計画
- 再読み込みの保持: 取り込み後にメッシュ形状・キーフォーム・パラメータを編集し、画像の大きさと位置が変わった PSD を再読み込みしても、頂点位置・キーフォーム・パラメータが変わらず、キャンバス上のピクセルの位置が保たれる（UV の付け替えをテストで確認）。ユーザーが編集した不透明度・ブレンドは上書きされない
- コマンド: 追加した各コマンドが JSON の往復と undo / redo のテストを通る。取り込み全体が 1 回の undo で戻る。失敗した適用でモデルとファイルが変わらない
- ブレンド: 通常・乗算・加算が対応し、それ以外は警告つきで Normal になる。グループの `pass` は警告しない
- 可視フラグ: 偽のメッシュが描画リストに入らない。`Part` が非表示でも入らない。保存・読み込みで保たれ、既存のファイル（項目なし）は真として読める。`SetMeshVisible` が JSON の往復と undo / redo を通る。JSON Schema が更新されている
- クリッピング: `masks` に対応づけたとき、切り抜き元のメッシュが入る。対応づけられない場合は警告が出る
- 実 PSD（メンテナーが用意したもの。リポジトリには入れない）: `psd inspect` でレイヤ構成と警告が出る。`psd import` が完走し、プロジェクトが `tsukumoe validate` を通り、エディタで開いてビューポートに描画される。所要時間とピークメモリを報告する
- CLI: `psd inspect` / `psd import --plan` / `--apply` の出力と、適用後に `tsukumoe validate` が通る
- エディタ: 取り込みダイアログの状態（差分の一覧・選択・確定）を純粋な状態としてテストする。実機では、実際の PSD を取り込んでビューポートに描画されることを確認する
- 依存: 追加の外部依存なし（`png` は既存）。`tsukumoe-psd` が egui・wgpu に依存しない

- [x] 不正な PSD でパニックせず、非対応の形式は明確なエラーまたは警告になる
- [x] CLI（`tsukumoe psd`）とエディタの両方から取り込める

## 決めたこと

- パーサは自前の最小リーダ。依存を足さない（ZIP 圧縮は初回は非対応、必要になった時点で deflate 依存を確認して足す）
- テクスチャは「レイヤごとに 1 枚（余白を切り詰める）」で持つ。アトラス化は M5-09 の書き出しで行う
- 再読み込みでは、取り込む前に差分を見せ、項目ごとに選ばせる（新規・消えた・画像変更・名前変更の手の対応づけ）。適用は 1 つの `Batch`
- 対応づけのキーは「グループのパス + レイヤ名」。同名は上からの順
- `ArtMesh` に可視フラグを新設する（利用者の要望。非表示レイヤの表現と、編集中の表示切替に使う）。不透明度 0 での代用はしない
- 1 レイヤずつ展開して PNG に書く（検証用 PSD の展開後の合計が約 0.97 GiB のため）
- PSD 本体はプロジェクトにコピーせず、`sources/psd-map.json` に参照・ハッシュ・対応を記録する

### 未決の解決（M5-03 の実装時に確定）

- **テクスチャ番号とファイルの対応**: `ArtMesh.texture` は `textures/*.png` のパス順の位置（`file-formats.md` 1.3 の既存規則。`model.json` に対応表は持たない）。取り込みは `textures/psd-NNNNNN.png`（6 桁の連番、既存の最大 + 1）に置く。新しいファイルでパス順が動き、既存メッシュの番号がずれるときは、同じ `Batch` の中で `SetMeshTexture` により付け替える。画像の置き換えは同じパスへの上書きで、番号は変わらない。消えたレイヤのテクスチャのファイルは残す（番号を動かさないため）
- **ルート `Part` とトップレベル**: ルート `Part` の名前は `PSD`（衝突するときは ` (2)` を付ける）。トップレベルのレイヤはルート直下のメッシュ、トップレベルのグループはルートの子 `Part`。`Part` 名はグループのパス、メッシュ名は対応づけのキーと同じ。グループの不透明度は `Part.opacity`、非表示は `Part.visible` に対応づける（グループのブレンドは使わない）。消えたグループの `Part` は残す
- **座標系**: 1000 px を 1 単位、x は右、y は上（描画空間は Y 上向き、`rendering.md`）、キャンバスの左上を原点とする（キャンバスは y が負の側に広がる）。キャンバスの大きさが変わっても既存の頂点がずれない。UV の (0, 0) は画像の左上。四角の三角形は表向きが反時計回りになる順（`[0,3,2]`, `[0,2,1]`）。倍率は `sources/psd-map.json` の `units_per_pixel` に記録する。描画順（`draw_order`）は PSD の重なり順の位置（最下が 0）
- **クレート追加の記録**: `docs/specifications/architecture.md` のクレート表に `tsukumoe-psd` を追加し、ADR-0015 には追記だけ行う（方針の範囲内のため新しい ADR は起こさない）。`scripts/check-deps.sh` に「`tsukumoe-psd` は `tsukumoe-core` にだけ依存する」を加えた
- **実 PSD の確認**: リポジトリに入れてよい PSD は無い。テストはテスト専用の最小 PSD ライタ（`tsukumoe-psd` の `test-writer` feature）で作る。メンテナーの PSD での確認結果は実装の報告に書く
- **クリッピングと `masks`**: `rendering.md` 3 節のマスクは「切り抜き元のメッシュのテクスチャのアルファ（その不透明度・色・自身の `masks` は無視）」で、係数は 4 節のブレンドの前に、描画する側のプリマルチ済みの色とアルファに掛かる（`s' = s * m`、そのあと通常のブレンド）。Normal・Multiply・Additive のどれでも、ブレンド後は PSD で切り抜いた結果と同じになるため、切り抜かれる側のブレンドは条件にしない。ブレンドが対応づけられず Normal に落ちる層（`over`・`sLit` など）も、形の切り抜きは効かせ、`blend_mode` の警告は残す（文言で「切り抜きはするが色は近似」と示す）。条件として残すのは切り抜き元（同じグループで下にある、クリッピングでない最初のレイヤ）だけで、「通常ブレンド・不透明度 255・表示・ピクセルあり」でなければ警告して無視する。ベースのブレンドと不透明度は PSD ではクリッピンググループ全体に掛かるが、ランタイムのマスクはアルファだけを使うため再現できない。ベースが非表示のとき PSD は組ごと隠すが、マスクは隠れたメッシュの形でも効くため再現できない。ベースがグループのときとピクセルが無いときは対象が無い。対応づけたときは `SetMeshMasks`（反転なし）で、記録は `psd-map.json` の `clip_base`
- **メモリ**: 走査と PNG 書き出しは 1 枚分のレイヤのバッファを使い回す（`decode_layer_into`）。以前はレイヤごとに RGBA と切り詰めの複製を確保し、macOS のアロケータが解放済みの大きな領域を保持して、検証用 PSD の `psd import --plan` のピークが約 530 MB、`--apply` が約 540 MB だった。使い回しと切り詰めなしのハッシュ（`hash_rect`）にして、`--plan` は約 82 MB、`--apply` は約 240 MB、同じ PSD の再読み込みは約 135 MB（プロジェクトのテクスチャ 631 枚を読むため）になった。バッファの確保回数はテスト（`layer_buffer_allocations`）で見る
- **既知の制約**: 取り込み済みの検証用プロジェクトを `tsukumoe render` で描くとピークが約 2.4 GB になる（レンダラが 631 枚のテクスチャをすべて読む）。この単位では直さない
- **可視フラグの形式**: `model.json` のメッシュに任意の `visible`（既定 true）を足し、プロジェクト形式を 1.1 に上げた（MINOR は任意の内容の追加、`file-formats.md` 1.1 節）。`.tmod` は任意のセクション `0x9A mesh_hidden`（偽のメッシュの番号の昇順）を、あるときだけ書く。再生系の任意セクションと同じ扱いで、`.tmod` の MINOR は 0 のまま（隠すメッシュの無いファイルはこれまでと同じバイト列、古い読み手はセクションを飛ばして全メッシュを描く）
- **取り込みの実装上の決め**: 16 ビットは `(v * 255 + 32767) / 65535` で 8 ビットに落とす。16 / 32 ビットの PSD でレイヤが `Lr16` / `Lr32` の追加ブロックにある場合も読む。画像のハッシュは SHA-256（既存の依存 `sha2`）で、切り詰めた後の大きさとピクセルに対して取る。名前の変更で手動対応づけをしたメッシュは、名前と所属 `Part` を変えない（改名のコマンドが無いため）。同名キーは上から順に、先頭は接尾辞なし、2 つ目以降は `#1`, `#2`。エディタは PSD を別スレッドで読む（走査に数秒かかるため）

## 検証用 PSD（メンテナーが用意）

- 手元の `~/Downloads/DeepSeek-chan/psd/` にある PSD を、動作確認だけに使う（学習・モデリング練習用として配布されたもの。再配布とアップロードは禁止されている）。**リポジトリに入れない**。取り込んで得たテクスチャ・プロジェクトもリポジトリに入れず、一時領域に置く。外部のサービスに送らない
- 同じフォルダのモデル本体（`DeepSeek/`）は開かない（ADR-0016: 他人のモデルは解析しない）。使うのは PSD だけ
- 実測（`tsukumoe-psd` の実装前に読み取り専用で調べた）: 3749 × 7697、RGB 8 ビット、レイヤ 872（グループの区切り 236 を含む）。圧縮は非圧縮と RLE のみ（ZIP なし）。ブレンドは `norm` 716、`pass` 97、`mul ` 54、`lddg` 3、`over` 1、`sLit` 1。非表示 138、不透明度が 255 でない 125、クリッピング 72、レイヤマスク 5。最大のレイヤは 3575 × 3679。展開後の合計は約 0.97 GiB
- クレジットが必要な公開（動画・投稿など）に使うときは、原画「神宫凉子」を表記する規約になっている。このリポジトリには作品を載せないので、表記は不要
