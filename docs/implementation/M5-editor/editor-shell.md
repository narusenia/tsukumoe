# エディタの骨格（`tsukumoe-app`）

- REQ: REQ-UI-004, REQ-PERF-008
- 単位: M5-02
- 状態: 計画中
- 依存: M1-14
- クレート: `tsukumoe-app`（新規。エディタ本体）、`tsukumoe-ui`（部品・トークン・キーマップ層。必要な部品を足す）。ランタイム系クレートは egui 系に依存させない（REQ-UI-003）

## 目的

M5-03 以降の編集機能を載せる土台を作る。ドック・ワークスペース・ビューポート・コマンドの流れ・キーマップの骨格までを作り、個別の編集ツールは作らない。

## UI 設計方針

- **Cubism に寄せる層は「概念と操作語彙」まで**。用語（パラメータ・デフォーマ・キーフォーム・アートメッシュなど）、ワークフローの順序、主要ショートカット、マウス操作の意味を Cubism に合わせる。既定の画面レイアウトと見た目は Tsukumoe 独自に設計する。そのうえで、パネルの配置だけを Cubism 風に並べる「配置プリセット」を選べるようにする（移行直後の迷いを減らすため）。見た目（配色・アイコン・文言）は Cubism を模倣せず、トークンで統一したまま
- **UX 改善**は次の 6 つに絞る。ほかは M5-02 では扱わない
  - パイメニュー: エディタ上のどこでも、キー（既定は右クリック長押しまたは専用キー。要確認）で円形メニューを出し、ツール切替・よく使うコマンドを方向で選ぶ。割り当ては利用者が変えられる
  - どこでもドラッグでパラメータ操作: 数値欄・スライダに限らず、ビューポート上でも、修飾キー + ドラッグで割り当てたパラメータ（既定は顔の角度 XY など）を直接動かす。ドラッグ量とパラメータの対応は設定できる
  - コマンドパレット: 全編集コマンドを検索して実行する
  - undo 履歴パネル: コマンド列を一覧し、任意の時点へ戻る
  - キーマップのプリセット: 既定は「Cubism 互換」。割り当ては利用者が変更・保存できる
  - AI 変更の差分プレビュー（REQ-AI-004）の置き場所: パネルの枠だけ確保し、中身は AI 機能の単位で作る
- 高密度の既定（ADR-0027: 文字 12pt・コントロール高 24pt）と、ライト / ダーク / システムのテーマを使う

## 範囲

- **ワークスペース**: 「モデリング」「アニメーション」の 2 つ。同じアプリ・同じプロジェクト・同じ編集中モデルのままタブで切り替え、ドック配置はワークスペースごとに保存する。M5-02 では切替の仕組みと空のパネルだけ作り、中身は M5-04 以降で足す
- **ドック**: 自前の最小ドックを `tsukumoe-ui` に作る。分割（水平・垂直、境界のドラッグで比率変更）・タブ・タブのドラッグ移動・配置の保存と復元まで。フローティングは本単位では作らない。配置は serde で JSON に往復できる木構造で、ワークスペースごとと配置プリセットがこれを使う。見た目はトークンで統一する
- **配置プリセット**: ワークスペースごとに「Tsukumoe（既定）」と「Cubism 風」の 2 つを同梱し、メニューから切り替える（現在の配置を上書きする前に確認を出す）。利用者が組んだ配置を名前を付けて保存・呼び出しもできる。プリセットはドックの配置データ（JSON）で、コードに埋め込まない
- **標準パネル（骨格）**: ビューポート、パーツ・デフォーマのツリー、パラメータ、インスペクタ、undo 履歴、コマンドパレット。ツリーとパラメータには名前の検索・絞り込みを付ける
- **ビューポート**: `tsukumoe-host` の viewer と同じく、egui-wgpu の device で `tsukumoe-gpu` が描く。パン・ズーム（Cubism と同じ割り当て）。ツール（選択・メッシュ編集など）を差し込む枠を持つが、ツールは作らない
- **コマンドの流れ**: エディタの編集はすべて `Command`（M1-02）を 1 つの送信口に通す。UI の操作も、のちに足す外部（MCP / CLI）も同じ口を使う。送信口の先は `Model::apply`。undo / redo と履歴パネルはここから得る。外部からの受け付け（ソケット等）は本単位では作らず、別単位として起票する
- **パイメニュー**: egui に無いため `tsukumoe-ui` に部品として作る（方向と距離で選択、放して確定、中心でキャンセル）。項目はキーマップのアクションを引く。階層（サブメニュー）は 1 段まで
- **ドラッグでパラメータ操作**: ビューポートの入力層に「ドラッグ → パラメータ値」の割り当て（ドラッグ軸・感度・対象パラメータ・修飾キー）を持たせる。パラメータの現在値は編集モデルに入れず、編集外の表示状態として評価に渡す（`Parameter` は min・max・default のみで、現在値を持たない。undo の対象外）。ホストの viewer の Space + ドラッグ（`feat/viewport-key-drag`）と競合しない割り当てにする
- **コマンドパレット**: `Command` のスキーマ（M5-01 の `schema` feature）から一覧を作る。引数の入力はスキーマからフォームを生成する簡易版
- **キーマップ**: `tsukumoe-ui` のキーマップ層（文脈つき）の上に、エディタのアクション（ツール切替・undo・パン・ズームなど）を登録し、プリセット「Cubism 互換」を同梱する。割り当ての変更と保存ができる
- **プロジェクト**: 開く・保存・未保存の表示・最近のプロジェクト。保存は `tsukumoe-format` を使う
- 範囲外: 個別の編集ツール（M5-03〜）、PSD、起動中エディタへの外部送信の実装、複数プロジェクトの同時編集、キーボードショートカットの網羅

## 方針

- 画面状態（ドック配置・選択・ビューポートのカメラ）は編集モデルに入れない。モデルは `Command` でしか変えない（ADR-0019）
- ビューポートの更新は入力から 16 ms 以下（REQ-PERF-008）。即時モードなので、操作中と物理が落ち着くまでだけ再描画し、止まっているときは描かない（ADR-0027）
- パネルは「描画」と「状態」を分け、パネル単位でテストできる
- 文言は翻訳キーで引く（REQ-UI-005）
- Cubism の画面・アイコン・文言を複製しない。操作語彙は一般に知られた範囲で合わせ、割り当ての根拠はメンテナーが確認できるもの（自分が使った経験）に限る

## 未決（レビューで決めたい）

- 「どこでもドラッグ」の解釈: ビューポート上でのドラッグ操作（顔の向きなど）を指すのか、画面上のあらゆる数値欄でドラッグ調整できることを指すのか、両方か。ここでは両方としている
- パイメニューの呼び出しキーと項目の初期割り当て
- 「Cubism 互換」キーマップの中身（主要ショートカットの一覧）。メンテナーに確認が要る
- 標準パネルの初期配置（モデリング / アニメーションそれぞれ、「Tsukumoe」と「Cubism 風」の 2 種）。「Cubism 風」の並べ方はメンテナーが確認する
- コマンド一覧のメタデータ生成（現状 `tsukumoe-cli`）を、エディタからも使えるよう共有の置き場へ移すか
- ドックの配置の保存先（プロジェクトに入れるか、利用者設定に入れるか）。推奨は利用者設定
- フローティングパネルを足す時期（M5-04 以降で必要になった時点）
- 上流 `egui_dock` が egui 0.37 に対応した場合に、自前ドックから乗り換えるか（0.21.1 は egui 0.36 依存、0.37 化の PR #354 は未マージ。2026-11-01 時点）

## 検査

- ドック: 配置を保存して復元すると同じになる。壊れた配置ファイルを読んでも落ちず、既定の配置に戻る
- ワークスペース: 切替で編集モデル・undo 履歴が保たれ、配置はワークスペースごとに独立する
- 配置プリセット: 2 種とも読み込めて全標準パネルを含む。切替後に再度切り替えても配置が壊れない。名前を付けた配置の保存・呼び出しが往復する
- コマンドの流れ: UI 操作 → 送信口 → `Model::apply`。失敗したコマンドでモデルが変わらず、エラーが UI に出る。undo / redo / 履歴パネルの選択で任意の時点に戻る
- コマンドパレット: `Command` の全バリアントが一覧に出る（バリアント追加で落ちるテスト）
- キーマップ: プリセットが読み込め、割り当て変更が保存・復元される。競合する割り当てを検出する
- パイメニュー: 方向と距離から項目を選ぶ判定（中心・各扇形・外側）と、放した時の確定・キャンセル
- ドラッグ操作: 割り当てどおりにパラメータが動く。範囲外にはクランプされる。現在値は undo 履歴に載らない（モデルを変えない）。割り当ての保存と復元
- 応答: 基準モデルでパラメータをドラッグ中のフレーム時間が 16 ms 以下
- 描画: `egui_kittest` のスナップショットでパネルの見た目を固定する（ライト・ダーク）
- 依存: ランタイム系クレートに egui 系が現れない（CI）。`cargo tree -d` に重複がない

## 受入条件

- [ ] 「モデリング」「アニメーション」を切り替えられ、ドック配置がそれぞれ保存・復元される
- [ ] 配置プリセット「Tsukumoe」「Cubism 風」を切り替えられ、利用者の配置を名前を付けて保存できる
- [ ] 標準パネル（ビューポート・ツリー・パラメータ・インスペクタ・undo 履歴）が出て、ツリーとパラメータを名前で絞り込める
- [ ] 編集は 1 つの送信口を通り、undo / redo と履歴パネルからの時点移動ができる
- [ ] パイメニューを呼び出して、ツール切替・コマンドを選べる
- [ ] ビューポート上の修飾キー + ドラッグで、割り当てたパラメータを動かせる
- [ ] コマンドパレットから全編集コマンドを検索して実行できる
- [ ] 「Cubism 互換」プリセットと、割り当ての変更・保存ができる
- [ ] 基準モデルでパラメータをドラッグ中のフレーム時間が 16 ms 以下である

## 決めたこと

- Cubism に寄せるのは概念と操作語彙まで。既定のレイアウトと見た目は独自。パネル配置だけは「Cubism 風」プリセットで選べる
- ワークスペースは「モデリング / アニメーション」の切替。M5-02 は仕組みだけ
- ドックは自前の最小実装（分割・タブ・ドラッグ移動・配置の保存）。`egui_dock` 0.21.1 は egui 0.36 依存で本リポジトリの 0.37 と合わず、上流 main も 0.36 のため見送った（未マージの PR に依存しない）
- UX 改善はパイメニュー・どこでもドラッグでパラメータ操作・コマンドパレット・undo 履歴・キーマップのプリセット・AI 差分プレビューの置き場の 6 つ
- パラメータの現在値は編集外の表示状態で、undo 対象外（Cubism のスライダ操作と同じ扱い）。「放した時に 1 コマンド」は、ドラッグでモデルを変えるツール（デフォーマ移動など）の確定に適用する
- 起動中エディタへの外部送信は、送信口の設計だけ本単位で行い、実装は別単位
