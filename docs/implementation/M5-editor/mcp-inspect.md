# MCP の検査ツール（lint・物理の試走）

- REQ: REQ-AI-002
- 単位: M5-01d
- 状態: 計画中
- 依存: M5-01a, M5-01b
- クレート: `tsukumoe-core`（検査の規則）、`tsukumoe-cli`（MCP のツール・CLI）

## 目的

`validate` は壊れているかどうか（参照切れ・範囲外）しか見ない。壊れてはいないが直したほうがよい点を構造化して返し、物理の動きも画像なしで確かめられるようにする。

## 範囲

- `lint` ツールと `tsukumoe lint <project>`
  - 規則（それぞれ ID・重さ `error` / `warning` / `info`・対象の要素名・説明を返す）
    - 使われていないパラメータ（紐づく要素・モーション・表情・物理の出力がない）
    - どのパラメータにも紐づかないデフォーマ
    - テクスチャの範囲外にはみ出した UV
    - 面積 0 の三角形、どの三角形にも使われない頂点
    - キーフォームの格子の欠け（キーはあるが値が既定のまま、など判定できるもの）
    - 左右の名前の組（`L` / `R` など）があるのに、片側にだけキーやバインドがある
    - 物理の入力・出力が存在しないパラメータを指す
    - 標準パラメータ（まばたき・口の開閉など）が割り当てられていない
  - 引数で規則の ID を絞れる。結果は規則・要素名の順で安定させる
- `simulate` ツール: 物理を `seconds`（最大 10）秒、指定のモーションまたはパラメータの時系列を入力にして動かし、出力パラメータの時系列（`fps` 既定 30）を返す。`render: true` で M5-01b の並べた画像も返す
- 範囲外: 規則の自動修正（M5-01f の高水準ツールを使う）

## 方針

- 規則は `tsukumoe-core` の `lint` モジュールに置き、CLI・MCP・将来のエディタの表示が共有する（`validate` とは分ける。`validate` は壊れたモデルを拒む用途のまま）
- 物理は `core/simulate.rs` をそのまま使う。固定の時間刻みで回し、結果は決定的にする
- 左右の名前の組の判定は、`mirror` の名前の対応規則と同じものを使う（M5-01e で移した後に共有する。それまではこの規則だけ後回しにしてよい）

## 検査

- 規則ごとに、該当するテストモデルで 1 件出て、直したモデルで 0 件になる
- 結果の並びが同じモデルで毎回同じ
- `simulate` が同じ入力で同じ時系列を返す。入力なしで静止のまま
- 上限超えの `seconds` がツールエラーになる

## 受入条件

- [ ] モデルの検査結果を構造化データで受け取れる（REQ-AI-002 の 3 つ目）
- [ ] 物理の動きを数値（と画像）で確かめられる
