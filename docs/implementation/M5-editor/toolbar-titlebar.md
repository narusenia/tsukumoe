# ツールバーと独自タイトルバー（`tsukumoe-app` / `tsukumoe-ui`）

- REQ: REQ-UI-001（エディタの操作性）
- 単位: M5-02c
- 状態: 実装済み（実機の GUI 操作は未確認）
- 依存: M5-02、M5-04b
- クレート: `tsukumoe-app`（ツールバー、タイトルバー、ウィンドウ操作）、`tsukumoe-ui`（共通部品が要れば）。新しい依存クレートは足さない。`tsukumoe-core` には触れない

## 目的

- 編集ツールの切替とプロポーショナル編集のオン・オフが、キーとメニュー（パイメニュー）にしかない。ビューポートの上に、アイコンで見えて押せる場所を置く
- OS の標準タイトルバーをやめ、アプリの見た目に合わせた独自のタイトルバーにする。メニューバー・ワークスペースのタブ・プロジェクト名を、1 行にまとめる

## 範囲

### ツールバー

- ビューポートの左上に浮かせて重ねる（ドックのパネルではない）。縦に並べる。ヘルプ行・プロポーショナルの操作箱とは重ならない位置に置く
- 中身（アイコンのボタン。名前とキーはツールチップ）
  - ツール切替: 選択（`tool.select`）、メッシュ（`tool.mesh-edit`）、デフォーマ（`tool.deformer`）。いまのツールは押された状態で示す
  - 補助の切替: プロポーショナル編集（`proportional.toggle`）。オン・オフを押された状態で示す
- ボタンは既存のアクションを実行するだけ。キー・メニュー・ツールバーで同じ経路（`run_action`）を通し、状態は `ViewState`（保存しない）
- アイコンは既存の Lucide から選ぶ。足りなければ追加するが、新しい依存は足さない
- 範囲外: Undo / Redo、ファイル操作、ワイヤ・グリッド・スナップの表示切替（まだ機能がない）、ツールバーの並べ替え・設定

### 独自タイトルバー

- Windows / Linux: OS の枠を消し（`with_decorations(false)`）、自前で描画する。macOS: OS の枠は残し、中身をタイトル領域まで広げる（信号機・角丸・影・リサイズ・全画面は OS のもの。下の「実装での決定」を参照）
- 1 行に並べるもの
  - 左: アプリ名とプロジェクト名（未保存は印）。macOS はシステムのメニューバーを使うので、ウィンドウ内のメニューは出さない（M5-02a の方針のまま）。Windows / Linux はメニューをここに置く
  - 中央: ワークスペースのタブ（いまメニュー行にあるものを移す）
  - ウィンドウボタン（Windows / Linux のみ）: 最小化、最大化（復元）、閉じる。右に置く。macOS は OS の信号機を使う。macOS の最大化ボタンは全画面ではなく最大化とする（OS の既定に合わせるなら全画面。実装時に実機の挙動を見て決め、「決めたこと」に書く）
- 空いている所のドラッグでウィンドウを移動、ダブルクリックで最大化と復元
- 枠のリサイズ（Windows / Linux のみ）: 四辺と四隅に細い当たり判定を置き、ドラッグでリサイズ。最大化中・全画面中は出さない。カーソルをリサイズの向きに変える
- 閉じるボタンは、未保存の変更があれば既存の確認（終了時の流れがあればそれ、なければ今の閉じ方）と同じにする。新しい確認は足さない。いまの閉じ方を最初に調べ、「決めたこと」に書く
- ウィンドウのタイトル（OS のタスクバー・Mission Control に出る名前）は、プロジェクト名に合わせて更新する
- 自前の枠（Windows / Linux）には角丸・影は付けない（OS ごとの差が大きいため）。枠の線だけ引く
- 範囲外: ウィンドウ位置・大きさの保存、タイトルバーの高さ・並びの設定、macOS の信号機ボタンそのものの再現（自前の見た目のボタンにする）

## 方針

- 画面状態（ツールバーの表示・タイトルバーの状態）は編集モデルに入れない（ADR-0019）。新しい `Command` は足さない
- ウィンドウ操作は egui の `ViewportCommand`（移動・リサイズ・最小化・最大化・閉じる）で行う。足りない操作があれば、最初に確かめて「決めたこと」に書く
- ツールバーとタイトルバーは、ライト・ダークの両テーマで読める色にする（`tsukumoe-ui` のテーマ値を使い、色の直書きをしない）
- 動作中のフレーム時間は予算 16 ms を守る。既存の `frame_time` 系の測定が通ること

## 受け入れ基準

- ツールバーのボタンで、3 つのツールが切り替わる。キー・メニューで切り替えたときも、ボタンの押された状態が追随する
- プロポーショナルのボタンで、オン・オフが切り替わり、`O` キーとも同期する
- タイトルバー: 移動、最小化、最大化と復元、閉じる、ダブルクリック、四辺・四隅のリサイズができる（`ViewportCommand` を出すことはテストで確かめ、実際の OS の動作は実機で確かめる）
- ワークスペースのタブがタイトルバーに移り、メニュー行はなくなる（macOS ではタイトルバーのみ、Windows / Linux ではメニューとタイトルバーが同じ行）
- 画像比較: ツールバーとタイトルバーを、ライト・ダークの両方で撮る
- 検証一式（fmt、clippy `-D warnings`、`cargo test --workspace`、wasm32、`cargo deny check`、依存検査）が通る

## 未決・確認

- 実機（macOS）の見た目・リサイズ・全画面の挙動は、利用者の確認待ち
- Windows / Linux は、実機がなく未確認。ビルドと `ViewportCommand` の発行までを確かめる
- ツールバーの位置（左上の縦並び）は、使ってみて変える可能性がある

## 実装での決定

実装時に決めたこと。本文は変えていない。

### 調べたこと

- 今の閉じ方: 確認も保存の問いもなく、OS の閉じるでそのままウィンドウが閉じる（`CancelClose` も `close_requested` の処理もない）。そこで閉じるボタンは `ViewportCommand::Close` を送るだけにした。新しい確認は足していない。未保存のまま閉じる問題は従来のまま残る
- `ViewportCommand`（egui 0.37）: `StartDrag`（移動）、`BeginResize(ResizeDirection)`（8 方向）、`Minimized`、`Maximized`、`Fullscreen`、`Close`、`Title` がそろっている。足りない操作はなかった
- 最大化と全画面: 最大化ボタンは `Maximized(!今の状態)`（macOS のズーム相当）。全画面にはしない。最大化と全画面のどちらでも、復元の絵とリサイズ辺の非表示に切り替える（`ViewportInfo` の `maximized` / `fullscreen`）。装飾なしの macOS ウィンドウでズームが効くかは未確認

### 決めたこと

- ツールバー: ビューポートの左上、ヘルプ行とプロポーショナルの操作箱の下（上から 72 pt）に縦並び。選択（新規アイコン `mouse-pointer-2`）、メッシュ（`Image`）、デフォーマ（`Grid`）、プロポーショナル（`Locate`）。押された状態は `Variant::Primary`。ボタンは `run_action` に渡すだけで、`ViewState` の値から毎フレーム描くので、キーやメニューの切替にも追随する。ツールチップは「名前（キー）」
- アイコンは Lucide の `mouse-pointer-2` だけ追加（他は既存）。ギャラリーの画像を更新した。ウィンドウボタンの絵（最小化・最大化・復元・閉じる）は線で描き、アイコンは足していない
- タイトルバー: `panels/titlebar.rs`。描画はウィンドウ操作（`WindowOp`）を返すだけで、`command()` が `ViewportCommand` に変える。そのため送る命令はテストで確かめられる
  - 並び: macOS はウィンドウボタンが左（閉じる・最小化・最大化）、Windows / Linux は右（最小化・最大化・閉じる）。その隣にアプリ名、プロジェクト名（未保存は `●`）、メニュー（macOS は出さない）、ワークスペースのタブ
  - タブは中央寄せにせず、メニューの続きに置いた（幅が決まらず揃えにくいため）。見た目の確認後に直す余地がある
  - 空きの押し込みで `StartDrag`、ダブルクリックで最大化と復元。ダブルクリックは kittest で押せないので、命令の対応だけテストし、クリックは実機で確かめる
  - 閉じるボタンの hover は `error` 色、他は `control_hover`。色はテーマ値のみ
- リサイズ: 四辺（5 pt）と四隅（12 pt）に当たり判定を置く。隅が辺より先に当たる。カーソルは各向きの `Resize*`。最大化中・全画面中は出さない。外枠の線（`border_strong`）は常に引く。角丸と影はなし
- OS のタイトル: `ViewportCommand::Title` を、変わったときだけ送る。「プロジェクト名（未保存は ` *`）- Tsukumoe」、未オープンは「Tsukumoe」
- `ViewportBuilder` は `with_decorations(false)` と最小サイズ 640 x 400 を足した。ウィンドウ位置・大きさは保存しない

### 検証

- fmt、clippy `-D warnings`、`cargo test --workspace`、wasm32（core・runtime・wasm）、`cargo deny check`、`scripts/check-deps.sh` は通った
- release の測定（GPU あり、p99 / 予算 16 ms）: パラメータ操作 2.65 ms、メッシュ頂点ドラッグ（AccessoryMesh14）3.82 ms、デフォーマ格子点 3.49 ms、プロポーショナル（参照 225 頂点）3.3 ms / 1.9 ms。合成 10 000 頂点のプロポーショナルは今回 14.1 ms / 11.3 ms（前回 8.0 / 7.5 ms、GPU なし、同じコード。他の処理と重なった測定のばらつきと見ている）
- 画像比較: エディタ全体（タイトルバー込み、ライト・ダーク）を更新、ツールバーを新規に追加（ライト・ダーク）

### 未確認・差

- 実機の GUI 操作は未確認: 移動、リサイズ、最小化、最大化と復元、閉じる、ダブルクリック、カーソルの向き
- 装飾なしの macOS ウィンドウでの最大化（ズーム）と、システムのメニューバーとの共存は未確認。Windows / Linux はビルドと `ViewportCommand` の発行まで
- タイトルバーのフレーム時間は、専用の測定を足していない（既存の `frame_time` 系は通った）
- 計画書の目的にある「メニュー行をなくす」は、メニューとタブを 1 行にまとめることで満たした（macOS はタイトルバーのみ）

### 追加修正: macOS は OS の枠を残す

利用者の指摘（角丸がない、信号機ボタンを使えないか）を受けて、上の決定のうち macOS の部分を変えた。

- macOS の `ViewportBuilder`: `with_fullsize_content_view(true)`、`with_titlebar_shown(false)`、`with_title_shown(false)`。`with_decorations(false)` は使わない。信号機ボタンは既定のまま出す（`with_titlebar_buttons_shown` は触っていない）。Windows / Linux は `with_decorations(false)` のまま。`cfg(target_os = "macos")` で分けた
- 理由: 自前では角丸・影・信号機の挙動（全画面、Option での最大化、Mission Control）を揃えきれない。macOS は OS の枠のほうが利用者の期待に合う
- macOS では自前のウィンドウボタンとリサイズ辺、外枠の線を出さない。`titlebar::Chrome`（`Native` / `Custom`）で分け、`show` と `frame` が引数で受けるので、どちらもテストできる（`Native` は信号機の分 76 pt を左に空け、ボタンと辺が出ないこと）。実行時の選択は `titlebar::CHROME`（OS で決まる定数）
- タイトルバーの高さは macOS で 33 pt（実機で信号機の中心に合わせた）に揃えた
- 空き部分のドラッグ移動（`StartDrag`）とダブルクリックの最大化（ズーム）は、自前の `interact` が両方の枠で効くようにしてある。装飾を消した macOS ウィンドウで `StartDrag` とズームが実際に効くかは未確認
- 画像比較は実行した OS の枠で撮る（macOS では信号機の場所を空けた形。信号機そのものは OS が描くので画像には写らない）。Windows / Linux の自前の枠は画像比較に入らず、ボタンの動作と命令の対応のテストだけが見る
- 未確認（実機）: 信号機の位置と高さが 33 pt の行に合うか、信号機と重なる部分がないか、ドラッグとダブルクリック、全画面、角丸と影
