# パラメータとキーフォームの編集（`tsukumoe-core` / `tsukumoe-app`）

- REQ: REQ-EDIT-004（パラメータとキーフォームの編集）
- 単位: M5-06a（パラメータとキー）、M5-06b（キー位置での形の編集）、M5-06c（左右反転コピーと多次元）。a → b → c の順に、1 つずつ実装して実機で確かめる
- 状態: M5-06a は実装済み（実機の GUI 操作は未確認）、M5-06b・M5-06c は計画中
- 依存: M5-02、M5-04、M5-04b、M5-05
- クレート: `tsukumoe-core`（コマンド、評価は変えない）、`tsukumoe-app`（パラメータパネル、ツールのキー対応）、`tsukumoe-format`（変更が出たとき）。新しい依存クレートは足さない

## 目的

パラメータを動かして形が変わる仕組み（キーフォーム）を、エディタで作って編集できるようにする。顔の向き・まばたき・口の開きのように、キー位置ごとに頂点・格子点・回転・不透明度を決め、キーの間は補間される。

編集のやり方は Live2D と同じ。パラメータのスライダをキー位置に合わせ、その位置の形を、これまでのツール（メッシュ・デフォーマ）でそのまま直す。

## 前提（現状）

- 要素（メッシュ・ワープ・回転・ほか）は `keyforms: Option<KeyformGrid<_>>` を持つ。`KeyformGrid` は `Binding`（パラメータの軸と各軸のキー位置）と、全キー組み合わせの形の列（最初の軸が最も遅く変わる、密な並び）からなる。同じパラメータ・同じキーに反応する要素は 1 つの `Binding` を共有する（ADR-0018）
- 評価は、キーフォームがあればそれを補間し、なければ基本形（`base_points` ほか）を使う。評価は変えない
- パラメータは `AddParameter` / `RemoveParameter` / `SetParameterRange` がある。キーフォームを作る・変えるコマンドはない
- M5-05 は、キーフォームを持つ要素の基本形の編集を `HasKeyforms` で拒否している（基準モデルのデフォーマは全部キーフォーム付き）。M5-06b でこの拒否をなくす

## M5-06a: パラメータとキー

- **パラメータの編集**（パラメータパネル）
  - 作成、削除、名前変更、範囲と既定値の変更、繰り返し（`repeat`）の切替。いずれも `Command`（`AddParameter` / `RemoveParameter` / `SetParameterRange` は既存。名前変更の `RenameParameter` を追加。名前で引いている式・物理・ポーズ・モーションの参照が壊れないことを実装時に確かめ、「決めたこと」に書く）
  - 削除は、そのパラメータにバインドされた要素があれば、そのキーフォームの軸を落とす（既定値の位置の形を残す）か、拒否するかを実装時に決める
- **バインド**
  - 選んだ要素（メッシュ・ワープ・回転、のちほかの種別）を、パラメータにバインドする。バインド直後は、範囲の両端と既定値の 3 キー（既定値が端と同じなら 2 キー）で、全キーフォームが今の形の複製。見た目は変わらない
  - 要素から軸（パラメータ）を外す。軸が 1 つになると外せない（キーフォームをなくす）かどうかは「バインドを外す」で別に扱う
  - 既存の `Binding` と同じ軸・同じキーなら共有する
- **キーの追加・削除**
  - 軸にキーを追加するとき、新しいキーの形は、その位置の補間結果で埋める（追加しても見た目が変わらない）。削除は、そのキーの形を捨てる（両隣の間が補間になる）
  - `Binding` を共有する要素は、すべて同じキーに揃える（1 つの `Command` で全要素の格子を更新する）。共有をやめて切り離す操作は範囲外
- **パラメータパネル**
  - スライダに、選択中の要素のキー位置を目盛りで出す。キー位置では目盛りに吸着する（Shift で吸着なし）
  - 「キーを追加」「キーを削除」「前のキーへ」「次のキーへ」。選択中の要素がバインドされていなければ「バインド」ボタン
  - 画面状態（スライダの値、選択）は編集モデルに入れない（ADR-0019）
- 範囲外: 形の編集（06b）、反転コピーと複数軸の組み合わせの編集（06c）、パラメータの並べ替え・グループ化

## M5-06b: キー位置での形の編集

- **編集できる条件**
  - 選択要素がバインドされていて、そのすべての軸のパラメータ値がキー位置に（許容誤差内で）合っているとき、そのキーフォームが編集対象。合っていないときは編集を拒否し、トーストで「キー位置に合わせてください」と伝える
  - バインドされていない要素は、いままでどおり基本形を編集する
- **編集の種類**
  - ワープの格子点: デフォーマツールで動かすと、その位置のキーフォームの格子点が変わる。プロポーショナル編集（M5-04b）はそのまま使える
  - メッシュの頂点: メッシュツールで動かすと、その位置のキーフォームの `positions` が変わる。頂点の追加・削除・辺の付け替え（形が変わる操作）は、キーフォームがあるメッシュでは拒否する（全キーの頂点数がそろわなくなるため）。拒否の文言を決めて「決めたこと」に書く
  - 回転デフォーマ: 角度・拡大・反転・軸の位置が、その位置のキーフォームに入る
  - 不透明度と描画順: インスペクタの値が、その位置のキーフォームに入る（描画順はメッシュのみ）
- **M5-05 の拒否の解禁**
  - 基本形の移動、リセット、回転の軸の移動、親の付け替えが、キーフォームを持つ要素でも通る
  - 移動・リセット: キー位置にいれば、その位置のキーフォームだけを変える。リセットは、その位置のキーフォームを、ワープなら作成時の格子（`rest_points`。なければ等間隔）、回転なら角度 0・拡大 1・反転なしに戻す
  - 軸だけの移動・親の付け替え: 子の見た目を保つため、全キーフォームに同じ変換をかける（1 つの `Batch`）
- **コマンド**
  - キーフォームの 1 つを置き換える `SetMeshKeyform`、`SetWarpKeyform`、`SetRotationKeyform`（キーの添字は `Binding` の各軸のキー番号の列。実装時に JSON の形を決める）。確定は放した時の 1 コマンド、undo 1 回
  - ライブ反映は `Scene::set_preview` と同じ仕組みで、編集中のキーフォームの形で評価する（モデルは変えない）
- **表示**: 編集中のキー（パラメータ名と値）を、ビューポートのヘルプ行の下に出す。キー位置にいないときは、その旨を薄く出す
- 範囲外: 反転コピー、複数軸の組み合わせの一括操作、形が変わる操作のキーフォーム全体への自動反映

## M5-06c: 左右反転コピーと多次元

- **左右反転コピー**（REQ-EDIT-004 の受入条件）
  - あるキーのキーフォームを、別のキーへ、左右（X）反転してコピーする。反転の中心線は既定でモデルの X 中心、変更できる
  - ワープの格子点: 中心線で鏡映し、列の並びを入れ替える。回転: 角度の符号を反転、軸の位置を鏡映。メッシュ: 頂点を鏡映し、対応する頂点を最も近い点で対にする（対が取れなければ拒否）
  - 左のパーツのキーを右のパーツ（別要素）へ反転コピーする操作も範囲に入れる（目の左右など）
- **多次元**（REQ-EDIT-004 の受入条件）
  - 要素に 2 つ目のパラメータをバインドする（軸を足す）。足した直後は、全組み合わせのキーフォームが今の形の複製で、見た目は変わらない
  - 組み合わせキーの編集は 06b のまま、各軸のスライダをキーに合わせて行う。パラメータパネルに、選択要素の軸と、いま編集中の組み合わせを出す
  - 軸の入れ替え（最初の軸が最も遅く変わる並び）の影響は `Binding` 側で閉じる
- 範囲外: 物理・ポーズ・グルー・ボーンのキーフォーム（`f32` や `BoneTransform` の型）の編集 UI（M5-05a・M5-07 ほかで扱う）、キーフォームの補間方式の変更

## 方針

- 画面状態（選択、スライダの値、編集中のキー）は編集モデルに入れない。モデルは `Command` でしか変えない（ADR-0019）
- 新しい `Command` は JSON Schema と `docs/reference/commands.md`（LF）を自動生成する既存の流れに乗せる。形式（`tsukumoe-format`）に変更が出るときは、先に利用者へ確認する
- 評価・補間（`eval.rs`）は変えない。変える必要が出たら止めて報告する
- 16 ms の予算を守る。キー位置の判定・目盛りの描画は毎フレーム走るので、要素数に対して軽く保つ。既存の `frame_time` 系の測定が通ること
- ツールの拒否（キー位置にいない、形が変わる操作）は、エラーにせずトーストで伝える（M5-04・05 と同じ流儀）

## 受け入れ基準

- 06a: パラメータの作成・削除・名前変更・範囲変更ができる。要素のバインド、キーの追加・削除ができ、追加・バインド直後に見た目が変わらない。共有している要素のキーがそろう。undo 1 回で戻る
- 06b: キー位置で格子点・頂点・回転・不透明度を編集でき、キーの間のスライダ位置で補間されて動く。キー位置にいないときは拒否される。基準モデルのデフォーマ（キーフォームつき）も編集できる。M5-05 の拒否が、キーフォームを持つ要素で通る
- 06c: 反転コピーで、左右対称の形が作れる。2 つ目のパラメータをバインドして、組み合わせキーを編集できる
- 各単位で、画像比較（ライト・ダーク）と、変更したクレートのテスト、clippy、fmt が通る。`tsukumoe-core` に触れた単位は wasm32 のビルドも通す

## 未決・確認

- 実機の GUI 操作は、各単位で利用者の確認待ち
- パラメータの削除の扱い（軸を落とす／拒否）、名前変更時の参照の追随は、06a の実装時に決める
- 反転の対応づけ（メッシュの頂点の対）は、06c の実装時に精度（許容誤差）を決める

## M5-06a 実装での決定

実装時に決めたこと。本文は変えていない。

- **モデル形式（`tsukumoe-format`）は変えていない**。評価（`eval.rs`）も変えていない
- **コマンド（`tsukumoe-core`）**: `RenameParameter`、`SetParameterRepeat`、`BindParameter`、`UnbindParameter`、`AddParameterKey`、`RemoveParameterKey`。対象の要素は `ElementRef`（`{"kind":"mesh","name":..}` か `{"kind":"deformer","name":..}`）。`schema` の生成物と `docs/reference/commands.md`（LF）を更新した（`model.schema.json` は変化なし）。履歴に載る変更を、バインドの配列（`Change::Binding`）とドライバ（`Change::Driver`）にも広げた。拒否は `CommandError::Refused { name, reason }`（固定のキー）
- **キーの形の埋め方**: 追加・削除・軸の削除・初回のバインドを、すべて 1 つの再サンプル（`keyform_edit::resample`）で作る。新しい格子は、各キーの組み合わせで旧格子が評価と同じ多重線形補間（端の外は端のキーに貼り付き）で返す値を取る。回転の反転フラグは補間せず、最も重いキーの値（評価と同じ）。だから、キーを足しても見た目は変わらない（テストで複数のパラメータ値の描画位置を比べている）
- **バインド直後**: キーはパラメータの最小・既定・最大（重なれば 2 つか 1 つ）。全キーフォームは今の形の複製。すでにキーフォームを持つ要素は `already-bound` で拒否（2 軸目は M5-06c）。範囲が点（最小 = 最大）のパラメータは範囲そのものが不正なのでバインドに入らない
- **共有 `Binding`**: 同じ軸・同じキーなら 1 つを共有する（同じコマンドでも別のコマンドでも、`Binding` が等しければ既存の ID を使う）。キーの追加・削除は、`Binding` を直接書き換えず、新しい `Binding`（または等しい既存のもの）を作り、その上の全要素（メッシュ・ワープ・回転）を新しい格子へ移し、使う要素がなくなった古い `Binding` を消す。履歴は配列の変更と要素の変更を一緒に記録するので、1 回の undo ですべて戻る。グルー・ボーンが同じ `Binding` に乗っているとき（編集 UI の範囲外の型）は、キーの追加・削除を `shared-with-other-kinds` で拒否する
- **キーの削除**: 値が一致するキー（完全一致）だけ。無ければ `no-such-key`、軸の最後の 1 キーは `last-key`
- **パラメータの削除**: 軸を落として拒否しない方を選んだ。`param_ops::delete_parameter` が、そのパラメータに乗る全要素の `UnbindParameter`（既定値の位置の形を残し、軸が尽きれば基本形にしてキーフォームをなくす）と `RemoveParameter` を 1 つの `Batch` にする。undo 1 回で全部戻る。ほかが名前で参照している（ドライバ・物理・モーション・表情・ポーズ・グルー・ボーン）ときは既存の整合性検査で失敗し、何も変わらない（トーストで知らせる）。そのための事前確認 UI は足していない
- **`RenameParameter` と名前参照の洗い出し**: 名前で引いているのはドライバの式の文字列だけ（物理・モーション・表情・ポーズ・バインドは `ParameterId`）。式を字句の規則（数値と関数名を飛ばす）で書き換え、同じ `Command` の中で名前変更と一緒に行う（`expr::rename_name`。undo で式も戻る）。式が読んでいる名前を、式に書けない名前（識別子でない）に変えようとしたときは `not-an-identifier` で拒否する。読まれていなければ任意の名前に変えられる。式の外の参照（ランタイム API・書き出した .tmod）は書き換えず、トーストで知らせる
- **パラメータパネル**: ラベルのクリックは、パラメータを選択せず、編集対象（`ViewState::param_focus`、保存しない）にする。編集部は、名前（フォーカスを外したときに確定）、削除、最小・既定・最大（ドラッグや入力の終わりに 1 コマンド）、繰り返し、前後のキー、キーの追加・削除、バインド、バインド解除、キー位置の一覧（キー上なら ◆）。キーは選択中の要素のうちパラメータに反応する最後の 1 つのもの。スライダの目盛りと吸着（6 pt 以内、Shift で吸着しない）は、その要素のキーを使う
- **画面外の割り切り**: スライダの目盛りの位置は、egui のスライダの内側の余白（高さの 1/2.5）で近似している。キーの追加・削除の対象要素は、選択の最後の 1 つを選ぶので、複数選択のときの切替 UI はない
- **ビューへの追随**: 名前変更でスライダの値とフォーカスと選択を新しい名前に移す。削除で値・フォーカス・選択を消す
- **測定**（release、GPU あり）: パラメータ操作の frame_time は p99 1.15 ms（予算 16 ms）。目盛りの描画は選択要素のキー数に比例する軽い処理
- **未確認**: 実機の GUI 操作（バインド、キーの追加・削除、目盛りと吸着、名前変更、削除、範囲の編集）。基準モデルでの実機の動作。目盛りの位置の細かい合い具合
