# ファイルダイアログと新規プロジェクト（`tsukumoe-app`）

- REQ: なし（M5 の完了条件「新しいモデルを Tsukumoe だけで作れる」に必要な導線）
- 単位: M5-02b
- 状態: 計画中
- 依存: M5-02, M5-03
- クレート: `tsukumoe-app`

## 目的

- エディタから新規プロジェクトを作れるようにする。いまはメニューに導線がなく、CLI（`tsukumoe psd import <新しいディレクトリ> <PSD> --apply`）でしか作れない
- 開く・名前を付けて保存・PSD を取り込むで、パスの文字入力ではなく OS のファイルダイアログを使う

## 範囲

- **依存の追加**: `rfd` 0.17.2（MIT）。`default-features = false`、`tsukumoe-app` の `cfg(any(target_os = "macos", target_os = "windows"))` の依存に限る。利用者が追加と範囲（macOS・Windows のみ）を了承した（2026-11-01）。Linux には入れない（`xdg-portal` 経由の非同期系の依存が重く、検証もできないため。ADR-0027 の方針）。`deny.toml`（ライセンス・重複）を通す
- **ファイルピッカーの層**: 「ファイルを選ぶ」操作を小さなトレイト（例: `FilePicker`）に切り出す。実装は 2 つ。
  - `rfd` を使うもの（macOS・Windows）
  - 従来のパス入力ダイアログを開くもの（Linux、およびテスト用の偽物）
  選ばれたパスは、既存の処理（`open`・`save_as`・PSD の取り込み）に渡す。ダイアログの状態と取り込みの処理は変えない
- **メニュー**（メニュー定義 `menu.rs` に足す。macOS のネイティブメニューも自動で追従する）:
  - 新規プロジェクト…（常に有効）: 保存先のフォルダを選ぶ（新しいフォルダ、または空のフォルダ）。空のプロジェクト（`manifest.json`・空の `model.json`）を作って開く。空でないフォルダは拒否する
  - PSD から新規プロジェクト…（常に有効）: PSD を選ぶ → 保存先のフォルダを選ぶ → 作成して、既存の取り込みダイアログ（差分の一覧）へ進む。確定すると 1 コマンドとして適用する
  - 開く…: `.tsukumoe` のファイルを選ぶ。フォルダ形式は「フォルダを開く…」（macOS では 1 つのダイアログでファイルとフォルダを同時に選べないため分ける）
  - 名前を付けて保存…: `.tsukumoe` の保存ダイアログ。「フォルダとして保存…」を別に置く
  - PSD を取り込む…: `.psd` に絞った開くダイアログ
- **ダイアログの扱い**: 同期（ブロッキング）で呼び、メインスレッドで開く（macOS の `NSOpenPanel` の要件）。開いている間はエディタの描画が止まるが、OS のダイアログではふつうの挙動。親ウィンドウ（モーダルにするため）は eframe のウィンドウハンドルから渡す
- **直前に使ったフォルダ**: 次回のダイアログの初期位置にする（利用者設定に保存。既存の `settings.rs` を使う）
- 範囲外: Linux のネイティブダイアログ、ドラッグ＆ドロップでの読み込み、プロジェクトのテンプレート、アーカイブ形式の新規作成（作成はフォルダ形式。アーカイブは「名前を付けて保存」で作る）、最近使った項目の拡張

## 方針

- 新規プロジェクトの作成はモデル（`Command`）の外の操作。ただし作成後の最初の取り込みは、既存どおり 1 つの `Batch` コマンドとして適用する（ADR-0019）
- 書き込みは作成するプロジェクトだけ。選んだフォルダの外には書かず、既存のファイルを上書きしない
- 失敗（権限・空でない・書き込めない）は、ダイアログの後にエラーとして UI に出し、作りかけのファイルを残さない
- ピッカーを差し替えられる形にして、メニューの動作・新規作成・エラー処理を、実際の OS ダイアログなしでテストする

## 未決（レビューで決めたい）

- 新しいプロジェクトの初期内容（完全に空か、取り込み用のルート `Part` などの最小の骨組みを置くか）。まず完全に空とし、PSD から作るときは取り込みが `PSD` のルート `Part` を作る
- 新規プロジェクトの名前: フォルダ名をそのまま使うか、マニフェストに名前を持たせるか（持たせるならフォーマットの規則を確認する）
- Windows での確認（利用者が実機で行う）。Linux はパス入力のまま

## 検査

- ピッカー（偽物）で、新規プロジェクト・PSD から新規・開く・フォルダを開く・名前を付けて保存・PSD を取り込むが、選ばれたパスで期待どおりに動く。キャンセルでは何も起きない
- 新規作成: 空のフォルダと新しいフォルダでプロジェクトができ、`tsukumoe validate` が通り、開ける。空でないフォルダ・書き込めない場所は拒否され、何も作られない。選んだフォルダの外に書かない
- PSD から新規: 作成 → 取り込みの差分 → 確定が 1 回の undo で戻る。途中でキャンセルしたとき、作ったフォルダを残さない（または残る旨を明示する）
- メニュー: 「新規プロジェクト…」「PSD から新規プロジェクト…」はプロジェクトがなくても有効。ほかは従来どおり。翻訳キーが日英で揃っている。macOS のネイティブメニューの項目も増える
- 依存: `rfd` が macOS・Windows 以外のビルドに入らない（`cargo tree --target` で確認）。`cargo deny check` が通る
- 実機（macOS）: 各ダイアログが OS のものとして開き、選んだパスで動く。キャンセルできる

## 受入条件

- [ ] メニューから新規プロジェクトを作れる（空から、および PSD から）
- [ ] 開く・保存・PSD の取り込みで、macOS と Windows では OS のファイルダイアログが開く
- [ ] Linux ではこれまでどおりパス入力で操作できる
- [ ] `rfd` が macOS・Windows 以外のビルドに入らない

## 決めたこと

- `rfd` 0.17.2 を `default-features = false` で、macOS・Windows 限定の依存にする。Linux はパス入力のまま
- 新規プロジェクトはフォルダ形式で作る。アーカイブ形式は「名前を付けて保存」
- ピッカーはトレイトで差し替え可能にする
