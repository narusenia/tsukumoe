# MCP のセッション機能（差分つきの結果・dry run・退避点・prompts・resources）

- REQ: なし（要件の追加を提案中）
- 単位: M5-01h
- 状態: 計画中
- 依存: M5-01a
- クレート: `tsukumoe-cli`

## 目的

エージェントの試行錯誤の往復を減らす。適用のたびに何が変わったかを読み直す、失敗した batch のどこが悪いか探す、駄目だった試行を何度も undo する、といった無駄な呼び出しをなくす。

## 範囲

- 適用結果の差分: 編集系のツールの応答を `"applied"` から、追加・削除・名前変更された要素（種類と名前）、値が変わった要素の名前、適用後の `validate` の件数、にする
- `dry_run: true`: 編集系のツールすべてに付ける。適用して差分と検証結果を返し、すぐ戻す（履歴に残さない）
- `batch` の失敗位置: 失敗したとき、何番目のコマンドが何で失敗したかを返す
- `checkpoint { name }` / `restore { name }` / `list_checkpoints`: 名前付きの退避点。`restore` はそこまで戻す（その後の編集は redo で取り戻せる）
- `history { limit? }`: 適用したコマンドの一覧（新しい順）
- MCP の `prompts`: 作業の手順の雛形（「まばたきを作る」「口の開閉を作る」「髪の揺れを付ける」「PSD を差し替える」）。どのツールをどの順で使うかを書いたもの
- MCP の `resources`: コマンドのリファレンス（`docs/reference/commands.md` と同じもの）、モデルの概要、lint の結果。読み取り専用
- 範囲外: 複数エージェントの同時接続、セッションをまたぐ退避点の保存

## 方針

- 差分はコマンドごとの個別実装にしない。適用前後で要素の名前の集合と、要素ごとの内容のハッシュを比べて出す（コマンドが増えても手を入れなくて済む）
- `dry_run` は `apply` → 差分を取る → `undo` で作る。undo 後のモデルが適用前と一致することをテストで保証する
- 退避点は undo の段数で記録する。`restore` は記録した段数まで undo する。履歴の上限で古い段が消え、戻れなくなったときはエラーにして理由を返す（モデルの丸ごとの複製は持たない）
- `prompts` の本文は `tsukumoe-cli` に Markdown で置き、ツール名の変更をテストで検出する（本文中のツール名が `tools/list` にあること）
- `initialize` の capabilities に `prompts` と `resources` を足す

## 検査

- 代表的なコマンドで、差分に期待の要素名が出る
- `dry_run` の前後でモデルと履歴が変わらない
- `batch` の 3 番目が失敗すると、番号 3 と理由が返り、モデルが変わらない
- `checkpoint` → 編集 → `restore` で元のモデルと一致する。上限で戻れないときはエラー
- `prompts/list`・`prompts/get`・`resources/list`・`resources/read` の往復。`prompts` 内のツール名がすべて実在する
