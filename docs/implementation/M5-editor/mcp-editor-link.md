# MCP と起動中のエディタの接続

- REQ: REQ-AI-001
- 単位: M5-01i
- 状態: 計画中
- 依存: M5-01a, M5-01h, M5-02
- クレート: `tsukumoe-cli`（MCP 側）、`tsukumoe-app`（エディタ側の受け口）、`tsukumoe-edit`（両者で共有するメッセージの型）

## 目的

エディタで開いているプロジェクトに、MCP からコマンドを送れるようにする。人とエージェントが同じ画面・同じ undo 履歴で作業でき、「今選んでいるこれを直して」が通じるようにする（REQ-AI-001 の「エディタ起動中は、開いているプロジェクトにも同じコマンドを送れる」）。

## 範囲

- エディタが、開いているプロジェクトごとにローカルの受け口を開く（macOS / Linux は Unix ドメインソケット、Windows は名前付きパイプ）
- `tsukumoe mcp <project>` は、そのプロジェクトを開いているエディタがあればそこへ中継し、なければ今までどおりファイルを開く。`--offline` で中継しない
- 中継中は、編集・読み取り・描画のツールがエディタのモデルに対して動く。`save` はエディタの保存と同じ
- `get_editor_state`: エディタの選択（要素名と頂点番号）、今の姿勢（パラメータ値）、今のツール、表示中の範囲
- `set_editor_state { select?, params?, view? }`: エディタの選択・姿勢・表示範囲を変える（エージェントが「ここを見て」と示す）
- `screenshot`: エディタのビューポートを画像で返す（オーバーレイ込み）
- エディタ側の表示: 接続中であることをタイトルバーに出す。エージェントの編集は履歴パネルで区別できる（由来の印）
- 範囲外: ネットワーク越しの接続、複数のエディタへの同時接続、認証付きの遠隔操作

## 方針

- エディタ側の入口は `dispatcher` だけにする（ADR-0019）。受け口のスレッドがチャネルでコマンドを渡し、UI スレッドが次のフレームで `submit` して再描画を要求する。モデルを UI スレッド以外から触らない
- 受け口は本人だけが開ける場所と権限に置く（ソケットのファイルは 0600、ディレクトリは利用者ごと）。プロジェクトのパスから受け口の場所を決め、ロックファイルで生存を確かめる
- メッセージは MCP の `tools/call` の中身をそのまま運ぶ（ツールの実装をエディタ側と CLI 側で二重に持たない。ツールの本体は `tsukumoe-edit` 側に寄せ、両方が呼ぶ）
- 人の操作とエージェントの操作が同時に来たときは、届いた順に 1 つずつ適用する。ドラッグ中はエージェントの編集をドラッグ終了まで待たせる
- エディタが途中で終了したら、MCP 側はツールエラーを返し、`--offline` で開き直すよう案内する
- 受け口の方式と保護の判断は ADR に残す

## 検査

- エディタを起動した状態で `tsukumoe mcp` からコマンドを送ると、エディタのモデルと履歴に入り、エディタの undo で戻る
- エディタがないときは従来どおりファイルを編集する
- `get_editor_state` がエディタの選択と一致し、`set_editor_state` で選択が変わる
- ドラッグ中に届いた編集がドラッグ後に適用される
- 他の利用者の権限では受け口に接続できない
- エディタの終了で MCP 側が落ちずにエラーを返す

## 受入条件

- [ ] 起動中のエディタで開いているプロジェクトに、MCP からコマンドを送れる
- [ ] エディタの選択と姿勢を MCP から読める・変えられる
- [ ] エディタの画面を MCP から画像で受け取れる
