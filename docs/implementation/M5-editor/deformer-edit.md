# デフォーマの編集（`tsukumoe-core` / `tsukumoe-app`）

- REQ: REQ-EDIT-003（前半: ワープ・回転デフォーマの作成と階層編集。ボーンとウェイトのブラシは M5-05a）
- 単位: M5-05
- 状態: 実装済み（実機の GUI 操作は未確認）
- 依存: M5-02、M5-04
- クレート: `tsukumoe-core`（コマンドの追加と座標変換の純粋関数）、`tsukumoe-app`（デフォーマツール、ツリーとインスペクタの拡張、メッシュツールの座標系の修正）。`tsukumoe-core` は `wgpu` に依存せず `wasm32-unknown-unknown` で動く

## 目的

ワープデフォーマと回転デフォーマを、ビューポートとツリーから作り、階層を組み、基本形（`base_points` / `base`）を編集できるようにする。あわせて、M5-04 から持ち越した「デフォーマで変形して表示されるメッシュで、オーバーレイとヒット判定が画面の絵とずれる」問題を直す。

データモデルと評価（`WarpDeformer`・`RotationDeformer`・`DeformerRef`、`evaluation.md`）は実装済みで、編集コマンドだけが無い。

## 範囲

- **コマンド**（いまの `Command` にデフォーマの操作は無い。名前で指す既存の流儀に合わせる）
  - `AddWarpDeformer { name, part, parent, rows, columns, base_points }` / `AddRotationDeformer { name, part, parent, base }`
  - `RemoveDeformer { name }`: 子（デフォーマ・メッシュ）を持つ間は失敗する
  - `SetDeformerParent { name, parent }`: 循環を作る親付けは失敗する
  - `SetMeshParent { name, parent }`（親を外すときは `None`）
  - `SetWarpBasePoints { name, points }`（点数は `(rows+1)*(columns+1)` と一致。格子の分割数は変えない。変えたいときは作り直す）
  - `SetRotationBase { name, base }`
  - デフォーマと親の名前の引き方（ワープと回転を 1 つの名前空間にするか）は、既存の `Model` の名前の持ち方を確認して決める
  - コマンドは座標を変換しない。親付けでは子の局所座標が変わる（下記）ので、見た目を保つ変換は UI 側が計算し、`Batch` で 1 回に確定する
  - キーフォームを持つ要素の親を変える・基本形を動かすと局所座標がずれるため、キーフォームを持つ場合の扱いは未決（下記）。M5-05 では、キーフォームを持たない要素の編集を主とし、キーフォームを持つ要素は拒否する
- **局所座標と見た目を保つ変換**（`tsukumoe-core` の純粋関数）
  - ワープの子の点は、親の基本形の格子を `(u, v)`（0〜1）に正規化した空間の値。回転デフォーマの子の点は、原点からの局所座標。親を付けるときは、子の世界空間の見た目が変わらないように、点をこれらの空間へ変換する。親を外すときは逆に戻す
  - 世界空間 → ワープの `(u, v)` の逆変換は、格子のセルごとの双線形の逆写像（ニュートン法）で求める。格子の外側は端のセルの延長で外挿する（`evaluation.md` と同じ）
- **ワープの作成**: メッシュ（複数可）を選んで「ワープを作る」を実行する。外接矩形（少し余白を持たせる）を列数 × 行数（既定 4 × 4。ツールのオプション欄で変える）の格子にし、選んだメッシュを子にする（メッシュの点は `(u, v)` へ変換）。1 回の undo で、デフォーマの追加とメッシュの付け替えがまとめて戻る
- **回転デフォーマの作成**: メッシュまたはデフォーマを選んで実行する。原点は選択の外接矩形の中心（既定）。選択を子にする
- **デフォーマツール**（既存のキーマップのアクション `tool.deformer`、キー D の枠を使う。ビューポートの差し込み枠に載せる）
  - 選択: デフォーマの格子線・格子点・回転の原点とハンドルをクリックで選ぶ。矩形で格子点を複数選ぶ
  - ワープ: 格子点のドラッグで基本形を動かす。放した時に `SetWarpBasePoints` を 1 回送る。ドラッグ中は編集モデルを変えず、プレビューだけを動かす。子は評価の結果として一緒に動いて見える
  - 回転: 原点のドラッグ、角度ハンドルのドラッグ、拡大率ハンドルのドラッグ。放した時に `SetRotationBase` を 1 回送る
  - 描画: 選択中のデフォーマの格子と、その親・子を色分けして重ねる（M5-04 のオーバーレイの流儀）。16 ms の予算を守る（REQ-PERF-008）
- **ツリー**: デフォーマの行を足す。各 Part の下で、デフォーマは親デフォーマの下にネストして並べる（メッシュも、親デフォーマの下に出る）。ドラッグでの付け替えと、コンテキストメニュー「親を設定」「親を外す」「削除」を持つ。行の見た目は M5-02 の可視切替・薄表示の流儀に合わせる。表示・名前絞り込みはメッシュと同じ
- **インスペクタ**: 選択中のデフォーマの基本値を数値で編集できる。回転は原点・角度・拡大率・反転、ワープは行数・列数の表示（読み取り専用）と選択中の格子点の座標。数値欄は egui の `DragValue`
- **座標ずれの修正**（M5-04 の制約の解消）
  - メッシュツールのオーバーレイ・ヒット判定・メッシュ選択を、現在のパラメータ値で評価した後の位置（描画と同じ）で行う。基本位置（`ArtMesh.positions`）では行わない
  - 頂点のドラッグは、画面上の移動量を親の変換の逆変換で局所座標へ戻して、`SetMeshPositions`（形が変わるものは `SetMeshGeometry`）に確定する
  - 親を持たないメッシュは従来と同じ結果になる
- **複数選択**: ツリーの Ctrl / Cmd + クリック（トグル）と Shift + クリック（表示中の行の範囲）で複数のメッシュを選べる。ビューポートでは、選択ツールのとき Shift + クリックで追加・取り消し（メッシュツール中の Shift は矩形追加に使うので対象外）。選択状態は画面状態で、モデルには入れない。単一選択の挙動は変えない: メッシュツールの対象は最後に選んだ 1 つ、ワープ・回転の作成は全選択メッシュ（ワープは全体の外接矩形）を対象にする
- **ライブ反映**: 頂点・格子点・回転ハンドルのドラッグ中は、絵（メッシュの画像）も一時状態でリアルタイムに変形して見せる。編集モデル・undo 履歴・未保存フラグは放した時の 1 コマンドまで変えない（ADR-0019）。評価用に持っているコンパイル済みの写し（`Scene`）の基本形に、ドラッグ中の値を上書きし（`Scene::set_preview`）、取り消し（Esc）や確定で元に戻す。子のメッシュ・デフォーマ・マスクは評価の結果として追従する。確定系の操作（頂点追加・グリッド敷き・輪郭など）は即時確定なので対象外
- **選択の外接矩形**: メッシュツール以外のとき、選択中のもの（メッシュ・複数メッシュ・Part の配下・デフォーマ）の外接矩形を、評価後の描画位置で薄い線と四隅の点で重ねる（表示のみ）。非表示のメッシュは含めない
- **ツリーの自動スクロール**: 選択がツリー以外（ビューポートなど）で変わったとき、ツリーはその行へスクロールする（行が既に全部見えていれば動かさない。名前の絞り込みで行が隠れていれば何もしない。ツリー自身のクリックでは動かさない）。ツリーに折りたたみは無いので展開は要らない
- 範囲外: ボーンの作成・ウェイトペイント（M5-05a）、キーフォームの編集（M5-06）、ベジェ補間の評価（未実装のまま）、デフォーマの複製、格子の分割数の変更（作り直す）、フローティングパネル

## 方針

- 画面状態（選択された格子点・ハンドル、ドラッグ中のプレビュー、作成のオプション）は編集モデルに入れない。モデルは `Command` でしか変えない（ADR-0019）
- ドラッグは放した時に 1 コマンド。履歴パネルに操作名を出す（`Dispatcher::submit_labeled`）
- 見た目を保つ親付けは、デフォーマ・メッシュの追加と付け替えを `Batch` 1 回で確定する。途中の状態をモデルに残さない
- ツールの状態はツール側が持ち、egui 非依存の状態関数としてテストできる形にする（M5-04 と同じ）
- 文言は翻訳キーで引く（REQ-UI-005）
- 新しい依存クレートは足さない

## 未決（レビューで決めたい）

- キーフォームを持つ要素の親付け・基本形の編集の扱い。キーフォームは局所座標の絶対値のため、基本形を動かしたときの再計算を M5-06 で決める。M5-05 では拒否する前提
- デフォーマの名前空間（ワープと回転で名前を共有するか）、親のコマンド引数での指し方
- 逆変換の精度と上限。ニュートン法が収束しない形（セルが潰れた格子）での扱い（拒否してエラー表示、など）
- ツリーでのデフォーマの並べ方（Part の下にネスト、または専用のセクション）の細部
- デフォーマツールの選択操作（格子線のクリックでデフォーマを選ぶ判定、重なったときの優先順位）
- 回転ハンドルの見た目と、拡大率ハンドルの操作量
- 「ワープを作る」の起動方法（キー・メニュー・パイメニュー・右クリックメニューのどこに置くか）

## 検査

- コマンド: 各コマンドが検証で拒否する形（存在しない名前・循環・点数の不一致・キーフォーム付き）で、モデルが変わらずエラーを返す。成功後の undo / redo で元に戻る。JSON Schema の一覧に出る（バリアント追加で落ちるテストが通る）。`RemoveDeformer` が子を持つ間は失敗する
- 座標変換: ワープの子の点を `(u, v)` へ変換して評価し直すと、世界空間の位置が元と一致する（許容誤差内）。親を外して戻すと元の点に戻る。格子の外側の点（外挿）でも往復する。回転デフォーマの子でも同じ。潰れたセルは拒否する
- 作成: 4 頂点のメッシュに 4 × 4 のワープを作ると、メッシュが子になり、評価の結果が作成前と同じ。1 回の undo で元に戻る。複数メッシュの外接矩形を囲む
- ツール: 選択（クリック・矩形）、格子点・原点・角度・拡大率の移動の確定（放した時に 1 コマンド）、ドラッグ中はモデルが変わらないことが状態関数としてテストされる
- 座標ずれ: ワープの子のメッシュで、オーバーレイの頂点位置とヒット判定が評価後の位置と一致する。パラメータを動かしたあとでも一致する。頂点をドラッグして確定すると、評価後の位置が指で動かした位置になる（往復の誤差が許容内）。親を持たないメッシュは M5-04 のテストが変わらず通る
- ツリー: デフォーマの行が親子で並ぶ。付け替えが `SetDeformerParent` を 1 回送る。名前の絞り込みで祖先が残る。631 メッシュでも軽い（`show_rows`）
- 応答: 基準モデルで、格子点のドラッグ中のフレーム時間が 16 ms 以下（release）
- 描画: `egui_kittest` のスナップショットで、デフォーマの格子・ハンドルのオーバーレイと、ツリーのデフォーマ行を固定する（ライト・ダーク）
- 複数選択: 選択のトグル・範囲・単一への戻り、フィルタ中の範囲選択（隠れた行を含めない）、複数メッシュでのワープ作成（見た目が変わらず 1 回の undo で戻る）
- ライブ反映: プレビュー中にモデル・履歴・未保存フラグが変わらない。確定後の絵とプレビューの絵が一致する。プレビューを外す（Esc）と元の絵に戻る。子メッシュが追従する。基準モデルの最大メッシュ・最大ワープのドラッグ中のフレーム（描画リスト生成と、ハードウェア GPU があれば GPU 描画を含む）が p99 16 ms 以下
- 外接矩形: 単一・複数メッシュ・デフォーマ・Part の外接矩形が純粋関数で正しく出る。非表示を含めない。親付きは評価後の位置。メッシュツール中は出さない。スナップショット（ライト・ダーク）
- 自動スクロール: 選択行の位置の計算とスクロール要否の判定（見えている・見えていない・絞り込みで隠れている・ツリー自身のクリック）が状態関数でテストされ、631 メッシュのツリーで外部選択の後に行が見える位置にある
- 依存: `tsukumoe-core` が `wgpu` に依存せず、`wasm32-unknown-unknown` でビルドできる（CI）

## 決めたこと

- ワープの作り方は、選択したメッシュを囲む格子（利用者の回答）。空の格子を描いて後から子を付ける方式は作らない
- 格子点の編集は基本形まで。パラメータごとの形（キーフォーム）の編集は M5-06
- ボーンとウェイトのブラシは M5-05a として分ける。M5-05 はワープ・回転デフォーマの作成・階層編集・基本形の編集
- M5-04 の座標ずれは M5-05 で直す。評価後の位置で表示・ヒット判定し、確定時に逆変換で局所座標へ戻す
- コマンドは座標を変換しない。見た目を保つ変換は UI 側で計算し、`Batch` で 1 回に確定する
- 実装での決定（未決の暫定案）:
  - 名前空間: ワープと回転は 1 つの名前空間を共有する。`Add*Deformer` は、どちらの表にも同名があれば `AlreadyExists`。名前で引くときはワープ、回転の順に探す。親の指し方は名前（`parent: Option<String>`）。回転の基本形は `RotationBase { origin, angle_degrees, scale, reflect_x, reflect_y }`（不透明度を含まない）
  - キーフォームを持つ要素は `CommandError::HasKeyforms` で拒否する（`SetDeformerParent`・`SetMeshParent`・`SetWarpBasePoints`・`SetRotationBase`）。基準モデルのデフォーマは全部キーフォームを持つので、基準モデルでの格子点ドラッグは放した時に拒否される（テストで確認）。`RemoveDeformer` は、子が残れば既存の検証（ぶら下がり参照）で失敗する
  - 見た目を保つ変換は基本形（パラメータなし・キーフォームなし）の空間 `deformer_space::Space` で行う。親がキーフォームを持ち、パラメータが既定値でないときは、画面の絵と少しずれる（近似）。逆写像はセルごとのニュートン法で、潰れたセルは `Degenerate` で拒否する。回転デフォーマの付け替えは、原点・x 軸の角度・拡大率を保つ（せん断は表せないので失う）
  - ワープの作成対象: ツリーの選択が単一のため、メッシュ 1 つ、デフォーマ 1 つ、または Part（その下のすべてのメッシュ）。複数メッシュの個別選択は未実装
  - 起動口: アクション `deformer.create-warp`（W）・`deformer.create-rotation`（R）（ビューポート文脈）と、メッシュツール・デフォーマツールの右クリックメニュー。ワープの行数・列数は、デフォーマツール中のビューポート右上のオプション欄（状態はツール側、既定 4 × 4）。作成後は作ったデフォーマを選択し、ツールをデフォーマツールにする
  - デフォーマツール: 格子と回転のハンドルを基本形の位置で描く。回転のハンドルは、原点・x 軸上の角度ハンドル・y 軸上の拡大率ハンドル（拡大率が大きいほど遠い）。デフォーマの選択は、回転の原点が近ければそれ、なければ格子を覆う最小のワープ。親は橙、子は緑で重ねる。D はメッシュツール中は再分割なので、メッシュツールからデフォーマツールへはパイメニューか V → D で切り替える
  - ツリー: Part の下で、デフォーマは同じ Part の親デフォーマの下にネストし、メッシュも親デフォーマの下に出る。親が別の Part にあるときは、その Part の直下に置く。ドラッグはデフォーマ行へのドロップで親付け（Part 行・空き地へのドロップによる親外しは作らず、メニューの「親を外す」だけ）。メニューは「親を設定」（デフォーマ一覧）「親を外す」「デフォーマを削除」
  - インスペクタ: 回転は原点・角度・拡大率・反転、ワープは格子の大きさ（読み取り専用）と選択中の格子点（最大 8 点）の座標を、親の空間の値（保存されている基本値）で編集する
  - 座標ずれの修正: メッシュツールは `Scene::drawn_positions`（評価後の位置）で表示・ヒット判定・矩形選択・クリックでのメッシュ選択（`pick_drawn`）を行う。頂点の移動と追加は、基本形の空間で「描画位置 + 移動量」を局所座標へ戻して確定する（`release_in`・`add_at_in`）。親なしメッシュは従来と同じ計算で、M5-04 のテストは変更なし
  - 測定: 基準モデルで最大のワープ（9 点）の格子点ドラッグ中のフレームはオーバーレイの生成とテッセレーションで p99 0.01 ms。基準モデルのワープは小さいので、大きい格子での測定はしていない
  - `tsukumoe-cli` のコマンド別ツールのスキーマは、複数のバリアントが共有する型（`RotationBase`）の `$defs` を各ツールに持たせるよう直した
- 未確認: 実機の GUI 操作（ドラッグ・右クリックメニュー・ツリーのドラッグ・ビューポートの描画）。実画像・実モデルでの作成と編集の使い勝手
- 追加の決定（複数選択・ライブ反映・外接矩形・自動スクロール）:
  - 選択は `ViewState.selection`（最後に選んだもの）と、同じ選択に属するほかのメッシュ（`selected_meshes`）。ほかの場所が `selection` を直接書き換えれば、ほかのメッシュは無効になる（単一選択へ戻る）
  - ライブ反映は、モデルのクローンを作らず、コンパイル済みの写しの上書きと復元で行う（クローンは重く、`Model` は複製できない）。メッシュの頂点・ワープの基本点・回転の基本形に対応する。ドラッグの状態は 1 フレーム遅れで絵に反映される（入力の処理が描画の後のため）。メッシュツールのオーバーレイも絵の位置（ライブ反映後）で描く
  - 基準モデルのデフォーマはキーフォームを持つので、基本点を上書きしても絵は変わらない（確定も拒否される）。測定では、評価・描画の仕事量は同じ
  - 外接矩形のデフォーマは、ワープは基本形の格子と配下のメッシュ、回転は配下のメッシュ（評価後の格子は評価側が公開していないため、格子は基本形の位置）
  - ツリーの自動スクロールの行の高さは `show_rows` が数える高さ（行の高さ + 項目間隔）で計算する
- 追加の実装での決定（デフォーマのリセットと、回転の軸だけの移動）:
  - **リセット**: コマンドは新設せず、`SetWarpBasePoints` / `SetRotationBase` を `Batch` 1 回で送る（複数選択も 1 つの `Batch`、1 回の undo）。ワープは、現在の基本形の外接矩形に合わせた等間隔の格子（作成時の `regular_grid` を再利用。分割数は変えない）、回転は角度 0・拡大率 1・反転なし（原点は変えない）。すでに初期状態のものは外し、全部そうなら「すでに初期状態です」のトースト。キーフォームを持つデフォーマが 1 つでも入っていれば `Batch` ごと失敗して、モデルは変わらず、既存のエラー文（キーフォームを持つ旨）が出る。履歴ラベルは `deformer_reset: <名前>`（複数は `<N> items`、変えたものの数）
  - リセットの入口: アクション `deformer.reset`（既定のキー無し、キーマップ設定の一覧には出る）、デフォーマツールの右クリックメニュー、デフォーマパネル・パーツパネルの行のメニュー、インスペクタのデフォーマ欄の rotate-ccw アイコンボタン。対象は選択中のデフォーマ（複数選択は全部）。メニュー定義の「編集」などには足していない
  - **回転の原点は軸だけを動かす**: 原点ハンドルのドラッグと、インスペクタの原点の数値編集は、軸だけを動かし、直下の子（メッシュの頂点、子ワープの基本点、子回転の原点・角度・拡大率）の局所座標を、世界の見た目が変わらないように補正する（`deformer_ops::move_axis`。新旧の回転の空間 `Space::rotation` を使い、補正は旧空間から新空間への変換）。軸の移動と子の補正を 1 つの `Batch`、1 回の undo で確定し、履歴ラベルは `deformer_move_axis: <名前>`。孫は子の補正に追随する。回転またはその直下の子がキーフォームを持つと失敗する
  - 親がワープのとき、回転の軸は原点での近似なので、子の回転の角度・拡大率は 1 つの角度と拡大率で表せる最も近い値になり、描画位置は許容内（テストは 0.05）でずれる。子ワープの点・メッシュの頂点は、回転の空間の中では厳密に一致する
  - **修飾キー**: 計画では Alt としたが、Alt + ドラッグはパラメータ操作に使われ、Shift + ドラッグはパンに使われるため、Cmd / Ctrl を押しながら原点をドラッグしたときに、従来の「配下ごと動かす」になる（`DeformerTool::whole`）。ツールのヒント文に説明を出した。インスペクタには「全体を動かす」の手段は置いていない
  - **ライブ反映**: ドラッグ中は、軸の移動と子の補正を `previews_of` で `Scene::set_previews`（複数のプレビューを同時に上書きできるようにした）に渡す。放した時の `Batch` と同じコマンドから作るので、プレビューと確定した絵は一致し、Esc で元に戻る。キーフォーム付きで補正できないときはプレビューを出さず、放した時にエラーを出す
  - 未確認: 実機の GUI 操作（原点ハンドルのドラッグ、Cmd / Ctrl での切り替え、リセットの各入口）

- 追加の実装での決定（リセットで作成直後の形へ戻す、モデル形式の追加）:
  - **症状と原因**: ワープを作成し、プロポーショナル編集で格子を細くしてからリセットすると、縦横比が変わり縦に伸びた。リセットは「いまの格子点の外接矩形に等間隔格子」を敷くが、作成時の矩形（子の外接矩形 + 5%）はどこにも残っておらず、細くした矩形がそのまま採用された。子の座標は (u,v) で、矩形の大きさで正規化されているため、(u,v) からは縦横比を戻せない
  - **検討した案**: (a) 子メッシュの位置と UV からの再構成 — 子ごとの平行移動が未知で、メッシュ編集後は成り立たない。(c) (u,v) 範囲と余白からの復元 — 縦横比の情報が (u,v) にない。履歴から作成時のコマンドを探す案 — 保存して開き直す、または取り消しで巻き戻すと残らない。利用者の承認を得て (b) の最小版を採用した
  - **モデル**: `WarpDeformer.rest_points: Option<Vec<Point>>`（作成時の格子、`base_points` と同じ空間・同じ個数）。`AddWarpDeformer` が `base_points` の複製を入れる。`SetWarpBasePoints`（プロポーショナル編集を含む通常の編集）は触らない。取り消し・やり直しは既存の変更記録に乗る
  - **捨てる操作**: 基本形の座標系が変わる操作では `rest_points` を捨てる（従来の「いまの外接矩形に等間隔」に戻る。利用者の選択）。`SetDeformerParent`（ワープ自身の親の付け替え、作成時にワープを子に取る場合を含む）は自動で捨てる。回転の軸だけの移動（`move_axis`）が子ワープの点を変換するときは、新しいコマンド `ClearWarpRestPoints { name }` を同じ `Batch` に入れる。取り消しで `rest_points` も戻る。メッシュや回転の編集、複製（`AddWarpDeformer` なので複製時の形が記憶になる）は上記のとおり
  - **リセット**: `rest_points` があればそれへ、基本形が同じなら `NoChange`。なければ従来どおり。回転と、キーフォームつきの拒否は変更なし
  - **形式（model.json）**: `WarpDto.rest_points`（任意、`serde(default, skip_serializing_if)`）。ない古いファイルはそのまま読める（記憶なし）。ないものを書き戻してもキーは足さない。個数が `base_points` と合わなければ形のエラー（検証に `rest_points` を追加）。フォーマットのバージョンと `Feature` は、`pose` や `group` など既存の任意フィールドと同じく変えていない。`.tmod`（実行時の形式）には載せない。`schema/model.schema.json` と `docs/reference/commands.md`（LF）を再生成し、`docs/specifications/data-model.md` に 1 行足した
  - **既存テストの変更**: エディタのリセットのテストは、`AddWarpDeformer` に曲がった格子を直接渡していた（作成時の形がすでに曲がっていることになるため、リセット対象にならなくなった）。作成後に `SetWarpBasePoints` で曲げる形に直した。ほかに `deformer_ops` のリセットのテストを、記憶なし（`ClearWarpRestPoints` 後）の挙動を見る形に直した
  - **テスト**: 作成 → 格子を細くする（辺の点が追従）→ リセットで格子と子の描画位置が作成直後と一致、取り消しで細い格子と記憶が戻る / 付け替えと軸の移動で記憶が捨てられ、取り消しで戻る / コアでコマンドごとの取り消し・やり直し / 形式で、古いファイル、書き戻し、個数の不一致
  - 未確認: 実機で、プロポーショナル編集 → リセットの見た目（縦横比が作成直後に戻るか）。既存のプロジェクトで作成済みのワープには記憶がないので、従来どおりの挙動になる（作り直すと記憶される）
