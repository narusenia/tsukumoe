# ランタイム形式（`.tmod`）

- REQ: REQ-FMT-004, REQ-FMT-005, REQ-FMT-006
- 単位: M3-01
- 状態: 計画
- 依存: M1-03
- 場所: `tsukumoe-core`（`tmod` モジュール）。仕様の正本は `docs/specifications/file-formats.md` の §2

## 目的

配布・再生用の評価データを、読み込み時にコピーも変換もせず評価に使える形で持つ。評価は WASM・C ABI・Unity から同じバイト列を読む。

## 現状の問題

`CompiledModel`（`compiled.rs`）は `Vec` の入れ子で、そのままバイト列にしても、読み込みで `Vec` を作り直すことになる。ゼロコピーにするには、評価器が読む保存形式を平らな配列だけにし、借用したバッファの上で動かす必要がある。

- 入れ子の `Vec`: `BindingDef.axes` と `AxisDef.keys`、`MeshDef.blends`、`WarpDef.blends`、`BlendDef.keys` / `weights`、式の命令列（`Op`）
- ペイロードを持つ列挙型: `ParentRef`、`BlendTarget`、`PhysicsKind`、`Op`
- 文字列: パラメータ・メッシュ・ボーン・物理の名前

## 方針

- **`CompiledModel<'a>`**: 各配列を `Cow<'a, [T]>` にする。所有版（`'static`）はコンパイル結果、借用版は読み込んだバッファの上の視点。評価器の読み取りコード（`model.warps[i]`）は変えずに済む
- 要素型は `#[repr(C)]` の POD（`bytemuck`）にする。入れ子の `Vec` は「先頭位置 + 個数」の組で、別の配列を指す。列挙型は「種別 u32 + 固定幅の値」にする。`usize` は `u32` にし、上限を仕様に書く
- 名前は文字列表（UTF-8、オフセット + 長さ）に置く。名前は評価に使わないので、名前の引き当て用の索引は読み込み後に作ってよい（評価データのコピーではない）
- 全セクションをリトルエンディアン・16 バイト境界に置く。借用の入口（`&[u8]`）が 16 バイト境界でなければ、コピーせずエラーにする。ファイルを読む側には 16 バイト境界のバッファ（`AlignedBuf`）を用意する
- 検証は、読み込み時に 1 度だけ行う。オフセット・長さ・配列間の添字・列挙型の値・有限な数値を調べ、通った後の評価は境界検査に頼らない（ただし `Frame` のバッファ確保は従来どおり）
- 機能フラグ: ヘッダに「必須」と「無視可」の 2 つのビット列を持つ。セクション表の各項目にも「必須」の印を持たせ、未知の無視可セクションは読み飛ばす（REQ-FMT-005）。M3-02 のモーション・表情はこの無視可セクションとして足す

## レイアウト（概要。確定した値は仕様書へ）

1. ヘッダ: マジック `TMOD`、メジャー・マイナー、必須フラグ、無視可フラグ、セクション数、全体の長さ
2. セクション表: ID、必須の印、オフセット、長さ、要素数
3. セクション: `CompiledModel` の配列ごとに 1 つ（約 40）、文字列表、埋め込みテクスチャ（PNG のバイト列をそのまま。任意）

## 範囲

- `tsukumoe-core`: 要素型の POD 化、`CompiledModel<'a>` への変更、`tmod` の書き出し・検証つき読み込み、`AlignedBuf`
- `tsukumoe-format` / `tsukumoe-cli`: プロジェクトからの書き出し（`tsukumoe-cli export` に `.tmod` を足す）、`inspect` で `.tmod` の要約を出す
- 仕様書 §2 の完成（ヘッダ・セクション ID・各要素のバイトレイアウト・上限）
- 範囲外: モーション・表情・自動動作（M3-02）、C ABI（M3-03）、WASM（M3-04）、圧縮、署名

## 検査

- 往復: モデル → `.tmod` → 借用版で評価した結果が、所有版の評価結果とビット単位で一致する（基準モデルと既存のテスト用モデル）
- 決定性: 同じモデルから同じバイト列が出る
- 不正入力: 切り詰め、先頭・中間・末尾の 1 バイト改変、オフセットや長さの境界値、未知のメジャー、未知の必須 / 無視可フラグで、パニックせずエラーを返す。ファズ相当の変異テストを CI に入れる
- 仕様との一致: 仕様書に載せるサンプル `.tmod`（小さなモデル）を `docs/` 配下に置き、別実装が読めたか確かめる基準にする（REQ-FMT-006）
- 評価時にコピーしないこと: 借用版の配列がバッファ内を指す（ポインタの範囲）ことをテストで確かめる

## 受入条件

- [ ] 読み込みで評価用データを複製・変換せず、バッファ上で評価できる
- [ ] 往復の評価結果がビット単位で一致する
- [ ] 不正入力の変異テストがパニックせず、CI で回る
- [ ] 新しいメジャー・未知の必須フラグを拒否し、未知の無視可フラグ・セクションを読める
- [ ] 仕様書だけで別言語のローダが書ける記述量があり、サンプルファイルがある
- [ ] `tsukumoe-core` が `wasm32-unknown-unknown` でビルドできる（依存は `bytemuck` のみ追加）

## 決めること（着手時）

- 変異テストを `cargo-fuzz`（新しいツール）で行うか、通常のテストとして書くか。後者なら新しいツールは要らない
- 配列の数と並びは、実装しながら確定する。そのとき仕様書を同時に更新する
