# ブレンドモードの拡張（`tsukumoe-core` / `tsukumoe-gpu` / `tsukumoe-wasm`）

- REQ: REQ-RT-005, REQ-RT-007（REQ-CORE-004 の「ブレンドモード」を広げる）
- 単位: M3-08
- 状態: 草案（起票。レビュー待ち）
- 依存: M3-06
- クレート: `tsukumoe-core`（`BlendMode`・描画リストの値）、`tsukumoe-gpu`（参照レンダラ）、`tsukumoe-wasm` / npm（WebGPU・WebGL2）、`tsukumoe-ffi`（`TsukumoeBlendMode`）、`tsukumoe-format`（`.tsukumoe` / `.tmod` の値）

## 目的

いまのブレンドは通常・加算・乗算の 3 種。PSD の取り込み（M5-03）で、`over`（オーバーレイ）と `sLit`（ソフトライト）のように、3 種に収まらないモードが実際のモデルに使われているのが分かった。これらを正しく描けるようにする。

## 範囲（案）

- 追加するモード: スクリーン、オーバーレイ、ソフトライト、ハードライト、暗く（Darken）、明るく（Lighten）、覆い焼き（カラー）、焼き込み（カラー）。どれも色のチャンネルごとに独立して決まる「分離可能」なモードで、W3C の合成仕様（Compositing and Blending）の式に従う。色相・彩度・カラー・輝度の非分離モードは範囲外
- 式: プリマルチプライドアルファの `s`（ソース）と `d`（描画先）に対し、`rgb = (1 − d_a) · s_rgb + (1 − s_a) · d_rgb + s_a · d_a · B(d_rgb / d_a, s_rgb / s_a)`、`a = s_a + d_a · (1 − s_a)`（`B` はモードごとの関数）。`d_a = 0` や `s_a = 0` での 0 除算を避ける。既存の 3 種の式は変えない。式と境界の扱いを `rendering.md` の 4 節に足す
- 描画の方式（参照レンダラ）: 描画先の色を読む必要があるため、固定機能のブレンドでは書けない。拡張モードのドローアブルの直前に、そのドローアブルの外接矩形だけ描画先を別のテクスチャにコピーし、シェーダがそのコピーを読んで描く。拡張モードを使わないモデルは、追加のコピーも負荷もない
- 値の拡張: `BlendMode` に新しい値を足す（既存の 0〜2 は変えない）。描画リスト・C ABI（`TsukumoeBlendMode`）・プロジェクト形式・ランタイム形式（`.tmod`）の表現を揃える。古いリーダは、知らない値を通常として描画する（任意の機能として扱い、形式の MINOR を上げる。規則は `file-formats.md` に従う）
- 一致検査: 各モードの固定の入力（小さなテクスチャ）をネイティブ・WASM（WebGPU・WebGL2）で描き、許容差 2/255 で一致させる。CPU の参照関数（式の純粋な実装）を作り、GPU の出力と比べる
- M5-03 の取り込み側の対応づけ（`over` → オーバーレイなど）は、本単位の完了後に M5-03 の計画へ足す
- 範囲外: 非分離モード、アルファのブレンド（Cubism 5 のアルファブレンド相当があるかは未確認）、エディタでのモード選択 UI（M5 のインスペクタで扱う）

## 方針

- 式は 1 か所（`rendering.md`）に定め、CPU の参照関数・WGSL・GLSL（WebGL2）のどれもそこから写す
- 参照レンダラが正。他の環境は参照との差が許容内であること（REQ-RT-007）
- 拡張モードを使わない描画の速度・出力は変えない（PERF の回帰検知で確認）
- Cubism 側の挙動との一致は、メンテナーが Cubism Editor で書き出した自作モデルでのみ確認する（ADR-0016。SDK・他人のモデル・非公開の資料は読まない）

## 未決（レビューで決めたい）

- 追加するモードの範囲。上の 8 種で足りるか、まずスクリーン・オーバーレイ・ソフトライトだけにするか。実モデルでの使用頻度で決める
- Unity（別 repo）の実装を本単位に含めるか。Unity は描画先を読む仕組み（GrabPass など）がレンダーパイプラインごとに違う。本単位は仕様と一致検査のデータまでとし、Unity 側は別単位にする案
- ランタイム形式の互換: 古いリーダが知らない値を通常として描くのは許容か、読み込みを拒否するか
- Cubism の拡張ブレンドとの対応（互換）は、メンテナーが自作モデルで確認できる範囲だけにする

## 検査（案）

- 式: 各モードで、純粋な参照関数が定義どおりの値を返す（`s_a = 0` で `d` のまま、`d_a = 0` で `s` のまま、通常との整合など）
- 描画: 参照レンダラの出力が CPU の参照関数と許容内で一致する
- 一致: ネイティブ・WASM（WebGPU・WebGL2）の画像が許容内で一致する
- 互換: 新しい値を含む描画リスト・プロジェクト・ランタイム形式が、JSON の往復とファズテストを通る。古いリーダ相当のテストで、知らない値が通常として描かれる
- 速度: 拡張モードを使わない基準モデルの描画が、変更前と同等（CI のベンチ）

## 受入条件

- [ ] 追加したモードを参照レンダラで描ける
- [ ] 各モードの式が `rendering.md` に書かれ、CPU の参照関数と GPU の出力が一致する
- [ ] ネイティブと WASM（WebGPU・WebGL2）で出力が一致する
- [ ] 拡張モードを使わないモデルの描画の出力と速度が変わらない

## 決めたこと

- 起票の経緯: M5-03 の検証で、実際の PSD に `over` と `sLit` が使われていた。3 種のブレンドでは描けないため、別単位として切り出した
- 方式は描画先のコピー + シェーダ（外接矩形のみ）。拡張モードを使うドローアブルだけ追加コストを払う
