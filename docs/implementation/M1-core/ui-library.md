# UI ライブラリの作り込み（tsukumoe-ui）

- REQ: REQ-UI-004
- 単位: M1-14
- 状態: 未着手
- 依存: M1-11（ADR-0027）
- クレート: `tsukumoe-ui`

## 目的

エディタ（M5）と配信ホスト（M4）が使う UI 部品を、見た目と操作感まで作り込んだライブラリとして整える。M1 では 5 部品と最小のテーマだけを作った。ここでは、エディタが要る部品・テーマ・キー操作を揃え、全部品を gallery で確認できる状態にする。

## 方針

- シンプルで、プロ向けで、情報密度が高い見た目（文字 12pt・コントロール高 24pt が基準）。装飾は少なくし、境界線と面の明度差で階層を出す
- 見た目はすべてトークンから決める。部品がトークン以外の値を持たない
- 部品は egui の標準部品を土台にし、足りない部品だけ自作する。egui の更新で壊れにくくする
- 部品を作るときは、同じ単位で gallery の項目とテストを足す

## 範囲

### 基盤

- トークンの拡張: 色の段階（背景・面・境界・文字・強調・状態色。警告・エラー・成功）、文字サイズの段階、サイズ違い（compact / regular）、角丸、動きの長さ
- テーマ: ライト / ダーク / システム、JSON（スキーマを公開し、検査する）、保存と復元。高コントラストテーマの要否を決める
- アイコン: 方式を決める（SVG を埋め込むか、アイコンフォントか）。ライセンスと依存を確認する
- 状態の表現: hover・押下・フォーカス（キーボードの輪郭）・無効・選択・エラーを全部品で揃える
- フォント: 同梱に決定（下の「決めたこと」）
- キー操作: アクション名・キーの組・文脈（パネルやツール）を持つ小さなキーマップ層。利用者が割り当てを変えられ、保存できる
- アクセシビリティ: AccessKit の対応範囲を確認し、既定の部品との差を記録する

### 部品

作成済み（2026-10-30 時点）: Button（Primary / Secondary / Ghost / Danger、アイコン付き）、アイコンボタン、Switch、Checkbox、Radio、Slider、数値欄、テキスト入力（日本語 IME は egui 標準で動作）、Select、色選択、Panel、タブ、選択行、仮想化した一覧、Tooltip、メニュー項目、ダイアログ、Toast、Badge、進捗表示。アイコン 39 個（Lucide）。

M1-14 は上記の範囲で完了とし、次は M1-15 以降へ持ち越す（2026-10-30）: 下の「未作成のもの」、規則の文書（`docs/specifications/ui-library.md`）、`schema/theme.schema.json` と `schema/keymap.schema.json` の生成と比較、ホストへのキーマップ適用、CI での画像比較の OS 差の確認。

エディタに要るのに未作成のもの（優先順）:

- 操作系: トグルボタン（押下状態を持つツールバー用）、セグメント選択（ツール切り替え）、検索欄（アイコンと消去つき）、複数行テキスト、ショートカット入力欄（キー割り当ての変更 UI）
- 構造: ツリー（アイコン・ガイド線つき）、折りたたみセクション（インスペクタ）、表（見出し・並べ替え・幅変更。`egui_extras::TableBuilder` を包む）、ツールバーとステータスバー、Splitter（`Panel` の見た目の確認）
- 補助: コンテキストメニューとメニューバー、ポップオーバー、スピナー、バナー（情報・警告・エラーの行内通知）、空の状態の表示
- 数値: ラベルのドラッグで値を変える欄、2 値（X・Y）の欄。エディタ（M5）で要るので、先に部品として用意する
- 後回し（M5）: ドック（`egui_dock` を M5-02 で評価）、カーブ・タイムライン・メッシュ編集の描画

### 確認

- gallery: 全部品を、通常・hover・押下・フォーカス・無効・エラー、ライト・ダーク、compact・regular で並べる
- 描画テスト: 画面の画像比較の方式（`egui_kittest` など）を評価し、採用するなら CI に入れる
- 規則の文書: トークンの使い方、部品を足す手順、キーマップの書き方（`docs/` に置く）

## 範囲外

- エディタ固有のパネル（パラメータ・タイムライン・メッシュ編集など。M5）
- 配信ホストの画面（M4）

## 受入条件

- [ ] 上の部品（M5 へ回すものを除く）が揃い、gallery に全状態が並ぶ。ライトとダークの両方で目視確認した
- [ ] 全部品がアクセシブルな名前を持つ（`egui_kittest` の検査が通る）
- [ ] 部品がトークン以外の色・寸法を持たない（コードで検査できる範囲で検査する）
- [ ] テーマを JSON で読み込め、スキーマがある。保存した選択を復元できる
- [ ] キーマップ層があり、割り当てを変更して保存できる
- [ ] 日本語の入力・表示が部品ごとに動く（macOS で確認し、他 OS は未確認の範囲を記録する）
- [ ] 画像比較の方式を決め、採用した場合は CI で回る
- [ ] `mise run check` が通り、`tsukumoe-ui` を使わないクレートが egui 系に依存しない

## 決めたこと

- アイコン: SVG 埋め込み（Lucide、必要なものだけをファイルとして取り込む。`egui_extras` の `svg`）
- ドック: M5-02 で評価する。この単位では Splitter とタブまで
- 画像比較: `egui_kittest`（dev 依存）を採用して評価。ダーク・ライト・Regular を保存し、アクセシビリティ検査も同じテストで回る
- 高コントラストテーマ: 今回は作らない（ニーズが出たとき）
- フォント: Inter（欧文）と Noto Sans CJK JP（日本語、部分集合）を同梱する。OS のフォントを fallback にすると基準線がずれるため。ライセンス（OFL）は `assets/fonts/` に置く（ADR-0027）
- テーマ: 名前付きテーマ（`NamedTheme`）を持つ。組み込みは Figma Dark / Figma Light。ホストは `<設定>/themes/*.json` を読み、テーマと密度を `preferences.json` に保存する
- 見た目: Linear 系。枠線を減らして面の明度差で区切り、強調色は控えめにする。コントロール高は Compact 22 / Regular 26
