# 編集コマンドと undo / redo

- REQ: REQ-CORE-007
- 単位: M1-02
- 状態: 着手中
- 依存: M1-01
- 設計判断: [ADR-0018](../../adr/0018-edit-model-design.md), [ADR-0019](../../adr/0019-command-application.md)

`Model::apply(command)` を唯一の書き込み経路にし、undo / redo と、JSON でのコマンドの保存・再生を作る。

## 範囲

| 含める | 含めない |
|---|---|
| `apply` / `undo` / `redo`・履歴・取引（検証と巻き戻し） | 他の要素のコマンド（デフォーマ・グルー・ボーン・ブレンドシェイプ・物理・モーションなど）。必要になるマイルストーンで足す |
| 初期のコマンド: パラメータ・パーツ・メッシュの追加 / 削除 / 値の変更、`Batch` | JSON のファイル入出力（M1-08）。この単位では serde の型として出せるところまで |
| 名前で要素を指すコマンド型と、`serde` による直列化 | 履歴の永続化 |
| アリーナへの ID 指定の復元 | |

## 依存の追加

`serde`（derive）を本番依存に追加する（相談済み）。テストの JSON 入出力用に `serde_json` を dev-dependency に足す。

## 実装ステップ

1. アリーナ・テーブルに ID 指定の復元と、生きている要素どうしの等価比較を足す
2. `Edit` / `Change` / `History` と `Editable`
3. `Command` と `CommandError`、`apply` / `undo` / `redo`
4. テスト

## 受入条件

- [ ] 初期セットのすべてのコマンドが JSON で直列化・復元できる
- [ ] すべてのコマンドが undo / redo できる。undo 後のモデルが適用前と等しい
- [ ] コマンド列を JSON 経由で空のモデルに再生すると、同じモデルになる
- [ ] 削除を undo すると、元の ID で復元され、他の要素の参照が生きている
- [ ] 使用中の要素の削除は、エラーでモデルが変わらない
- [ ] `Batch` の途中で失敗するとモデルが変わらない
- [ ] 新しい `apply` で redo の履歴が消える
- [ ] `mise run check` が通る
