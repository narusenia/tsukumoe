# 編集用データモデル

- REQ: REQ-CORE-002, REQ-CORE-007（土台のみ）
- 単位: M1-01
- 状態: 完了
- 依存: M0-02
- 設計判断: [ADR-0018](../../adr/0018-edit-model-design.md)

`tsukumoe-core` に、Cubism の機能をすべて表現できる編集用モデルを作る。コマンドと undo（M1-02）、評価用モデルへのコンパイル（M1-03）、JSON 入出力（M1-08）はこの単位に含めない。

## 範囲

| 含める | 含めない |
|---|---|
| 要素の型（`docs/specifications/data-model.md` の表） | コマンドと undo（M1-02） |
| ID（世代付きインデックス + 永続 ID） | 評価・コンパイル（M1-03） |
| キーフォームのバインディングと格子 | シリアライズ（M1-08。ただし serde で出せる形にしておく） |
| 整合性の検証（参照切れ・永続 ID の重複・格子の大きさ） | ボーン・パラメータ式・物理の評価（M1-04〜06）。型だけ持つ |

## 構成

- `id`: 種類ごとの ID 型（`MeshId` `DeformerId` `ParameterId` など）と、世代付きインデックスのアリーナ。永続 ID の索引（種類ごとの `名前 → ID`）
- `model`: `Model` 本体。要素ごとのテーブルと、バインディングのアリーナを持つ。フィールドは crate 内限定で、公開 API は読み取りのみ（書き込みは M1-02 の `apply`）
- `keyform`: `Binding`（パラメータ ID の並びと、パラメータごとのキー位置）、`KeyformGrid<T>`（バインディングへの参照 + 行優先の密な配列）。`T` は対象の種類ごと（メッシュ頂点・デフォーマ・ボーン・描画順・不透明度・色）
- `validate`: `Model::validate() -> Vec<ModelError>`

## 決めたこと（この単位の中）

- アリーナは自前の小さな実装にする（`Vec` + 世代番号 + 空きスロットの再利用）。外部クレートを足さない
- 永続 ID は文字列で、種類ごとに一意。空文字と重複は検証でエラーにする
- 範囲外のキー位置・昇順でないキー位置・格子の大きさとキー数の不一致は、検証でエラーにする

## 実装ステップ

1. アリーナと ID 型、永続 ID の索引（挿入・削除・世代の無効化）
2. 要素の型を 1 種類ずつ追加（Parameter → Part → ArtMesh → デフォーマ → Glue → Bone → BlendShape）
3. バインディングと `KeyformGrid`（キー位置と配列の大きさの対応、共有）
4. `validate`
5. 単体テスト

## 受入条件

- [x] Cubism の機能と要素の対応表（data-model.md）の全行を、型で表現できる
- [x] 削除した ID を使うと検出される（世代の不一致）
- [x] 同じバインディングを複数の要素が共有できる
- [x] 検証が、参照切れ・永続 ID の重複・格子の大きさの不一致を検出する
- [x] `mise run check` が通る。`tsukumoe-core` が wgpu・gpui に依存しない

## 残した制約

- ブレンドシェイプの対象はメッシュとワープデフォーマだけ。Cubism の他の対象（回転デフォーマ・パーツ不透明度など）に広げるかは、moc3 読み込み（M2）で確認する
- パーツの不透明度は固定値で、キーフォームを持たない。同上
- 物理・ドライバ・モーション・表情・ポーズは型だけ。評価・再生は M1-04〜06 と M3-02
- 検証は構造の整合だけを見る。意味的な検査（未使用パラメータなど）は M1-10 の CLI で扱う
