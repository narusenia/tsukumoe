# ボーンとスキニング

- REQ: REQ-CORE-003
- 単位: M1-05
- 状態: 完了
- 依存: M1-03
- 設計判断: [ADR-0021](../../adr/0021-skinning-order.md)
- 仕様: [evaluation.md](../../specifications/evaluation.md)「ボーンとスキニング」

## 範囲

| 含める | 含めない |
|---|---|
| ボーン階層・キーフォーム（平行移動・角度・拡大率）の評価 | ボーン木が複数の親デフォーマにまたがる構成（別 ADR） |
| 1 頂点 4 ボーンまでのウェイトによるスキニング | ウェイトの値の検証（負・非有限。JSON 読み込みの M1-08 で入力境界として検査する） |
| ADR-0021 の適用順、コンパイル時の検査（退化ボーン・空間の不一致） | ボーンの編集コマンド |
| `affine.rs`（合成・逆行列）への切り出し | |

## 実装ステップ

1. ADR-0021、仕様の更新
2. `Affine` の切り出しと拡張
3. `CompiledModel` にボーン・頂点の影響を追加、コンパイル時の検査
4. `Frame::evaluate` にボーンの姿勢とスキニング
5. テスト

## 受入条件

- [x] 1 頂点あたり最大 4 ボーンのウェイトを扱える
- [x] ボーン変換をパラメータのキーフォームで駆動できる
- [x] デフォーマ階層と併用したときの適用順が仕様に定義され、テストで確認している
- [x] 基本形で恒等、親ボーンに子が追従、ウェイト合計が 1 を超えるときの正規化がテストで確認できる
- [x] 定常状態のフレーム評価でヒープ確保が 0 回である
- [x] `mise run check` が通る

## 残した制約

- ボーン木を使うメッシュは同じ親デフォーマを持つ必要がある（ADR-0021）
- スキニングの結果が Cubism の用語にない Tsukumoe 独自の機能のため、M2 の画像差分の対象外
