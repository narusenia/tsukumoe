# 描画リスト

- REQ: REQ-CORE-006
- 単位: M1-07
- 状態: 完了
- 依存: M1-03
- 仕様: [draw-list.md](../../specifications/draw-list.md)

## 範囲

| 含める | 含めない |
|---|---|
| `CompiledModel` に UV・インデックス・テクスチャ・ブレンドモード・マスク・両面を追加 | C ABI / WASM の関数の公開（M3）。メモリレイアウトの規定までを含める |
| 描画順（`draw_order` 昇順、同値はメッシュ番号順）を `Frame::evaluate` で求める | マスクバッファの生成・ブレンド式（M1-09 の描画規則） |
| 前フレームとの変化フラグ（形状・見た目・順序） | 可視判定（不透明度 0 の除外） |
| `Frame::draw_list` → `DrawList` / `Drawable`（コピーなしのビュー） | |

## 実装ステップ

1. `CompiledModel` に静的な描画データを追加
2. `Frame` に前フレームの保持・変化フラグ・描画順を追加
3. `draw.rs`: `DrawList` と `Drawable`
4. テスト

## 受入条件

- [x] 頂点位置・UV・インデックス・不透明度・描画順・マスク関係・乗算色・スクリーン色・ブレンドモードを取れる
- [x] 前フレームから変化した要素を判定できる
- [x] 連続バッファのスライスで参照でき、追加コピーがない
- [x] 描画順が決定的である（同値はメッシュ番号順）
- [x] フレーム評価が無アロケーションのまま（既存テストが通る）
- [x] `mise run check` が通る

## 残した制約

- 変化検出は前フレームのバッファを持つため、`Frame` のメモリは頂点バッファ分だけ増える
- ボーン（M1-05）・物理（M1-06）は、頂点を書き換える手順を変化検出の前に置くこと
