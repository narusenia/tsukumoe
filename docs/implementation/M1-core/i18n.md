# 多言語対応の基盤（i18n）

- REQ: REQ-UI-005
- 単位: M1-15
- 状態: 完了（未達は「受入条件」に記載）
- 依存: M1-11（UI ライブラリの M1-14 と並行してよい）
- クレート: `tsukumoe-i18n`（新設。UI を知らない）。`tsukumoe-ui` が使う

## 目的

UI の文言を最初から翻訳可能にする。後から文字列を拾い集めるのは高くつくので、エディタの部品が増える前に土台を置く。最初の対応言語は日本語と英語。

## 方針

- 文言はコードに直書きせず、キーで引く。キーは Fluent の識別子で、`area-component-purpose` の形（例: `dialog-close`、`host-reset`。ドットは使えない）
- 形式は Fluent（`.ftl`）に決定（`fluent-bundle` + `unic-langid`）。複数形・性・引数つきの文を表せる。言語の検出は `sys-locale`
- 翻訳ファイルは `crates/tsukumoe-i18n/locales/{ja,en}/*.ftl` に置き、バイナリに埋め込む（実行時にファイルを探さない）
- 言語は設定として保存し（`Preferences` に `language` を足す）、既定は OS の言語。取れなければ英語
- 引けなかったキーは、選択言語 → 英語 → キー名の順で代える。画面にはキー名が出るので、抜けに気づける
- 言語に合う CJK フォントを同梱して選ぶ（日本語・中国語・韓国語は字形が違う）。現在は Noto Sans CJK JP のみ。`install_cjk_font` を言語を受け取る形にする
- 日付・数値・単位の表示は、言語の規則に従う（小数点・桁区切り）

## 範囲

- `tsukumoe-i18n`: メッセージの読み込みと検索、引数の埋め込み、複数形、フォールバック、言語の検出
- `tsukumoe-ui`: ライブラリ自身の文言（閉じる、キャンセル、リセットなど）を翻訳キーにする。部品は文字列を呼び出し側から受け取るので、アプリ側は `tr` で引いて渡す
- ホスト・エディタの文言: 新しく書くものは最初からキー経由にする。M1-11 のホストの文言も移す
- 言語の切り替え UI（gallery と、ホストの設定行）
- 範囲外: ドキュメントの翻訳（要件・仕様は日本語、README は英語のままで、README_ja を別に持つ方針は維持）、右から左に書く言語の対応

## 検査

- 英語のキーが日本語に全部あり、日本語にしかないキーがない（テストで検査）
- 同じキーで、両言語の引数名が一致する
- 部品のソースに、翻訳キーを通さない英語の文言が残っていない（未実装。検査の方法は未定）
- gallery に言語切り替えを置き、日本語と英語でレイアウトが崩れないことを画像比較に加える

## 受入条件

- [x] 日本語と英語を切り替えられ、選択が保存される（ホストの設定行。保存先は `preferences.json`）
- [x] ライブラリとホストの文言が、すべてキー経由になっている（gallery のデモ文字列は対象外）
- [x] キーの過不足と引数の不一致を CI が検出する（`tsukumoe-i18n` のテスト）
- [ ] 言語に合う CJK フォントが選ばれる（未達: 同梱は Noto Sans CJK JP のみ。中国語・韓国語を足す時に選択を入れる）
- [x] 画像比較に、英語と日本語の両方が入っている（`theme_en` / `theme_ja`）
- [ ] 新しい文言の足し方が文書にある（未達: `ui-library.md` が未作成。M1-14 の持ち越しと同時に書く）
