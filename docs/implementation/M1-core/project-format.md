# JSON プロジェクト形式

- REQ: REQ-FMT-001, REQ-FMT-002, REQ-FMT-003, REQ-FMT-005
- 単位: M1-08
- 状態: 着手中
- 依存: M1-01
- 仕様: [file-formats.md](../../specifications/file-formats.md)
- クレート: `tsukumoe-format`（`tsukumoe-core` に依存を足さない）

## 方針

- 要素どうしの参照は内部の `Id` なので、JSON は名前で参照する専用の型を `tsukumoe-format` に持ち、`Model` と相互に変換する。型から JSON Schema を生成する（`schemars`）
- zip の読み書きは `zip` クレート。どちらも依存の追加を利用者が承認済み

## 段階

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | コンテナ（zip / 展開ディレクトリ）、マニフェスト、バージョンと機能フラグ、入力の防御 | 完了 |
| 2 | `model.json` ほか: `Model` ↔ JSON の変換とラウンドトリップ | 完了 |
| 3 | JSON Schema の生成、`schema/` への書き出し、CI の差分検査 | 未着手 |

## 段階 1 の受入条件

- [x] 読み込み → 書き出しで内容が変わらない（zip・ディレクトリ）。出力は決定的
- [x] JSON のキー順が安定し、差分が読める形（2 スペース・末尾改行）
- [x] 破損した zip・不正な JSON・危険なパス・サイズ超過でパニックせずエラーを返す（全長の切り詰めと全バイトの反転で確認）
- [x] 新しいメジャーバージョンを拒否し、未知の「無視可」機能を読み、未知の「必須」機能をエラーにする
- [x] 展開ディレクトリを読み書きでき、リンクは辿らない

## 段階 2 の受入条件

- [x] 全種類の要素（パラメータ・パーツ・バインディング・ボーン・ワープ・回転・メッシュ・グルー・ブレンドシェイプ・ドライバ・ポーズ・物理・モーション・表情）が、書き出し → 読み込みで等しい `Model` に戻る。2 回目の書き出しはバイト単位で同じ
- [x] zip・展開ディレクトリのどちらでも同じ `Model` になる
- [x] 定義のない名前・名前の重複・存在しないバインディング・形状の不整合は、要素を名指しするエラーになる
- [x] 手書き JSON で既定値のある項目を省略できる
- [x] 壊れた JSON（全ファイルの切り詰めとバイト反転）でパニックしない
- [x] 要素の読み込みは検証付きの `Model::from_parts`（`tsukumoe-core` に追加）を通る。履歴は空で始まる

## 残した制約

- 読み込み時の `Id` は、ファイル内の並び順で振り直される。名前（永続 ID）は保たれるが、内部 `Id` は保存前と同じとは限らない
- 重み・範囲などの数値の妥当性（負・順序）は `Model::validate` が見る範囲まで。追加の検査は段階 3 以降で必要になれば足す
- `tsukumoe-core` の `Model::from_parts` は、コマンド（`Model::apply`）以外で `Model` を組み立てる唯一の経路
