# 推論プロバイダ抽象（`tsukumoe-ai`）

- REQ: REQ-AI-003
- 単位: M4-04
- 状態: 未着手
- 依存: なし
- クレート: `tsukumoe-ai`（新設。`tsukumoe-core` / `tsukumoe-runtime` / UI / GPU / HTTP クライアント / 推論ランタイムに依存しない）

## 目的

AI 機能の推論先を差し替えられる土台。プロバイダ trait、モデル（重み）の記述と取得・検証・保管、クラウド送信の事前明示の仕組みを作る。実際の推論バックエンド（ONNX）は含めない。リップシンク（M4-05）が最初の利用者。

## 範囲

- `Provider` trait: 入力テンソル（名前つき、`f32` の形状つき平らな配列）→ 出力テンソル。同期呼び出しのみ。提供元の種別 `Locality`（`Local` / `Cloud`）を返す
- モデル記述 `ModelSpec`: ID、バージョン、ファイル名、サイズ、SHA-256、ライセンス（SPDX 識別子 + 表示名 + 全文または URL）、取得 URL。マニフェストは JSON（`serde`）で読み込む
- 重み管理 `ModelStore`: 保管先ディレクトリ（呼び出し側が渡す）、`status`（未取得 / 取得済み / 壊れている）、`ensure(spec, fetcher)`。取得は一時ファイルに書き、サイズと SHA-256 を検証してから確定する（検証に失敗したら捨てる）。壊れた取得済みファイルは再取得
- 取得の抽象 `Fetcher` trait: URL からバイト列を順に読む（`Read` を返す）。実 HTTP 実装は本単位に含めない（host 側で依存追加を確認して実装する）。テストでは差し替え用の実装を使う
- ライセンス表示: `ModelSpec` から表示用の構造（`LicenseNotice`）を返す。取得（`ensure`）の前に呼び出し側が表示できるよう、取得の確認コールバックを `ensure` に渡す（確認が `false` なら取得しない）
- クラウド明示: `Locality::Cloud` のプロバイダは `Disclosure`（送信先の名前、送るデータの種類）を持ち、`ProviderRegistry::acquire` が確認コールバックを通さない限り使えない。既定は `Local` のみ登録され、`Cloud` は利用者が設定で明示的に登録したときだけ
- `ProviderRegistry`: 機能名（例: `lipsync`）ごとに使うプロバイダを選ぶ。登録がなければエラー
- SHA-256: `sha2`（RustCrypto、`default-features = false`）を `[workspace.dependencies]` に足して使う。ハッシュ以外の暗号機能は持たない
- 範囲外: ONNX バックエンド（M4-05 で必要になった時点で依存追加を確認）、実 HTTP の `Fetcher`、クラウドプロバイダの実装、リップシンク本体、設定ファイルの読み書き（保管先・クラウド登録の永続化は host）

## 方針

- `tsukumoe-ai` は I/O を `Fetcher` とファイルシステム（`ModelStore` の保管先）に限る。ネットワークは触らない
- 外部由来の入力（マニフェスト JSON、取得したバイト列）は信頼境界。サイズ・ID（パス区切りや `..` を含まない）・URL スキーム（`https` のみ）を検証し、不正なものは取得前に拒否する。取得中のバイト数が `ModelSpec` のサイズを超えたら中断する
- 重みは同梱しない（受入条件）。テストの重みはテスト内で生成した小さなバイト列
- 確認コールバックは同期の `FnOnce(&Notice) -> bool`。UI はこの上に載せる（トーストやダイアログは host / ui の責務）

## 検査

- SHA-256: 配線の確認として既知のベクタ（空・`abc`）が一致する。分割入力と一括入力が一致する（ハッシュ自体の正しさは `sha2` に任せる）
- マニフェスト: 正常、必須項目の欠落、不正な ID（`..`・区切り・空）、`https` 以外の URL、サイズ 0、SHA-256 の桁違い。不正でパニックしない
- `ModelStore`: 取得 → 検証 → 確定、サイズ超過で中断し一時ファイルが残らない、ハッシュ不一致で捨てる、壊れた取得済みファイルを再取得する、取得済みならフェッチャを呼ばない、確認が `false` ならフェッチャを呼ばない、途中で失敗しても取得済みの正しいファイルを壊さない
- クラウド: 確認なしでは `acquire` が拒否する、確認 `false` で拒否、`true` で通る、`Local` は確認なし
- レジストリ: 未登録の機能はエラー、登録の置き換え
- ダミープロバイダ（入力を決まった規則で変換する）で、trait 越しの呼び出しと形状の不一致のエラーを検査する
- 依存: `tsukumoe-core` / `tsukumoe-runtime` / `egui*` / `wgpu` / HTTP・推論クレートに依存しない（`sha2` 以外の外部依存を持たない）ことをクレート依存のテストで検査

## 受入条件

- [ ] 推論先を `Provider` trait で差し替えられ、機能ごとに選べる
- [ ] 重みは同梱せず、`ModelStore` が初回利用時に `Fetcher` 経由で取得し、サイズと SHA-256 を検証して保管する
- [ ] 重みごとのライセンス表示用の情報を取得前に返し、利用者の確認なしでは取得しない
- [ ] クラウドのプロバイダは送信先とデータの種類を明示し、確認なしでは使えない
- [ ] 追加する依存は `sha2` のみ（HTTP・推論ランタイムを含まない）

## 決めたこと

- 初回は抽象 + 重み管理のみ。ONNX バックエンドは M4-05
- 取得は `Fetcher` trait 越しで、`tsukumoe-ai` は HTTP に依存しない
- SHA-256 は `sha2` を使う（検証の信頼境界なので、自前実装より監査済みの実装を選ぶ。依存はこれのみ）
