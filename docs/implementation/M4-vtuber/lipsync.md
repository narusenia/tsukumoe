# リップシンク（`tsukumoe-ai` / `tsukumoe-cli`）

- REQ: REQ-AI-008
- 単位: M4-05
- 状態: 完了
- 依存: M4-02, M4-04
- クレート: `tsukumoe-ai`（音声処理の本体。PCM → 口形。`tsukumoe-core` / `tsukumoe-runtime` に依存しない）、`tsukumoe-cli`（音声ファイル → モーション書き出し。`tsukumoe-core` と `tsukumoe-ai` に依存する側で組み立てる）

## 目的

音声から口のパラメータ（開閉・母音形）を作る。リアルタイム（PCM を流し込む）と、音声ファイルからのモーション書き出しの両方を、同じ解析器で扱う。

## 範囲

- 解析器 `Lipsync`: モノラル PCM（`f32`、サンプルレートは呼び出し側が指定）を `push` し、ホップごとに `MouthFrame`（開き `open` 0..1、母音の重み あ・い・う・え・お、有声か）を返す。窓 32 ms・ホップ 10 ms を既定とし、設定できる
- 手法（推論モデルを使わない信号処理）:
  - 音量: RMS を対数にして、無音のしきい値と飽和の範囲で `open` の下地にする（ノイズ床は自動で追従）
  - 母音: 有声区間で LPC によりスペクトル包絡を求め、フォルマント F1・F2 を推定する。日本語 5 母音の代表値（あ 800/1200、い 300/2300、う 350/1300、え 500/1900、お 500/900 Hz 付近）への距離から重みを出す（話者差は設定の補正係数で寄せる）
  - 時間方向: 開閉は立ち上がりを速く・立ち下がりを遅くしたスムージング、母音の重みは短い移動平均で、口の跳ねを抑える
- 口形からパラメータへ: `MouthFrame` → `(ParamMouthOpenY, ParamMouthForm)` の値への変換関数（あ: 開 1・形 0、い: 開 0.3・形 +1、う: 開 0.3・形 −1、え: 開 0.6・形 +0.5、お: 開 0.7・形 −0.6 を母音の重みで混ぜ、`open` を掛ける）。出力は名前つきの値の列で、M4-02 の `Mapper` と同じく添字は呼び出し側（host）が解決する
- 音声ファイル: 自前の最小 WAV 読み込み（RIFF/WAVE、PCM 8/16/24/32 ビット整数と 32 ビット浮動小数、モノラル・ステレオ（平均してモノラル化）、`fmt ` と `data` 以外のチャンクは読み飛ばす）。サイズの上限と不正な見出しは拒否する
- モーション書き出し: `tsukumoe lipsync <wav> -o <motion>`。一定のフレームレート（既定 30 fps）で `ParamMouthOpenY` と `ParamMouthForm` の曲線を作る。冗長な点は間引く（許容誤差の範囲で線形に近い点を落とす）。出力形式は既存のモーション書き出しの経路（`tsukumoe-core` の `Motion` / `.tmod` のモーション）に合わせる
- 遅延: 解析器の遅延（窓の中心までの待ち + 出力の平滑の遅れ）を `latency()` で返し、既定設定で 50 ms 以下にする（受入条件は音声入力から口パラメータまで 100 ms 以下。残りは入出力側の予算）
- 範囲外: 実マイクのキャプチャ（M4-03 の host。`cpal` 等の依存追加はそこで確認）、ONNX による推論（精度不足が出た時点で M4-04 の `Provider` の上に足す。本単位は M4-04 の `ModelStore` を使わない）、母音以外の音素（子音）の口形、実時間のホスト配線

## 方針

- 音声は信頼境界ではないが外部由来。非有限サンプル・長さ 0・極端なサンプルレート（8 kHz 未満・192 kHz 超は拒否）を検証し、パニックしない
- 毎ホップの処理は割り当てをしない（作業用バッファは `Lipsync` が持つ）
- `push` はサンプルを任意の長さで受ける（呼び出し側のバッファ境界に依らず、同じ入力で同じ出力になる）。決定的（乱数なし）
- 母音の判定は「当てる」ことより「口が不自然に動かない」ことを優先する。不確かなとき（フォルマントが取れない・無声）は `open` を下げ、母音の重みは直前を保つ
- F1・F2 の代表値は設定として持ち、話者や声質に合わせて JSON で変えられるようにする（既定は日本語成人の平均的な値）

## 検査

- 合成母音: ソース・フィルタ（基本周波数 120 / 220 Hz の声帯パルス列 + 5 母音のフォルマント）で作った音から、各母音が最大の重みになる（男声・女声の両方）。無音で `open` が 0 に落ち、母音の重みは変動しない
- 開閉: 振幅を変えた同一母音で `open` が単調に増える。ノイズ（白色）で母音が暴れない
- 時間: 遅延の報告値が既定で 50 ms 以下。立ち上がり・立ち下がりの時定数が設定どおり
- 分割入力: 同じ音を 1 サンプルずつ・不揃いな長さで `push` しても、一括と同じ `MouthFrame` 列になる
- WAV: 各ビット深度・モノラル/ステレオ・余計なチャンク・`data` が見出しより短い・巨大なサイズ宣言・非 WAV。不正でパニックしない（変異テスト）
- モーション: 合成 WAV（「あ」→無音→「い」）から書き出し、曲線の値が区間ごとに期待どおり。間引きの誤差が許容内。ランタイムで読み込んで再生できる（`tsukumoe-cli` のテスト）
- 変換関数: 5 母音と `open = 0` の値
- 依存: `tsukumoe-ai` が `tsukumoe-core` / `tsukumoe-runtime` / `egui*` / `wgpu` に依存しない。追加の外部依存なし

## 受入条件

- [x] リアルタイム時の遅延が 100 ms 以下である（解析器の遅延 50 ms 以下を検査で確認。入出力側の遅延は host で測る）
- [x] 日本語の母音（あいうえお）に対応する口形パラメータを出せる
- [x] 音声ファイル（WAV）から motion を生成できる
- [x] 追加の外部依存を持たない

## 決めたこと

- 初回は信号処理（LPC によるフォルマント推定）。ONNX は使わない
- PCM を受ける API まで。実マイクは host（M4-03）
- WAV は自前の最小パーサ（依存なし）
- 母音の口形は Live2D 標準の `ParamMouthOpenY` / `ParamMouthForm` の 2 つに落とす
- モーション書き出しの出力形式: プロジェクトのモーションファイル（`tsukumoe-format` の `MotionFile`、`motions/<name>.json`）。曲線は名前でパラメータを指すためモデルなしで書け、`read_model` がそのまま読んで `Runtime` で再生できる。`.tmod` は書かない（`.tmod` はプロジェクト全体の変換 `tsukumoe convert` が作る）。区間は線形のみ、既定 30 fps・許容誤差 0.01（Douglas-Peucker）。`--fps` `--tolerance` `--config`（解析器設定の JSON）`--name` で変えられる
- 無声音・子音: `open` は音量に従わせ、母音の重みは直前の値を保つ。有声だがフォルマントが取れない区間は `open` を半分にする
- 解析は 16 kHz 付近に間引いて行う（32 kHz 以上は整数倍で平均）。F1・F2 は包絡のピークではなく LPC 多項式の根（極）から取る（あ・お のようにフォルマントが近い母音でもピークが 1 つに潰れないため）
- 遅延は 窓の半分 + 母音の移動平均の遅れ + `attack_ms` で、既定 41 ms
- 合成母音（男声 120 Hz・女声 220 Hz、16 / 22.05 / 44.1 / 48 kHz）で 5 母音とも全フレームが最大の重みになる。う は お との差が最も小さい（最大の重み 0.52〜0.65、お が 0.23〜0.30）
