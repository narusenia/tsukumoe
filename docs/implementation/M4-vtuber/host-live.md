# ホスト: トラッキング配線と透過ウィンドウ（`tsukumoe-host`）

- REQ: REQ-TRK-003（透過ウィンドウ・モデル/トラッキング/マッピングの選択）、REQ-TRK-004（機能追加が容易な構造）
- 単位: M4-03a（M4-03 を a / b / c に分割した最初の単位。b: Syphon 出力、c: 仮想カメラ・Spout2）
- 状態: 着手中（実装済み。設定パネルの操作確認が残る）
- 依存: M1-11, M4-01, M4-02
- クレート: `tsukumoe-host`（`tsukumoe-tracking` を path 依存に足す。外部依存は追加しない）

## 目的

`tsukumoe-host` を、VMC のトラッキング入力でモデルを動かし、透過ウィンドウに表示するアプリにする。配信ソフトへの映像出力（Syphon / Spout2 / 仮想カメラ）は含めない。OBS のウィンドウキャプチャ（アルファつき）で使える状態がこの単位のゴール。

## 範囲

- 配線の層 `live`（UI に依存しない。`viewer` と同じ疎結合）: `TrackingAdapter`（M4-01）→ `Postprocess`（スムージング・感度・途切れ復帰）→ `Mapper`（M4-02）→ `Scene::set_parameter`。毎フレーム 1 回 `step(now)`。トラッキングが有効なとき、マッピングされたパラメータはトラッキングの値が優先する（スライダは読み取り専用の表示になる）。無効なときは従来どおりスライダで動かす
- 起動オプション: `tsukumoe-host <project> [--vmc-port <n>] [--mapping <json>] [--transparent]`。`--vmc-port` を指定するとトラッキングを有効にして起動する。`--mapping` は M4-02 の JSON 上書き。不正なオプション・JSON はエラーで終了する（黙って既定に落とさない）
- 設定パネル（`tsukumoe-ui` の部品を使う。文字列は `tsukumoe-i18n` の日本語・英語）: トラッキングの on/off と受信ポート、受信状態（受信中 / 途切れ / 待機中）、スムージング・感度の調整、マッピングで束縛できたパラメータ数・読み飛ばした数、透過の on/off
- 透過ウィンドウ: ウィンドウを透過にし、背景を完全な透明（アルファ 0）で描く。モデルの半透明はアルファつきで合成する（premultiplied か straight かはレンダラの出力に合わせ、OBS 側のキャプチャで縁が汚れないことを確かめる）。透過時は枠なし・最前面を選べる
- 範囲外: Syphon / Spout2 / 仮想カメラ（M4-03b・c）、実マイクのキャプチャとリップシンクの配線（音声キャプチャの依存追加を確認してから別単位）、iFacialMocap / MediaPipe、モーション・表情の再生（M3 のランタイム経由の配線は別単位）、ファイル選択ダイアログ

## 構成

| 層 | 内容 | UI への依存 |
|---|---|---|
| `viewer` | 既存（`Scene` / `Viewer`） | なし |
| `live` | トラッキング → 後処理 → マッピング → `Scene`。入力は `TrackingAdapter` trait なので、テストは偽のアダプタで動く | なし |
| `app` | ウィンドウ・設定パネル・透過。`live` を毎フレーム呼ぶだけ | `tsukumoe-ui` と `eframe` |

## 検査

- `live`（偽のアダプタ）: 入力が `Scene` のパラメータに反映される。標準 ID のモデルで `jawOpen = 1` → `ParamMouthOpenY` が上がる。入力が途切れると既定姿勢へ戻り、再開すると追従に戻る。トラッキング無効のときは `Scene` に触れない。スムージング・感度の変更が次のフレームから効く。束縛できなかったパラメータの数が報告される
- 起動オプション: 引数の解析（正常・未知のオプション・不正なポート・存在しないマッピング・不正な JSON はエラー）
- 往復（ローカル UDP）: 実際の VMC パケットを送り、`live` 経由で `Scene` の値が変わる
- 依存: `viewer` と `live` が `egui*` / `eframe` に依存しない。外部依存の追加がない
- 窓まわり: CI ではビルドのみ。手元の macOS で、VMC を送る小さなスクリプト（テスト用）で基準モデルを動かし、スクリーンショットで確認する。透過は、背景が透けることを確認する

## 受入条件

- [x] VMC の入力でモデルの頭・目・口が動く（標準 ID のモデル、設定なし）
- [x] 入力が途切れると既定姿勢へ戻り、再開すると追従に戻る
- [x] マッピングを JSON で上書きして起動できる
- [x] 透過ウィンドウで表示でき、背景が透ける
- [ ] 設定パネルでトラッキングの有効・無効、ポート、スムージング・感度を変えられる
- [x] `live` が UI クレートに依存しない。外部依存の追加がない

## 決めたこと

- M4-03 を a（本単位）/ b（Syphon）/ c（仮想カメラ・Spout2）に分割
- 本単位は依存追加なし。配信ソフトには、まずウィンドウキャプチャで渡す
- リップシンクの配線は音声キャプチャの依存を確認してから別単位
- 透過の方式: premultiplied のまま通す。レンダラの出力は premultiplied（`One, OneMinusSrcAlpha`、クリアは透明）で、egui のテクスチャ合成も premultiplied のため変換しない。透過時は eframe の `clear_color` を `[0; 4]`、中央パネルの塗りを透明にして背景をアルファ 0 で描く。ウィンドウは常に `with_transparent(true)` で作る（表面のアルファは作成時にしか決められず、設定パネルの切り替えを実行時に効かせるため）。枠なし・最前面は透過時のみ有効なチェックボックス。F1 で設定パネルを隠せる（配信ソフトで映す範囲を広げすぎないため）
- 設定の永続化: しない。`preferences.json`（テーマ・密度・言語）は `tsukumoe-ui` の `Preferences` で型が固定されており、ポート・マッピング・透過は起動オプションが正で、保存した値でソケットが勝手に開くのを避ける
- 確認の状況（手元の macOS）: 基準モデルのパラメータ名を標準 ID に付け替えて VMC を送り、受信中・途切れ・スライダーの読み取り専用化・透過（背後の画面が透ける）を目視。`--mapping` の上書きも目視。設定パネルのスイッチ・スライダーのクリック操作は未確認（自動操作の手段がない）。縁の汚れは半透明テクスチャで未確認
