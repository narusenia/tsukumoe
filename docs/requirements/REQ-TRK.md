# TRK 要件定義（トラッキング・配信ホスト）

対象クレート: `tsukumoe-tracking` / `tsukumoe-host`

## REQ-TRK-001: トラッキング入力アダプタ

| 項目 | 内容 |
|------|------|
| ID | REQ-TRK-001 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

外部のトラッキング手段から入力を受ける。顔追跡の推論そのものは外部・既存 SDK に任せ、自前で学習しない。

対象: VMC プロトコル（OSC）、iFacialMocap（iPhone ARKit）、MediaPipe Face Landmarker（Web 版はブラウザ内で完結）。

### 受入条件

- [ ] 各アダプタが共通の入力型（ARKit 52 blendshape + 頭部姿勢）に正規化して出力する
- [ ] 入力が途切れたとき、既定姿勢へ滑らかに戻る
- [ ] 入力のスムージングと感度を設定できる

### 依存要件

- なし

## REQ-TRK-002: 標準パラメータマッピング

| 項目 | 内容 |
|------|------|
| ID | REQ-TRK-002 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

トラッキング入力をモデルのパラメータへ対応付ける。Live2D の慣習 ID（`ParamAngleX` / `ParamEyeLOpen` 等）と ARKit blendshape 名の両方に既定マッピングを持ち、moc3 から読み込んだモデルも設定なしで追跡で動く。

### 受入条件

- [ ] Live2D 標準パラメータ ID を持つモデルが設定なしで頭・目・口を追跡する
- [ ] マッピングをモデルごとに JSON で上書きできる
- [ ] パラメータ式（REQ-CORE-004）と組み合わせられる

### 依存要件

- REQ-TRK-001
- REQ-RT-001

## REQ-TRK-003: 最小の配信ホスト

| 項目 | 内容 |
|------|------|
| ID | REQ-TRK-003 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

モデルを表示して配信ソフト（OBS 等）に流す最小のアプリ。M1 では動作確認用のビューアとして始める。

### 受入条件

- [x] 透過ウィンドウでモデルを表示できる
- [ ] Windows は Spout2、macOS は Syphon で映像を出力できる
- [ ] 仮想カメラとして出力できる
- [ ] モデル・トラッキング入力・マッピングを選べる

### 依存要件

- REQ-TRK-002
- REQ-RT-005

## REQ-TRK-004: 配信ホストを育てられる構造

| 項目 | 内容 |
|------|------|
| ID | REQ-TRK-004 |
| 優先度 | Should |
| ステータス | Draft |

### 説明

v2 で本格的な配信ホストアプリにする見込みのため、機能追加が容易な構造にしておく。開発中の動作確認に必要になれば v1 中でも機能を足す。

### 受入条件

- [ ] ホストの UI はエディタと同じ UI 基盤（egui + `tsukumoe-ui`）で作る
- [ ] ホストの機能はコマンドとして実装され、エディタと共有できる

### 依存要件

- REQ-TRK-003
- REQ-UI-001
