# FMT 要件定義（ファイル形式）

対象クレート: `seimei-format`

## REQ-FMT-001: JSON プロジェクト形式（zip コンテナ）

| 項目 | 内容 |
|------|------|
| ID | REQ-FMT-001 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

エディタが読み書きするプロジェクト形式。zip コンテナの中に JSON とテクスチャ（PNG）を入れる。元 PSD は参照として持つ。

### 受入条件

- [ ] 読み込み → 書き出しで内容が変わらない（ラウンドトリップテスト）
- [ ] JSON はキー順が安定し、git 差分が読める形で出力される
- [ ] 破損した zip・不正な JSON でパニックせずエラーを返す

### 依存要件

- REQ-CORE-002

## REQ-FMT-002: 展開ディレクトリ形式

| 項目 | 内容 |
|------|------|
| ID | REQ-FMT-002 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

zip と同じ中身をディレクトリとして読み書きできる。git 管理と、AI エージェントによる直接編集を想定する。

### 受入条件

- [ ] zip 形式と展開ディレクトリ形式を相互変換できる（`seimei-cli`）
- [ ] 展開ディレクトリを外部で編集したあと、スキーマ検証してから読み込む

### 依存要件

- REQ-FMT-001

## REQ-FMT-004: ゼロコピーのランタイムバイナリ形式

| 項目 | 内容 |
|------|------|
| ID | REQ-FMT-004 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

配布・再生用のバイナリ形式。mmap または読み込んだバッファをそのまま評価に使えるレイアウトにする。テクスチャを同梱できる。

### 受入条件

- [ ] 読み込み時に評価用データへの変換・コピーを行わない
- [ ] 信頼できない入力として扱い、境界・整合性を検証してから使う（ファズテストを持つ）
- [ ] リトルエンディアン固定・アライメント規約が仕様に定義されている

### 依存要件

## REQ-FMT-005: 形式のバージョニングと機能フラグ

| 項目 | 内容 |
|------|------|
| ID | REQ-FMT-005 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

プロジェクト形式とランタイム形式にメジャーバージョンと機能フラグを持たせる。未知の機能フラグは「無視してよい」と「必須（読めなければエラー）」を区別する。

### 受入条件

- [ ] 新しいメジャーバージョンのファイルは明示的なエラーで拒否する
- [ ] 未知の「無視可」フラグを含むファイルを読める
- [ ] 未知の「必須」フラグを含むファイルはエラーにする

### 依存要件

- REQ-FMT-001
- REQ-FMT-004
