# CORE 要件定義（リグ評価コア）

対象クレート: `seimei-core`

## REQ-CORE-001: GPU 非依存の固定段評価パイプライン

| 項目 | 内容 |
|------|------|
| ID | REQ-CORE-001 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

モデルの 1 フレーム評価を、GPU・ウィンドウ・GPUI に依存しない純 Rust で行う。
評価は次の固定段で進む:
パラメータ入力 → パラメータ式 → キーフォーム補間 → デフォーマ階層 → スキニング → 物理 → 描画リスト。

### 受入条件

- [ ] `seimei-core` が `wgpu` / `gpui` 系に依存しない（`cargo tree` で CI 検査）
- [ ] `wasm32-unknown-unknown` 向けにビルドできる
- [ ] 各段が独立にテストできる

### 依存要件

- なし

## REQ-CORE-002: Cubism の機能をすべて含むリグモデル

| 項目 | 内容 |
|------|------|
| ID | REQ-CORE-002 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

moc3 を損失なく読み込めるよう、Cubism モデルの機能をすべて表現できるデータモデルを持つ。
対象: ArtMesh、ワープデフォーマ、回転デフォーマ、パラメータ、キーフォームの多重線形補間、
ブレンドシェイプ、グルー、クリッピングマスク（反転含む）、乗算色・スクリーン色、描画順（キーフォーム付き）、
パーツと不透明度、ブレンドモード。

### 受入条件

- [ ] 上記の各機能をデータモデルで表現できる
- [ ] 各機能の評価結果が単体テストで検証されている
- [ ] Cubism 機能と Seimei データモデルの対応表が `docs/specifications/data-model.md` にある

### 依存要件

- REQ-CORE-001

## REQ-CORE-003: ボーンと頂点ウェイトによるスキニング

| 項目 | 内容 |
|------|------|
| ID | REQ-CORE-003 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

ボーン階層と頂点ウェイトで ArtMesh を変形する。ボーンの変換はパラメータのキーフォームで駆動できる。

### 受入条件

- [ ] 1 頂点あたり最大 4 ボーンのウェイトを扱える
- [ ] ボーン変換をパラメータのキーフォームで駆動できる
- [ ] デフォーマ階層と併用したときの適用順が仕様に定義されている

### 依存要件

- REQ-CORE-002

## REQ-CORE-004: パラメータ式（ドライバ）

| 項目 | 内容 |
|------|------|
| ID | REQ-CORE-004 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

あるパラメータの値を他のパラメータの式で決める。式言語は副作用のない安全な小言語とし、汎用スクリプト（Lua 等）は採用しない。

### 受入条件

- [ ] 四則演算・比較・clamp / lerp / smoothstep 等の組み込み関数を使える
- [ ] 循環参照をロード時に検出してエラーにする
- [ ] 式は評価前に事前コンパイルされ、フレーム評価中にパースしない

### 依存要件

- REQ-CORE-001

## REQ-CORE-005: 物理演算（振り子互換と物理チェーン）

| 項目 | 内容 |
|------|------|
| ID | REQ-CORE-005 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

Cubism の振り子物理（physics3）と同じ結果を出せる物理と、髪・アクセサリ向けの多関節物理チェーンを持つ。

### 受入条件

- [ ] physics3 を読み込んだモデルの物理出力が Cubism と許容誤差内で一致する
- [ ] 物理チェーンの関節数・剛性・減衰・重力・風を設定できる
- [ ] 固定タイムステップで、フレームレートに依存しない結果になる

### 依存要件

- REQ-CORE-001

## REQ-CORE-006: 描画リストの出力

| 項目 | 内容 |
|------|------|
| ID | REQ-CORE-006 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

評価の最終出力として、レンダラに依存しない描画リストを出す。各レンダラ（wgpu・Unity 等）はこれだけを入力に描画する。

### 受入条件

- [ ] 頂点位置・UV・インデックス・不透明度・描画順・マスク関係・乗算色・スクリーン色・ブレンドモードを含む
- [ ] 前フレームから変化した要素を判定できるフラグを持つ
- [ ] C ABI と WASM から追加コピーなしで参照できるメモリレイアウトである

### 依存要件

- REQ-CORE-001

## REQ-CORE-007: 編集コマンドと undo

| 項目 | 内容 |
|------|------|
| ID | REQ-CORE-007 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

モデルへの変更はすべて、シリアライズ可能な編集コマンドを通して行う。エディタ UI・CLI・MCP・AI 機能は同じコマンドを使う。

### 受入条件

- [ ] すべてのコマンドが JSON でシリアライズできる
- [ ] すべてのコマンドが undo / redo できる
- [ ] コマンド列を再生すると同じモデルになる（テストで検証）

### 依存要件

- REQ-CORE-002

## REQ-CORE-008: データ指向レイアウトとフレーム中の無アロケーション

| 項目 | 内容 |
|------|------|
| ID | REQ-CORE-008 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

評価用のデータを SoA で持ち、SIMD と並列化を使えるようにする。編集用のデータモデルと評価用のデータは分けてよい。

### 受入条件

- [ ] 定常状態のフレーム評価でヒープ確保が 0 回である（テストで検証）
- [ ] SIMD 経路とスカラ経路の結果が一致する
- [ ] 1 体の評価を複数スレッドに分けるか、複数体を並列評価できる

### 依存要件

- REQ-CORE-001

## REQ-CORE-009: Live2D 互換モード

| 項目 | 内容 |
|------|------|
| ID | REQ-CORE-009 |
| 優先度 | Should |
| ステータス | Draft |

### 説明

Live2D にない機能（ボーン・パラメータ式・物理チェーン）を無効にし、Cubism と同じ評価結果を出すモード。moc3 読み込み時の既定とする。

### 受入条件

- [ ] 互換モードで Seimei 独自機能を含むモデルを読むと警告を出す
- [ ] 互換モードの出力が REQ-COMPAT-005 の画像差分検証を通る

### 依存要件

- REQ-CORE-002
- REQ-COMPAT-005
