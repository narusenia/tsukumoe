# COMPAT 要件定義（互換性）

対象クレート: `seimei-compat`

## REQ-COMPAT-001: moc3 読み込みの法務ゲート

| 項目 | 内容 |
|------|------|
| ID | REQ-COMPAT-001 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

moc3 対応は法的に安全な側へ倒す。実装着手前と公開前にゲートを通し、結果を ADR に記録する。

### 受入条件

- [ ] 着手前: Cubism Core / SDK ライセンスと Cubism Editor 利用規約の該当条項（リバースエンジニアリング禁止の範囲）を確認し、ADR に記録している
- [ ] 公開前: 専門家（弁護士）の確認を受けている
- [ ] ゲートを通るまで moc3 関連コードを main に入れない、または公開しない

### 依存要件

- なし

## REQ-COMPAT-002: moc3 のクリーンルーム実装

| 項目 | 内容 |
|------|------|
| ID | REQ-COMPAT-002 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

moc3 の読み込みをクリーンルームで実装する。

### 受入条件

- [ ] 解析素材は自作モデル（自分で Cubism Editor から書き出した moc3）だけを使う
- [ ] 他者のモデル・Cubism SDK / Core のバイナリを解析しない（逆アセンブルを含む）
- [ ] 既存 OSS の moc3 パーサのコード・ドキュメントを参照しない。このルールを AGENTS.md に明記し、AI エージェントのコンテキストにも入れない
- [ ] 形式の知見は自作ドキュメントに記録し、その出所（どの自作モデルのどの差分から得たか）を残す

### 依存要件

- REQ-COMPAT-001

## REQ-COMPAT-003: moc3 機能の分離可能な構造

| 項目 | 内容 |
|------|------|
| ID | REQ-COMPAT-003 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

法務ゲートが NG になっても本体を出せるよう、moc3 対応を独立した Cargo feature に閉じ込め、別リポジトリ・別配布に移せる構造にする。

### 受入条件

- [ ] `moc3` feature を無効にしたビルドに moc3 関連コードが含まれない
- [ ] moc3 対応を外しても、他のクレートの公開 API が変わらない
- [ ] 既定の feature に moc3 を含めるかは法務ゲートの結果で決める

### 依存要件

- REQ-COMPAT-001

## REQ-COMPAT-004: Live2D JSON 群の読み込み

| 項目 | 内容 |
|------|------|
| ID | REQ-COMPAT-004 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

`model3.json` / `motion3.json` / `exp3.json` / `physics3.json` / `pose3.json` を読み込み、Seimei のモーション・表情・物理・ポーズに変換する。`cdi3.json`（表示名）・`userdata3.json` も読む。

### 受入条件

- [ ] 各 JSON の公開仕様の全項目を読み込める、または読めない項目を警告する
- [ ] motion3 のカーブ（線形・ベジェ・ステップ・逆ステップ）を再生結果で検証している

### 依存要件

- REQ-CORE-005

## REQ-COMPAT-005: 画像差分による同等表示の検証

| 項目 | 内容 |
|------|------|
| ID | REQ-COMPAT-005 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

Live2D モデルを Seimei で表示した結果が Cubism と同等であることを、画像差分テストで検証する。

### 受入条件

- [ ] 自作の検証モデル群について、複数のパラメータ姿勢で Cubism の出力と画素差分が閾値内である
- [ ] 期待画像は自作モデルから手元で生成したものだけを使う
- [ ] CI で回帰テストとして実行される

### 依存要件

- REQ-COMPAT-002
- REQ-COMPAT-004
- REQ-RT-005
