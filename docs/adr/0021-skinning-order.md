# ADR-0021: スキニングはデフォーマ階層の前に適用する

- 状態: 採用
- 日付: 2026-10-30

## 背景

REQ-CORE-003 は、ボーンによるスキニングとデフォーマ階層を併用したときの適用順を仕様に定めるよう求める。選択肢は 2 つある。

- A: キーフォーム補間・ブレンドシェイプの後、親デフォーマの変換の**前**にスキニングする。ボーンはメッシュの親デフォーマの局所空間（ADR-0020）にある
- B: 親デフォーマの変換の**後**、世界（描画）空間でスキニングする。ボーンは描画空間にある

`Bone` は所属するデフォーマを持たない。

## 決定

**A を採る。**

1. 頂点は、キーフォーム補間 → ブレンドシェイプ → スキニング → 親デフォーマの変換 → グルー、の順に処理する
2. ボーンの変換は、そのボーンで変形するメッシュの**親デフォーマの局所空間**の値で持つ。親のないメッシュなら描画空間
3. 1 本のボーン木（根が同じボーン）を使うメッシュは、すべて同じ親デフォーマを持たなければならない。違えばコンパイルエラー
4. スキニング行列は `K = W_pose · W_rest⁻¹`（`W` はボーンの階層を通した変換、rest は基本形 `Bone::base`）。基本形のとき `K` は恒等になる。基本形が可逆でない（拡大率に 0 がある）ボーンはコンパイルエラー
5. 頂点の位置は `Σ wᵢ·Kᵢ·v + max(0, 1 - Σ wᵢ)·v`。`Σ wᵢ > 1` のときは `wᵢ` を `Σ wᵢ` で割る

## 理由

- B だと、頭の回転デフォーマに付いた髪のボーンが、頭の回転についてこない。ボーンの支点が描画空間に残り、揺れの中心がずれる。A なら、ボーンはメッシュと同じ局所空間にあるので、デフォーマの動きに自然に従う
- A の制約（3）は、ボーンに所属デフォーマがないことの代償。局所空間が異なるメッシュ（ワープの 0〜1 正規化空間と描画空間など）で 1 つのボーン木を共有しても、変換の単位が合わない
- アーキテクチャ図の「デフォーマ → スキニング」の順は、この ADR に合わせて入れ替える

## 結果

- `docs/specifications/evaluation.md` の手順にスキニングを加え、`data-model.md` の TODO を解く
- 複数の親にまたがるボーン木が必要になったら、ボーンに所属デフォーマを持たせる（別 ADR）
