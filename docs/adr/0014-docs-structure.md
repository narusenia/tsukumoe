# ADR-0014: implementation をマイルストーン単位で整理し、ADR を新設する

- 状態: 採用
- 日付: 2026-10-30

## 背景

Ravel の `docs/implementation/` は 46 ファイルがフラットに並び、名前の付け方がそろっていない（`-plan` / `-design` / 日付付き）。`plan.md` / `roadmap.md` / `backlog.md`（1500 行）の役割が重なり、状態をファイル内の Status 行と `done/` `archive/` への移動の 2 か所で管理している。handoff がリポジトリ直下に散らばっている。

## 決定

- `roadmap.md`: マイルストーンと完了条件だけ（1 画面）
- `M{n}-{name}/`: マイルストーンごとのディレクトリ。計画 1 本 = 1 ファイル、冒頭に REQ-ID・状態・依存
- 状態は各マイルストーンの `README.md` の表だけで管理する。ファイル移動で状態を表さない
- `backlog.md`: 予定の決まっていない項目だけ。着手したらマイルストーンへ移す。200 行程度まで
- 終わった計画は残すが更新しない。残す価値のある設計判断は `specifications/` か ADR に移す
- `docs/adr/`: 設計判断の記録
- `docs/handoff/`: セッション引き継ぎ。古いものは削除する（git 履歴に残る）
- ファイル名は kebab-case。`-plan` 等の接尾辞・日付を付けない

## 結果

- 状態を知るには、該当マイルストーンの README を 1 つ見ればよい
