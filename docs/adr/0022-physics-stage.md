# ADR-0022: 物理はドライバの直後、固定刻みで評価する

- 状態: 採用
- 日付: 2026-10-30

## 背景

アーキテクチャ図は物理をデフォーマ階層のあとに置き、「物理が書いたパラメータに依存する段を再評価する」としていた。物理の入力と出力はどちらもパラメータで、頂点には触れない。

## 決定

1. **物理はドライバの直後、パラメータを範囲に収める前に評価する。** 出力パラメータは同じフレームのキーフォーム補間・デフォーマに届く。再評価の段は要らない
2. **時間は固定刻み（1/60 秒）で進める。** 呼び出し側の経過時間は蓄積し、刻みの整数倍だけ進めて、余りを次フレームに持ち越す。1 フレームの上限は 10 刻み。超えた時間は捨てる
3. **物理の入力は、ドライバの出力を含む、そのフレームのパラメータ値を読む。** 物理の出力を読むドライバは、前フレームの値を見る（1 フレームの遅れ）
4. **物理の出力パラメータをドライバが書くのはコンパイルエラー。** 書き手は 1 つにする
5. 物理の出力パラメータは、評価の始めに既定値へ戻し、各出力の値を足す。同じパラメータへの複数の出力は足し合わせになる

## 結果

- アーキテクチャ図で、物理をドライバとキーフォーム補間の間に移す
- 内部の運動方程式は Tsukumoe 自身の定義として `docs/specifications/physics.md` に書く。Cubism（physics3）と一致するかは M2 で検証する
- 1 フレーム内の複数刻みでは入力を一定として扱う（入力の補間はしない）
