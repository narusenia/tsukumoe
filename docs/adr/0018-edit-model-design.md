# ADR-0018: 編集用モデルの ID・更新方式・キーフォーム構造

- 状態: 採用
- 日付: 2026-10-30

## 背景

M1-01（編集用データモデル）の実装前に、後から変えにくい 3 点を決める必要がある。編集用モデルは、編集コマンドと undo（REQ-CORE-007）、JSON プロジェクト形式（REQ-FMT-001）、評価用モデルへのコンパイル（REQ-CORE-001）の土台になる。

## 決定

1. **ID**: 内部は要素の種類ごとに型を分けた世代付きインデックス（`MeshId` など）。各要素には変わらない文字列の永続 ID も持たせ、コマンドと JSON はこれで参照する。永続 ID は種類ごとに一意とし、パラメータは Live2D の慣習 ID（`ParamAngleX` など）をそのまま使う。
2. **更新方式**: モデルは可変。書き換えは `Model::apply(command)` の 1 か所だけを通し、そこで変更前後を自動で記録する。undo / redo は記録した差分を戻す・進める。外部から直接書き換えられない API にする。
3. **キーフォーム**: Cubism と同じ格子。要素ごとにバインディング（使うパラメータとそのキー位置）を持ち、同じバインディングを持つ要素どうしで共有する。キーフォームは全キー位置の交点ごとに 1 つで、密な配列に行優先で並べる。中身は絶対値（基本形からの差分にしない）で、対象の種類ごとに型を分ける。

## 結果

- 内部インデックスは再読み込みで変わるので、外に出す参照は永続 ID に限る（ID の同期を保つ実装が要る）
- 差分の記録を通さない書き換え経路を作らない（API の可視性で防ぐ）
- 3 軸以上のキー数は掛け算で増える。エディタで警告し、解決は v2（非格子パラメータ空間）に送る
- 逆コマンドを手書きしないので undo の実装漏れが起きにくい。差分は AI 出力の適用前プレビュー（REQ-AI-004）にそのまま使える
