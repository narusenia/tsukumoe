# ADR-0019: コマンドの適用方式

- 状態: 採用
- 日付: 2026-10-30

## 背景

ADR-0018 は、書き換えを `Model::apply` 1 か所に集め、変更前後を自動記録すると決めた。実装には次の 3 点が残る。

- コマンドを JSON に出す必要がある（REQ-CORE-007）が、モデルの要素は再読み込みで変わる内部 ID で互いを参照している
- 参照されている要素の削除など、モデルを壊すコマンドをどう扱うか
- 削除を undo したとき、他の要素が持つ ID をどう生かすか

## 決定

1. **コマンドは永続 ID（名前）で要素を指す。** コマンド専用の型（`Command`）が名前の文字列を持ち、適用時に内部 ID へ解決する。内部 ID は JSON に出さない。
2. **適用は取引（トランザクション）にする。** コマンドの適用後に `validate` を走らせ、適用前になかったエラーが出たら全体を巻き戻して `Err` を返す。個々のコマンドに「使用中か」の検査を書かない。適用前から壊れているモデルでも、新しいエラーを足さない編集は通す。
3. **差分は要素単位の前後スナップショットで持つ。** 追加は前が空、削除は後が空、変更は両方を持つ。undo は前、redo は後を書き戻す。
4. **削除した要素は元の ID のまま復元する。** アリーナに、スロットと世代を指定して書き戻す操作を持たせる。履歴は後入れ先出しなので、復元先は必ず空いている。
5. **複数コマンドを 1 つにまとめる `Batch` を持つ。** 途中で失敗したら全体を巻き戻す。1 回の undo で取り消せる（REQ-AI-004 の下地）。

## 結果

- 検証が毎回走るので、適用 1 回の費用がモデル全体の大きさに比例する。連続操作（ドラッグ）の最適化が必要になったら、過渡的な編集の経路を別に足す
- 要素単位のスナップショットなので、頂点数の多いメッシュの 1 頂点の移動でも、メッシュ全体を前後 2 回複製する。細かい差分は性能計測のあとで検討する
- コマンドの追加は、型 1 つと適用の分岐 1 つで済む。要素の種類を増やすには `Editable` の実装が 1 つ要る
